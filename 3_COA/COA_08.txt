============================================================
CHAPTER 8 — BASIC COMPUTER ORGANISATION
============================================================

LEVEL:
B.Tech 1st Year | Absolute Beginner

OBJECTIVE:
Understand the basic structure of a computer, its functional
units, CPU components, system buses, and how data/instructions
move between CPU, memory, and I/O devices.


============================================================
8.1 WHAT IS COMPUTER ORGANISATION?
============================================================

Computer Organisation explains:

    HOW the different hardware components of a computer
    are arranged and HOW they work together.

It deals with components such as:

    • CPU
    • ALU
    • Control Unit
    • Registers
    • Memory
    • Input/Output
    • Buses


Simple idea:

    Computer Organisation
            ↓
    How hardware components
    are connected and operate


============================================================
8.2 BASIC COMPUTER MODEL
============================================================

A computer can be viewed as four major functional parts:

    1. Input Unit
    2. Central Processing Unit (CPU)
    3. Memory Unit
    4. Output Unit


Basic structure:

                    ┌──────────────────┐
                    │    INPUT UNIT    │
                    └────────┬─────────┘
                             │
                             ▼
                  ┌─────────────────────┐
                  │        CPU          │
                  │                     │
                  │  ┌───────────────┐  │
                  │  │     ALU       │  │
                  │  └───────────────┘  │
                  │                     │
                  │  ┌───────────────┐  │
                  │  │ Control Unit  │  │
                  │  └───────────────┘  │
                  │                     │
                  │  ┌───────────────┐  │
                  │  │   Registers   │  │
                  │  └───────────────┘  │
                  └──────────┬──────────┘
                             │
                     ┌───────┴───────┐
                     │               │
                     ▼               ▼
              ┌────────────┐  ┌────────────┐
              │   MEMORY   │  │   OUTPUT   │
              │    UNIT    │  │    UNIT    │
              └────────────┘  └────────────┘


============================================================
8.3 FUNCTIONAL UNITS OF A COMPUTER
============================================================

The major functional units are:

    INPUT
       ↓
    MEMORY
       ↕
    CPU
       ↓
    OUTPUT


CPU itself contains:

    • ALU
    • Control Unit
    • Registers


============================================================
8.4 INPUT UNIT
============================================================

The Input Unit allows the computer to receive:

    • Data
    • Instructions
    • Commands

from the outside world.


Examples:

    • Keyboard
    • Mouse
    • Scanner
    • Microphone
    • Camera
    • Touchscreen


Basic operation:

    User
      ↓
    Input Device
      ↓
    Input Unit
      ↓
    Computer


Example:

    You type:

        25 + 10

    Keyboard sends the input to the computer.

The computer then processes it.


============================================================
8.5 FUNCTIONS OF INPUT UNIT
============================================================

The input unit:

    1. Accepts data from the user/device.
    2. Converts data into a machine-readable form.
    3. Sends data to memory/CPU for processing.


Example:

    Keyboard
       ↓
    Electrical/Digital signals
       ↓
    Computer-readable data


============================================================
8.6 OUTPUT UNIT
============================================================

The Output Unit presents processed results to the user.

Examples:

    • Monitor
    • Printer
    • Speaker
    • Projector
    • Headphones


Basic operation:

    Computer
       ↓
    Output Unit
       ↓
    Human-readable result


Example:

    CPU calculates:

        25 + 10 = 35

    Monitor displays:

        35


============================================================
8.7 MEMORY UNIT
============================================================

Memory stores:

    • Instructions
    • Input data
    • Intermediate results
    • Final results


Simple model:

              MEMORY
                 │
       ┌─────────┼─────────┐
       ▼         ▼         ▼
   Instructions Data     Results


Example:

    Program:
        Calculate A + B

    Memory may contain:

        Instruction
        A
        B
        Intermediate result


============================================================
8.8 CPU — CENTRAL PROCESSING UNIT
============================================================

CPU is often called:

    "Brain of the computer"


The CPU executes instructions and controls computer
operations.


Main CPU components:

    1. ALU
    2. Control Unit
    3. Registers


Concept:

              CPU
               │
       ┌───────┼────────┐
       │       │        │
       ▼       ▼        ▼
      ALU   Control   Registers
            Unit


============================================================
8.9 ALU — ARITHMETIC LOGIC UNIT
============================================================

ALU performs:

    • Arithmetic operations
    • Logical operations
    • Comparisons
    • Bitwise operations
    • Shifts


Arithmetic examples:

    Addition
    Subtraction
    Increment
    Decrement


Logical examples:

    AND
    OR
    XOR
    NOT


Comparison examples:

    A > B
    A < B
    A = B


Example:

    A = 10
    B = 5

    ALU can calculate:

        A + B = 15

        A - B = 5

        A > B


============================================================
8.10 ALU INTERNAL IDEA
============================================================

Conceptually:

        Operand A ─────┐
                       │
                       ▼
                  ┌─────────┐
        Operand B ─►   ALU   │
                  └────┬────┘
                       │
                       ▼
                     Result


Control signals tell the ALU which operation to perform.


Example:

    Control = ADD

    ALU:
        A + B


Control = AND

    ALU:
        A AND B


============================================================
8.11 CONTROL UNIT
============================================================

The Control Unit (CU) coordinates the activities of the
computer.


It:

    • Fetches instructions
    • Decodes instructions
    • Generates control signals
    • Controls ALU
    • Controls registers
    • Controls memory operations
    • Coordinates data movement


Think of the Control Unit as:

    "Manager of the CPU"


============================================================
8.12 CONTROL UNIT ANALOGY
============================================================

Imagine a restaurant.

    Customer → gives order

    Manager → tells workers what to do

    Workers → perform tasks

In a computer:

    Instruction → CPU request

    Control Unit → coordinator

    ALU/Register/Memory → perform operations


The Control Unit does not normally perform arithmetic
itself.

Instead, it tells the appropriate hardware what to do.


============================================================
8.13 REGISTERS
============================================================

Registers are very small and very fast storage locations
inside the CPU.

They temporarily store:

    • Data
    • Instructions
    • Addresses
    • Intermediate results
    • CPU state


Example:

    Register R1 = 25
    Register R2 = 10

ALU can calculate:

    R1 + R2


Registers are much faster to access than main memory.


============================================================
8.14 WHY REGISTERS ARE FAST
============================================================

Registers are:

    • Located inside/very close to the CPU datapath
    • Built from fast storage elements
    • Small in number
    • Designed for rapid CPU access


General hierarchy:

    Registers
        ↓
    Cache
        ↓
    RAM
        ↓
    Secondary Storage

Moving downward:

    Capacity generally increases
    Cost per bit generally decreases
    Access speed generally decreases

============================================================
8.16 DATAPATH
============================================================

The datapath is the portion of the processor through which
data moves and is processed.


It typically contains:

    • Registers
    • ALU
    • Internal buses
    • Multiplexers
    • Other data-processing hardware


Concept:

    Registers
       │
       ▼
    Datapath
       │
       ▼
      ALU
       │
       ▼
    Registers


Control Unit controls the datapath.


============================================================
8.17 CONTROL PATH
============================================================

The control path generates signals that control the
datapath.


Concept:

        Control Unit
             │
             │ Control Signals
             ▼
          Datapath
             │
             ▼
       Data Processing


Therefore:

    Datapath → moves/processes data

    Control path → controls what happens


============================================================
8.18 SYSTEM BUS
============================================================

A bus is a group of electrical/signal lines used for
communication between computer components.


Instead of connecting every component directly to every
other component, components can communicate through buses.


Example:

        CPU
         │
    ┌────┴────┐
    │   BUS   │
    └────┬────┘
       ┌─┴──────────┐
       ▼            ▼
    Memory          I/O


A bus can carry:

    • Addresses
    • Data
    • Control information


============================================================
8.19 THREE MAIN SYSTEM BUSES
============================================================

Traditionally, the system bus is divided conceptually into:

    1. Address Bus
    2. Data Bus
    3. Control Bus


Diagram:

             SYSTEM BUS
                  │
        ┌─────────┼─────────┐
        ▼         ▼         ▼
      Address    Data     Control
        Bus       Bus       Bus


============================================================
8.20 ADDRESS BUS
============================================================

The Address Bus carries:

    ADDRESS information


The CPU uses an address to identify:

    • Memory location
    • I/O location/device


Example:

    CPU wants to read memory location:

        5000

It places:

        5000

on the address bus.


IMPORTANT:

    Address bus is generally considered unidirectional
    from the address source/controller toward the selected
    memory or I/O component in a traditional system model.


============================================================
8.21 ADDRESS BUS WIDTH
============================================================

Address bus width determines how many unique addresses
can be represented.

If there are:

    n address lines

then number of possible addresses is:

    2^n


Example:

    8 address lines

    Number of addresses:

        2^8 = 256


Example:

    16 address lines

        2^16 = 65,536 addresses


Example:

    32 address lines

        2^32 addresses


Therefore:

    More address lines
        ↓
    Larger address space


============================================================
8.22 DATA BUS
============================================================

The Data Bus carries:

    ACTUAL DATA


Example:

    CPU wants to read:

        10110100

The data can travel through the data bus.


Unlike the traditional simplified address-bus model, the
data bus is generally bidirectional:

    CPU ↔ Memory

    CPU ↔ I/O


============================================================
8.23 DATA BUS WIDTH
============================================================

Data bus width determines how many bits can be transferred
in one bus transfer.


Example:

    8-bit data bus:

        8 bits per transfer


    16-bit data bus:

        16 bits per transfer


    32-bit data bus:

        32 bits per transfer


    64-bit data bus:

        64 bits per transfer


Generally:

    Wider data bus
        ↓
    More bits can be transferred per transfer


But actual performance also depends on clock rate,
protocol, latency, memory system, and other factors.


============================================================
8.24 CONTROL BUS
============================================================

The Control Bus carries:

    CONTROL SIGNALS


Examples:

    • Read
    • Write
    • Clock
    • Interrupt
    • Reset
    • Bus request
    • Bus grant


Concept:

       CPU
        │
        │ Control signals
        ▼
    Memory / I/O


Control signals tell components:

    WHAT operation should happen.


============================================================
8.25 READ OPERATION
============================================================

Suppose CPU wants to read data from memory.


Sequence:

    1. CPU places address on Address Bus.
    2. CPU activates READ control signal.
    3. Memory identifies the address.
    4. Memory places requested data on Data Bus.
    5. CPU receives the data.


Diagram:

       CPU
        │
        │ Address
        ▼
    Address Bus
        │
        ▼
      Memory
        │
        │ Data
        ▼
     Data Bus
        │
        ▼
       CPU


============================================================
8.26 WRITE OPERATION
============================================================

Suppose CPU wants to write data to memory.


Sequence:

    1. CPU places destination address on Address Bus.
    2. CPU places data on Data Bus.
    3. CPU activates WRITE control signal.
    4. Memory stores the data at the specified address.


Diagram:

       CPU
        │
    ┌───┴─────────┐
    │             │
    ▼             ▼
 Address Bus    Data Bus
    │             │
    └──────┬──────┘
           ▼
         Memory

       WRITE signal
           ↓
         Control Bus

8.27 COMPLETE BUS OPERATION
============================================================

             └──────┬───────┘
                    │
          ┌─────────┼─────────┐
          │         │         │

       Address     Data     Control
         Bus        Bus       Bus
          │         │         │
          └─────────┼─────────┘
                    │
             ┌──────┴───────┐
             │              │
             ▼              ▼
          MEMORY           I/O


============================================================
8.28 BUS WIDTH
============================================================

Bus width means:

    Number of bits carried by the bus in parallel.


Examples:

    32-bit data bus
    64-bit data bus


For an address bus:

    32-bit address bus
        → 2^32 addressable positions

    64-bit address bus
        → 2^64 addressable positions

assuming the addressing model uses all address bits.


Important:

    Address width ≠ Data width


============================================================
8.29 DATA TRANSFER RATE
============================================================

A simplified theoretical idea:

    Transfer Rate
        ≈
    Bits transferred per transfer × transfers per second


For a simple single-transfer-per-cycle model:

    Bandwidth ≈ Bus Width × Clock Frequency


Example:

    32-bit bus
    100 MHz clock

    Theoretical raw rate:

    32 bits × 100,000,000/s

    = 3.2 × 10^9 bits/s

    = 3.2 Gbit/s


In real systems, protocol overhead and other limitations
reduce usable bandwidth.


============================================================
8.30 BUS BANDWIDTH
============================================================

Bandwidth refers to the amount of data that can be
transferred per unit time.


Common units:

    bits/s
    bytes/s
    MB/s
    GB/s
    Gbit/s


Remember:

    1 Byte = 8 bits


Therefore:

    8 Gbit/s

    = 1 GB/s

    ignoring protocol overhead and unit-convention details.


============================================================
8.31 BUS ARBITRATION
============================================================

What happens if multiple devices want to use the same bus?

Example:

    CPU ─────┐
             │
    DMA ─────┼──► Shared Bus
             │
    I/O ─────┘


Only one bus master may be allowed to control the bus at
a given time in a conventional shared-bus arrangement.

Therefore, we need:

    BUS ARBITRATION


Bus arbitration decides:

    WHO gets control of the bus?


============================================================
8.32 BUS MASTER
============================================================

A bus master is a component that can initiate a bus
transaction.

Examples may include:

    • CPU
    • DMA controller
    • Other bus-capable devices


The arbiter decides which requester gets bus ownership.


============================================================
8.33 CENTRALIZED BUS ARBITRATION
============================================================

In centralized arbitration:

    One central arbiter controls bus access.


Concept:

    CPU ───────┐
    DMA ───────┼────► Arbiter ───► BUS
    I/O ───────┘


The arbiter receives requests and grants bus access.


Advantages:

    • Simple control
    • Easier to implement


Disadvantage:

    • Central arbiter can become a bottleneck or
      single point of failure.


============================================================
8.34 DISTRIBUTED BUS ARBITRATION
============================================================

In distributed arbitration:

    No single central arbiter controls everything.

Devices participate in determining who gets the bus.


Concept:

    Device A ─┐
    Device B ─┼──► Distributed arbitration
    Device C ─┘


Advantages:

    • No single central arbiter
    • Can be scalable depending on design


Disadvantages:

    • More complex
    • Arbitration logic distributed among devices


============================================================
8.35 SYNCHRONOUS BUS
============================================================

A synchronous bus operates according to a common clock.


Concept:

    Clock:
    ─┐ ┌─┐ ┌─┐ ┌─┐
     └─┘ └─┘ └─┘ └─


Bus operations occur according to clock timing.


Advantages:

    • Simple timing model
    • Predictable operation
    • Easier coordination


Disadvantages:

    • Clock distribution required
    • Timing constraints can limit distance/flexibility


============================================================
8.36 ASYNCHRONOUS BUS
============================================================

An asynchronous bus does not rely on one common clock
for every bus transaction.

Instead, devices coordinate using control/handshake
signals.


Typical concept:

    Request
       ↓
    Acknowledgement
       ↓
    Data transfer


Advantages:

    • Can accommodate devices with different speeds
    • No common clock required for the transaction


Disadvantages:

    • More complex control
    • Handshaking introduces overhead


============================================================
8.37 SYNCHRONOUS VS ASYNCHRONOUS BUS
============================================================

    +----------------------+----------------------+
    | Synchronous         | Asynchronous         |
    +----------------------+----------------------+
    | Uses common clock   | No common clock      |
    | Clock-based timing  | Handshake-based      |
    | Simpler timing      | More flexible        |
    | Predictable timing  | Variable timing      |
    | Easier coordination | More control logic   |
    +----------------------+----------------------+

8.39 HOW A COMPUTER PROCESSES AN INSTRUCTION
============================================================

Suppose a program contains:

    ADD R1, R2


Simplified process:

    STEP 1:
        CPU fetches instruction from memory.

    STEP 2:
        Instruction enters the CPU.

    STEP 3:
        Control Unit decodes the instruction.

    STEP 4:
        Registers provide operands.

    STEP 5:
        ALU performs addition.

    STEP 6:
        Result is stored in a register.

    STEP 7:
        CPU proceeds to the next instruction.


Concept:

    Memory
       ↓
    Instruction
       ↓
      CPU
       ↓
    Control Unit
       ↓
    Registers
       ↓
      ALU
       ↓
    Result


The detailed instruction cycle will be studied in:

    CHAPTER 12 — INSTRUCTION EXECUTION

============================================================
8.41 IMPORTANT DIFFERENCES
============================================================

ALU vs Control Unit:

    ALU:
        Performs operations.

    Control Unit:
        Controls operations.


Register vs Memory:

    Register:
        Very small, very fast, inside CPU.

    Main Memory:
        Larger, slower than registers.


Address Bus vs Data Bus:

    Address Bus:
        Specifies WHERE.

    Data Bus:
        Carries WHAT.


Control Bus:

    Specifies HOW/WHICH operation.


Easy memory trick:

    ADDRESS = WHERE

    DATA = WHAT

    CONTROL = HOW

------------------------------------------------------------
PROBLEM 1
------------------------------------------------------------

A computer has a 10-bit address bus.

How many unique addresses are possible?


Formula:

    Number of addresses = 2^n

    n = 10

    2^10 = 1024


ANSWER:

    1024 unique addresses

A computer has a 16-bit address bus.

    2^16
    = 65,536


ANSWER:

    65,536 addresses

PROBLEM 3
------------------------------------------------------------

A system has a 32-bit data bus.

How many bits can be transferred in one simple
parallel transfer?


    32 bits


In bytes:

    32 / 8 = 4 bytes


ANSWER:

    32 bits = 4 bytes


------------------------------------------------------------
PROBLEM 4
------------------------------------------------------------

A 64-bit data bus operates at 100 MHz, assuming one
transfer per clock cycle.

Calculate theoretical raw bandwidth.


Given:

    Bus width = 64 bits
    Frequency = 100 MHz


Bandwidth:

    = 64 × 100,000,000
    = 6.4 × 10^9 bits/s


Convert to bytes:

    = 6.4 × 10^9 / 8
    = 0.8 × 10^9 bytes/s


ANSWER:

    800 MB/s approximately


This is an idealized value before protocol overhead.


------------------------------------------------------------
PROBLEM 5
------------------------------------------------------------

A system has 20 address lines.

How many addressable locations are possible?


    2^20

    = 1,048,576


ANSWER:

    1,048,576 locations


If each location stores 1 byte:

    Capacity = 1,048,576 bytes

    = 1 MiB

============================================================
8.44 COMMON MISTAKES
============================================================

MISTAKE 1:

"ALU controls the entire computer."

WRONG.

Correct:

    Control Unit coordinates operations.

    ALU performs arithmetic and logical operations.


MISTAKE 2:

"Memory is part of the CPU."

Generally wrong in basic computer organisation.

Main memory is a separate major system component.

Registers are inside the CPU.


MISTAKE 3:

"Data bus tells the memory location."

WRONG.

Address bus identifies the location.

Data bus carries the data.


MISTAKE 4:

"More data-bus width always means proportionally faster
computer."

Not necessarily.

Performance depends on:

    • Clock rate
    • Latency
    • Protocol
    • Memory speed
    • Cache
    • CPU architecture
    • Workload


MISTAKE 5:

"Address bus carries data."

WRONG.

Address bus carries address information.


MISTAKE 6:

"Asynchronous bus means no synchronization."

Not exactly.

It does not use a common clock for each transaction,
but uses coordination/handshaking signals.

COMPUTER ORGANISATION:

    How hardware components are arranged and operate.


MAIN FUNCTIONAL UNITS:

    Input
    Output
    Memory
    CPU


CPU:

    ALU
    Control Unit
    Registers


ALU:

    Performs arithmetic and logical operations.


CONTROL UNIT:

    Coordinates operations and generates control signals.


REGISTERS:

    Very fast temporary CPU storage.


DATAPATH:

    Moves and processes data.


CONTROL PATH:

    Generates signals controlling the datapath.


SYSTEM BUS:

    Address Bus
    Data Bus
    Control Bus


ADDRESS BUS:

    Carries WHERE.


DATA BUS:

    Carries WHAT.


CONTROL BUS:

    Carries HOW/WHICH operation.


ADDRESS SPACE:

    n address lines → 2^n possible addresses.


DATA BUS WIDTH:

    Determines bits transferred per parallel transfer.


BUS ARBITRATION:

    Decides who gets control of a shared bus.


CENTRALIZED ARBITRATION:

    Central arbiter.


DISTRIBUTED ARBITRATION:

    Devices participate in arbitration.


SYNCHRONOUS BUS:

    Common clock.


ASYNCHRONOUS BUS:

    Handshaking/coordination without a common transaction
    clock.
