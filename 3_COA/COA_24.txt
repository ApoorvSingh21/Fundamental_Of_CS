------------------------------------------------------------
24.1 WHAT IS PROCESSOR ORGANISATION?
------------------------------------------------------------

Processor organisation describes how the internal components
of a CPU are arranged and connected so that instructions can
be executed.

A processor mainly contains:

    • Registers
    • ALU
    • Control Unit
    • Internal buses
    • Datapath
    • Control signals

Basic idea:

                 +----------------------+
                 |         CPU          |
                 |                      |
                 |  +----------------+  |
                 |  | Control Unit   |  |
                 |  +----------------+  |
                 |          |           |
                 |    Control Signals   |
                 |          ↓           |
                 |  +----------------+  |
                 |  |    Datapath    |  |
                 |  |                |  |
                 |  | Registers      |  |
                 |  | ALU            |  |
                 |  | Buses          |  |
                 |  +----------------+  |
                 +----------------------+


------------------------------------------------------------
24.2 PROCESSOR VS CPU
------------------------------------------------------------

CPU = Central Processing Unit.

Processor is commonly used to mean the CPU or processing unit.

The CPU performs:

    • Instruction execution
    • Arithmetic operations
    • Logical operations
    • Data movement
    • Control operations


Example:

    Program:
        A = B + C

The CPU must:

    1. Fetch instructions.
    2. Read B.
    3. Read C.
    4. Add them.
    5. Store the result in A.


------------------------------------------------------------
24.3 BASIC CPU STRUCTURE
------------------------------------------------------------

A simplified CPU:

                 CPU
                  |
       +----------+----------+
       |                     |
       ↓                     ↓
 Control Unit             Datapath
                             |
              +--------------+--------------+
              |              |              |
          Registers         ALU           Buses
              |
              ↓
           Data


CONTROL UNIT:
    Controls what happens.

DATAPATH:
    Provides the hardware through which data moves and
    operations are performed.


------------------------------------------------------------
24.4 WHAT IS A DATAPATH?
------------------------------------------------------------

A datapath is the collection of hardware components and
connections that move and process data inside the processor.

It usually includes:

    • Registers
    • ALU
    • Multiplexers
    • Internal buses
    • Shifters
    • Functional units


Example:

    Register A
        |
        ↓
       ALU
        ↑
        |
    Register B
        |
        ↓
    Result Register


The datapath is essentially:

    "Where the data travels and gets processed."


------------------------------------------------------------
24.5 WHAT IS THE CONTROL PATH?
------------------------------------------------------------

The control path generates signals that tell the datapath
what operations to perform.

Example:

    Control Unit
         |
         +----> Select Register A
         |
         +----> Select Register B
         |
         +----> ALU = ADD
         |
         +----> Enable Result Register


Therefore:

    DATAPATH
        = Does the operation.

    CONTROL PATH
        = Tells the datapath what to do.


------------------------------------------------------------
24.6 DATAPATH VS CONTROL PATH
------------------------------------------------------------

+-------------------+-----------------------------+
| Datapath          | Control Path               |
+-------------------+-----------------------------+
| Processes data    | Controls processing        |
+-------------------+-----------------------------+
| Registers         | Control signals            |
| ALU               | Control logic              |
| Buses             | Instruction decoding       |
| MUXes             | Timing/control generation  |
+-------------------+-----------------------------+


MEMORY TRICK:

    Datapath = DATA moves

    Control path = CONTROL happens


------------------------------------------------------------
24.7 PROCESSOR INTERNAL COMPONENTS
------------------------------------------------------------

Important components:

    1. Register file
    2. ALU
    3. Internal buses
    4. Multiplexers
    5. Control Unit
    6. Program Counter
    7. Instruction Register
    8. Status/Flag register


Conceptual structure:

                CONTROL UNIT
                     |
             Control Signals
                     ↓
    +--------------------------------+
    |            DATAPATH            |
    |                                |
    | Registers → ALU → Registers    |
    |      ↑       ↑       ↑         |
    |      +-------BUS-----+         |
    +--------------------------------+


------------------------------------------------------------
24.8 REGISTERS
------------------------------------------------------------

A register is a small, high-speed storage location inside
the CPU.

Registers hold:

    • Operands
    • Intermediate results
    • Addresses
    • Instructions
    • CPU state


Examples:

    PC
    IR
    MAR
    MDR
    Accumulator
    General-purpose registers
    SP
    Status register


------------------------------------------------------------
24.9 WHY ARE REGISTERS FAST?
------------------------------------------------------------

Registers are located inside the processor and are implemented
using very fast storage circuitry.

Therefore:

    Register access
        ↓
    Very fast

    Main memory access
        ↓
    Slower


Typical data movement:

    Register
       ↓
      ALU
       ↓
    Register


This is much faster than repeatedly accessing external main
memory.


------------------------------------------------------------
24.10 REGISTER FILE
------------------------------------------------------------

A register file is a collection of processor registers
organised as a unit.

Example:

    +------------------+
    | Register File    |
    +------------------+
    | R0               |
    | R1               |
    | R2               |
    | R3               |
    | R4               |
    | R5               |
    | ...              |
    | R31              |
    +------------------+


Modern processors commonly have multiple general-purpose
registers.


------------------------------------------------------------
24.11 REGISTER FILE READ AND WRITE
------------------------------------------------------------

A register file may support:

    • Reading one or more registers
    • Writing a register


Example:

    ADD R3, R1, R2

Conceptually:

    R1 ──────→ ALU input A
                  +
    R2 ──────→ ALU input B
                  |
                  ↓
                 ALU
                  |
                  ↓
                 R3


Meaning:

    R3 = R1 + R2


------------------------------------------------------------
24.12 ALU
------------------------------------------------------------

ALU = Arithmetic Logic Unit.

The ALU performs arithmetic and logical operations.

Arithmetic:

    • Addition
    • Subtraction
    • Increment
    • Decrement

Logical:

    • AND
    • OR
    • XOR
    • NOT
    • Comparisons


Example:

    R1 = 10
    R2 = 5

    ALU ADD:

    10 + 5 = 15


------------------------------------------------------------
24.13 ALU INPUTS AND OUTPUT
------------------------------------------------------------

Basic ALU:

             Input A
                |
                ↓
          +-----------+
          |    ALU    |
          +-----------+
                ↑
                |
             Input B

                |
                ↓
             Result


The control unit selects the ALU operation.

Example:

    ALU control = ADD

or:

    ALU control = SUB

or:

    ALU control = AND


------------------------------------------------------------
24.14 STATUS FLAGS
------------------------------------------------------------

Many processors maintain status information after arithmetic
or logical operations.

Common flags:

    • Zero (Z)
    • Carry (C)
    • Sign/Negative (S/N)
    • Overflow (V/O)


Example:

    5 - 5 = 0

The Zero flag may become:

    Z = 1


Example:

    An arithmetic operation produces a carry.

    Carry flag may become:

    C = 1


------------------------------------------------------------
24.15 INTERNAL CPU BUS
------------------------------------------------------------

An internal bus is a communication pathway inside the CPU.

It transfers information between:

    • Registers
    • ALU
    • Other functional units


Example:

    R1 ──────┐
             |
             ↓
          Internal Bus
             |
             ↓
            ALU
             |
             ↓
          Internal Bus
             |
             ↓
            R2


------------------------------------------------------------
24.16 SINGLE-BUS ORGANISATION
------------------------------------------------------------

In single-bus organisation, many CPU components share one
common internal bus.

Example:

        R0 ──┐
        R1 ──┤
        R2 ──┤
        R3 ──┤
        PC ──┤
        IR ──┤
             ↓
       +-----------+
       | INTERNAL  |
       |   BUS     |
       +-----------+
             |
             ↓
            ALU
             |
             ↓
           Register


Only one major transfer can use the shared bus at a time,
depending on the design.


------------------------------------------------------------
24.17 SINGLE-BUS ORGANISATION EXAMPLE
------------------------------------------------------------

Suppose:

    R1 = 10
    R2 = 20

We want:

    R3 = R1 + R2


A simplified sequence:

    Step 1:
        R1 → Bus → ALU input

    Step 2:
        R2 → Bus → ALU input

    Step 3:
        ALU performs ADD

    Step 4:
        ALU result → Bus

    Step 5:
        Bus → R3


Therefore:

    R3 = 30


------------------------------------------------------------
24.18 LIMITATION OF SINGLE-BUS ORGANISATION
------------------------------------------------------------

Main limitation:

    Only one shared bus is available.

This can create:

    • More transfers
    • More control complexity
    • Potential bottlenecks
    • Lower parallel data movement


For example:

    R1 → Bus

then:

    R2 → Bus

then:

    Result → Bus

Transfers cannot all occur simultaneously on the same bus.


------------------------------------------------------------
24.19 MULTI-BUS ORGANISATION
------------------------------------------------------------

A multi-bus organisation uses multiple internal buses.

A common conceptual design uses three buses:

    Bus A
    Bus B
    Bus C


Example:

       Register File
        /         \
       ↓           ↓
     Bus A       Bus B
        \         /
         \       /
           ALU
            |
            ↓
          Bus C
            |
            ↓
       Register File


This allows multiple data transfers simultaneously.


------------------------------------------------------------
24.20 THREE-BUS ORGANISATION
------------------------------------------------------------

A typical three-bus datapath:

                 Register File
                /             \
               ↓               ↓
            Bus A             Bus B
               |               |
               +------\ /------+
                       ALU
                        |
                        ↓
                      Bus C
                        |
                        ↓
                 Register File


Bus A:
    First ALU operand

Bus B:
    Second ALU operand

Bus C:
    ALU result


------------------------------------------------------------
24.21 THREE-BUS ADDITION EXAMPLE
------------------------------------------------------------

Instruction:

    R3 = R1 + R2


At one stage:

    R1 → Bus A
    R2 → Bus B

              ↓
             ALU
              |
             ADD
              |
              ↓
           Bus C
              |
              ↓
             R3


Thus two operands can reach the ALU simultaneously.


------------------------------------------------------------
24.22 SINGLE-BUS VS MULTI-BUS
------------------------------------------------------------

+----------------------+--------------------------+
| Single Bus           | Multi-Bus               |
+----------------------+--------------------------+
| One shared bus       | Multiple buses          |
+----------------------+--------------------------+
| Simpler              | More complex            |
+----------------------+--------------------------+
| Lower hardware cost  | More hardware           |
+----------------------+--------------------------+
| More transfers may   | More parallel transfers |
| be required          | possible                |
+----------------------+--------------------------+
| Potential bottleneck | Better data movement    |
+----------------------+--------------------------+


MEMORY TRICK:

    Single bus:
        SIMPLE but SLOWER DATA MOVEMENT

    Multi-bus:
        COMPLEX but MORE PARALLELISM


------------------------------------------------------------
24.23 MULTIPLEXER (MUX) IN DATAPATH
------------------------------------------------------------

A multiplexer selects one input from several inputs.

Example:

        R1 ──┐
        R2 ──┤
        R3 ──┤→ MUX → ALU
        R4 ──┘


Control signal decides which register is selected.

Example:

    Select = 2

    MUX chooses R2.


------------------------------------------------------------
24.24 WHY ARE MUXES IMPORTANT?
------------------------------------------------------------

The CPU has many possible data sources.

The ALU may need:

    • Register value
    • Immediate value
    • PC
    • Memory data
    • Other intermediate value


A MUX selects the required source.

Therefore:

    MUX
      ↓
    Selects data path


------------------------------------------------------------
24.25 CONTROL SIGNALS
------------------------------------------------------------

Control signals are signals generated by the control unit
that direct CPU operations.

Examples:

    • Register read
    • Register write
    • ALU operation select
    • MUX select
    • Memory read
    • Memory write
    • PC update
    • IR load


Conceptually:

               Instruction
                    |
                    ↓
             +-------------+
             |   Control   |
             |    Unit     |
             +-------------+
                    |
       +------------+------------+
       ↓            ↓            ↓
     MUX         Register       ALU
    Select        Enable       Control


------------------------------------------------------------
24.26 CONTROL SIGNAL EXAMPLE
------------------------------------------------------------

Instruction:

    ADD R3, R1, R2


The control unit may generate:

    Read register 1
        ↓
    Read register 2
        ↓
    Select ALU = ADD
        ↓
    Enable write to R3


Conceptually:

    R1 ──────→
               \
                ALU → R3
               /
    R2 ──────→


------------------------------------------------------------
24.27 REGISTER TRANSFER
------------------------------------------------------------

Register transfer means moving data from one register
to another.

Example:

    R2 ← R1


Meaning:

    Copy the contents of R1 into R2.


Important:

    R1 is not destroyed.

    R2 receives a copy of R1.


------------------------------------------------------------
24.28 REGISTER TRANSFER LANGUAGE
------------------------------------------------------------

Register Transfer Language (RTL) is used to describe
microoperations and data transfers.

Examples:

    R2 ← R1

    R3 ← R1 + R2

    PC ← PC + 1

    IR ← MDR


The arrow:

    ←

means:

    "Load the value on the right into the destination
     on the left."


------------------------------------------------------------
24.29 MICROOPERATIONS
------------------------------------------------------------

A microoperation is a basic operation performed on data
stored in registers.

Types:

    1. Register transfer
    2. Arithmetic
    3. Logical
    4. Shift


Examples:

REGISTER TRANSFER:

    R2 ← R1


ARITHMETIC:

    R3 ← R1 + R2


LOGICAL:

    R3 ← R1 AND R2


SHIFT:

    R1 ← shl R1


------------------------------------------------------------
24.30 PROCESSOR CLOCK
------------------------------------------------------------

The CPU uses clock signals to coordinate operations.

Conceptually:

    Clock:
    ↑   ↑   ↑   ↑   ↑
    |   |   |   |   |
    T1  T2  T3  T4  T5


Operations occur according to timing/control requirements.


Example:

    T1:
        MAR ← PC

    T2:
        MDR ← Memory[MAR]

    T3:
        IR ← MDR


This is a simplified illustration.


------------------------------------------------------------
24.31 CLOCK CYCLE
------------------------------------------------------------

A clock cycle is one period of the processor clock.

If clock frequency is:

    1 GHz

then:

    1 GHz = 1,000,000,000 cycles/sec


Clock period:

    T = 1 / f


For 1 GHz:

    T = 1 / 10^9
      = 1 ns

24.32 DATAPATH OPERATION
------------------------------------------------------------

Consider:

    R1 = 5
    R2 = 7

Instruction:

    R3 = R1 + R2


Data movement:

    R1
     |
     ↓
    Bus A
     |
     ↓
    ALU ← Bus B ← R2
     |

     ↓
    Bus C
     |
     ↓
    R3

------------------------------------------------------------

    PC contains address of next instruction.


Simplified fetch:

    1. MAR ← PC

    2. Memory Read

    3. MDR ← Memory[MAR]

    4. IR ← MDR

    5. PC ← PC + instruction length


Conceptually:

    PC
    ↓
    MAR
    ↓
    Memory
    ↓
    MDR
    ↓
    IR


The control unit coordinates these operations.

             ALU

             ADD
              ↓
             R3

    • Register selection

    Instruction
        ↓
    Decode
        ↓
    Select operands

    Instruction Register
          ↓
    Control Unit
          ↓

          ↓

          ↓

24.38 PROCESSOR ORGANISATION EXAMPLE
------------------------------------------------------------

Suppose:

    R1 = 15
    R2 = 25

Instruction:

    ADD R3, R1, R2


Step 1:

    Control unit decodes instruction.


Step 2:

    Register file reads R1.


Step 3:

    Register file reads R2.


Step 4:

    ALU receives:

        A = 15
        B = 25


Step 5:

    ALU performs:

        15 + 25 = 40


Step 6:

    Result is written into R3.


Final:

    R3 = 40

------------------------------------------------------------
24.46 COMMON MISTAKES
------------------------------------------------------------

MISTAKE 1:

    Datapath and control unit are the same.

CORRECT:

    Datapath processes data.
    Control unit controls the datapath.


MISTAKE 2:

    Register = cache.

CORRECT:

    Registers are CPU-internal storage.
    Cache is a separate memory hierarchy level.


MISTAKE 3:

    A bus stores data permanently.

CORRECT:

    A bus primarily transfers information.


MISTAKE 4:

    More buses always means a better processor.

CORRECT:

    More buses can increase parallelism but also increase
    hardware complexity and cost.


MISTAKE 5:

    ALU controls the CPU.

CORRECT:

    ALU performs operations.
    Control unit coordinates operations.


MISTAKE 6:

    Register transfer means the source register is erased.

CORRECT:

    R2 ← R1 means R1's value is copied into R2.
