============================================================
CHAPTER 11 — ADDRESSING MODES
============================================================

LEVEL:
B.Tech 1st Year | Absolute Beginner

OBJECTIVE:
Understand where operands are located, how the CPU finds
them, what an Effective Address (EA) is, and how different
addressing modes work.


============================================================
11.1 WHY ADDRESSING MODES?
============================================================

An instruction tells the CPU:

    WHAT operation to perform
    +
    WHERE/WHAT data to use


Example:

    ADD R1, R2

The CPU needs to know:

    • Where is R1?
    • Where is R2?
    • How should the operands be interpreted?


ADDRESSING MODE tells the CPU HOW to locate an operand.


Simple definition:

    Addressing Mode =
    The method used by an instruction to specify
    the location or value of its operand.


============================================================
11.2 REAL-WORLD ANALOGY
============================================================

Suppose someone says:

    "Bring me the book."

There are different ways to identify the book:

    1. "The book is right here."
    2. "The book is at shelf 5."
    3. "Ask Rahul where the book is."
    4. "Take the book from the location stored in this note."


Similarly, the CPU can locate data in different ways.


These different methods are called:

    ADDRESSING MODES


============================================================
11.3 OPERAND
============================================================

An operand is the data or information on which an
instruction operates.


Example:

    ADD R1, R2


Operands:

    R1
    R2


Another example:

    ADD R1, 25


Operand:

    25


The operand may be:

    • An immediate value
    • A register
    • A memory location
    • An address derived from registers and offsets


============================================================
11.4 EFFECTIVE ADDRESS — EA
============================================================

EA = Effective Address


The Effective Address is the actual memory address
calculated/identified for accessing an operand.


Example:

    LOAD R1, 5000


If the instruction directly specifies memory address 5000:

    EA = 5000


Then:

    R1 ← Memory[5000]


IMPORTANT:

    EA is especially important for memory-addressing modes.


============================================================
11.5 ADDRESS VS EFFECTIVE ADDRESS
============================================================

Instruction may contain:

    Address field

But the actual address used to access memory may be:

    Effective Address


For direct addressing:

    EA = Address field


For indirect addressing:

    EA = Memory[Address field]


For indexed addressing:

    EA = Address field + Index register


Therefore:

    Address field ≠ necessarily final memory address.


============================================================
11.6 MAIN ADDRESSING MODES
============================================================

Important addressing modes:

    1. Immediate
    2. Direct
    3. Indirect
    4. Register
    5. Register Indirect
    6. Indexed
    7. Base
    8. Relative
    9. Auto-Increment
   10. Auto-Decrement


Different ISAs may use different names or variations.


============================================================
11.7 IMMEDIATE ADDRESSING
============================================================

In immediate addressing, the operand value is directly
present inside the instruction.


Example:

    MOV R1, #25


Meaning:

    R1 ← 25


Here:

    25 = actual data


There is no need to access memory to obtain the operand
itself.


Concept:

    Instruction
        │
        └──► Value = 25
                │
                ▼
               R1


============================================================
11.8 IMMEDIATE ADDRESSING — EXAMPLE
============================================================

Instruction:

    ADD R1, #10


Meaning:

    R1 ← R1 + 10


Here:

    10 is part of the instruction.


No separate memory lookup is required to obtain 10.


============================================================
11.9 IMMEDIATE ADDRESSING — ADVANTAGES
============================================================

Advantages:

    • Very simple
    • Fast for small constants
    • No additional memory access for the operand
    • Useful for constants


Disadvantages:

    • Constant size is limited by instruction format
    • Cannot directly represent arbitrarily large values


============================================================
11.10 DIRECT ADDRESSING
============================================================

In direct addressing, the instruction contains the
memory address of the operand.


Formula:

    EA = A


where:

    A = address field in instruction


Example:

    LOAD R1, 5000


Meaning:

    EA = 5000

    R1 ← Memory[5000]


Diagram:

    Instruction
         │
         │ address = 5000
         ▼
    ┌─────────────┐
    │   Memory    │
    │    5000     │
    └─────────────┘
         │
         ▼
        R1


============================================================
11.11 DIRECT ADDRESSING — EXAMPLE
============================================================

Suppose:

    Memory[1000] = 75


Instruction:

    LOAD R1, 1000


Then:

    EA = 1000

    R1 = Memory[1000]

    R1 = 75


============================================================
11.12 INDIRECT ADDRESSING
============================================================

In indirect addressing, the instruction contains an
address that points to another memory location containing
the actual address of the operand.


Formula:

    EA = Memory[A]


Example:

    LOAD R1, 500


Suppose:

    Memory[500] = 2000
    Memory[2000] = 75


Then:

    EA = Memory[500]
       = 2000


Therefore:

    R1 ← Memory[2000]
       = 75


============================================================
11.13 INDIRECT ADDRESSING — DIAGRAM
============================================================

             Instruction
                  │
                  │ A = 500
                  ▼
          ┌──────────────┐
          │ Memory[500]  │
          │     2000     │
          └──────┬───────┘
                 │
                 │ EA = 2000
                 ▼
          ┌──────────────┐
          │ Memory[2000] │
          │      75      │
          └──────┬───────┘
                 │
                 ▼
                R1


So:

    A → address of address
    EA → actual operand address


============================================================
11.14 DIRECT VS INDIRECT
============================================================

DIRECT:

    EA = A


    Instruction
         │
         ▼
    Memory[A]
         │
         ▼
       Data


INDIRECT:

    EA = Memory[A]


    Instruction
         │
         ▼
    Memory[A]
         │
      address
         ▼
    Memory[EA]
         │
         ▼
       Data


Key difference:

    Direct:
        One memory access for operand.


    Indirect:
        Additional memory access is needed to obtain
        the effective address.


============================================================
11.15 REGISTER ADDRESSING
============================================================

In register addressing, the operand is stored in a
CPU register.


Example:

    ADD R1, R2


Here:

    R1 and R2 are registers.


No memory address calculation is required for the
register operand.


Concept:

    Instruction
        │
        ├──► R1
        │
        └──► R2


============================================================
11.16 REGISTER ADDRESSING — EXAMPLE
============================================================

Suppose:

    R1 = 20
    R2 = 30


Instruction:

    ADD R1, R2


Possible result:

    R1 ← R1 + R2

    R1 = 20 + 30
       = 50


The operands are already inside CPU registers.


============================================================
11.17 ADVANTAGES OF REGISTER ADDRESSING
============================================================

Advantages:

    • Very fast
    • No memory access for operand
    • Shorter fields can identify registers
    • Excellent for frequently used data


Disadvantage:

    • Number of registers is limited.


============================================================
11.18 REGISTER INDIRECT ADDRESSING
============================================================

In register indirect addressing, a register contains
the memory address of the operand.


Formula:

    EA = R


where R contains an address.


Example:

    LOAD R1, (R2)


Suppose:

    R2 = 5000
    Memory[5000] = 75


Then:

    EA = R2
       = 5000


Therefore:

    R1 ← Memory[5000]
       = 75


IMPORTANT:

    Register contains the ADDRESS,
    not the actual data.


============================================================
11.19 REGISTER VS REGISTER INDIRECT
============================================================

REGISTER:

    R1 contains the DATA.


Example:

    ADD R1, R2


If:

    R2 = 50

then 50 itself is the operand.


REGISTER INDIRECT:

    R1/R2 contains the ADDRESS of the DATA.


Example:

    LOAD R1, (R2)


If:

    R2 = 5000
    Memory[5000] = 50

then:

    R2 → address
    Memory[5000] → data


============================================================
11.20 INDEXED ADDRESSING
============================================================

Indexed addressing calculates the effective address by
adding an address/displacement to an index register.


Formula:

    EA = A + XR


where:

    A  = address/displacement
    XR = index register


Example:

    LOAD R1, 1000(R2)


Suppose:

    R2 = 200


Then:

    EA = 1000 + 200
       = 1200


Therefore:

    R1 ← Memory[1200]


============================================================
11.21 WHY INDEXED ADDRESSING?
============================================================

Indexed addressing is extremely useful for arrays.


Suppose an array begins at address:

    1000


and each element occupies 4 bytes.


Addresses:

    A[0] → 1000
    A[1] → 1004
    A[2] → 1008
    A[3] → 1012


An index/offset can help calculate the desired element
address.


Concept:

    Base address + offset
             ↓
       Effective Address


============================================================
11.22 INDEXED ADDRESSING — ARRAY EXAMPLE
============================================================

Suppose:

    Base address = 1000
    Index = 3
    Element size = 4 bytes


Offset:

    3 × 4 = 12


Effective address:

    EA = 1000 + 12
       = 1012


Therefore:

    A[3] is stored at address 1012.


IMPORTANT:

    In real systems, the index may already be scaled
    depending on the instruction/ISA.


============================================================
11.23 BASE ADDRESSING
============================================================

Base addressing uses a base register plus an offset.


Formula:

    EA = BR + A


where:

    BR = Base Register
    A  = displacement/offset


Example:

    LOAD R1, 100(RB)


Suppose:

    RB = 5000


Then:

    EA = 5000 + 100
       = 5100


Therefore:

    R1 ← Memory[5100]


============================================================
11.24 INDEXED VS BASE ADDRESSING
============================================================

INDEXED:

    EA = A + Index Register


Often useful for:

    Arrays
    Loops
    Element selection


BASE:

    EA = Base Register + Offset


Often useful for:

    Data structures
    Relocatable programs
    Memory regions
    Stack frames


The exact terminology and uses vary between ISAs.


============================================================
11.25 RELATIVE ADDRESSING
============================================================

Relative addressing calculates the target address relative
to the current Program Counter (PC).


Formula:

    EA = PC + Offset


Example:

    PC = 1000
    Offset = 200


Then:

    EA = 1000 + 200
       = 1200


A branch instruction can use this to reach a nearby
instruction.


============================================================
11.26 WHY RELATIVE ADDRESSING?
============================================================

Relative addressing is especially useful for:

    • Branches
    • Loops
    • Conditional jumps
    • Position-independent code concepts


Example:

    BEQ +40


Meaning conceptually:

    If condition is true:

        target = current PC + 40


The exact PC used can depend on the ISA's definition.


============================================================
11.27 AUTO-INCREMENT ADDRESSING
============================================================

In auto-increment addressing:

    1. Use the address in a register.
    2. Access the operand.
    3. Increment the register.


Concept:

    EA = R

    Access Memory[EA]

    R ← R + increment


Example:

    LOAD R1, (R2)+


Suppose:

    R2 = 1000


Then:

    EA = 1000

    R1 ← Memory[1000]

    R2 ← R2 + element size


If the data size is 4 bytes:

    R2 becomes 1004.


============================================================
11.28 AUTO-INCREMENT — USE
============================================================

Useful when processing sequential data.


Example:

    Read array element 0
    Increment pointer
    Read array element 1
    Increment pointer
    Read array element 2
    ...


This reduces the number of explicit instructions needed
to update the pointer.


============================================================
11.29 AUTO-DECREMENT ADDRESSING
============================================================

In auto-decrement addressing, the register is decremented
before the operand is accessed.


Concept:

    R ← R - increment

    EA = R

    Access Memory[EA]


Example:

    LOAD R1, -(R2)


Suppose:

    R2 = 1000

and element size = 4 bytes.


First:

    R2 = 1000 - 4
       = 996


Then:

    EA = 996


Then:

    R1 ← Memory[996]


============================================================
11.30 AUTO-INCREMENT VS AUTO-DECREMENT
============================================================

AUTO-INCREMENT:

    Use address
        ↓
    Access data
        ↓
    Increment register


AUTO-DECREMENT:

    Decrement register
        ↓
    Use new address
        ↓
    Access data


These modes are useful for:

    • Arrays
    • Pointers
    • Stacks
    • Sequential data processing

============================================================

    ┌──────────────────────┬────────────────────────────┐
    │ Addressing Mode      │ Effective Address / Idea   │

11.39 NUMERICAL PROBLEM 8 — ARRAY ADDRESS
============================================================

An integer array starts at address:

    2000


Each integer occupies:

    4 bytes


Find the address of:

    A[5]


Formula:

    Address(A[i])
        = Base + (i × element size)


Therefore:

    Address(A[5])
        = 2000 + (5 × 4)

        = 2000 + 20

        = 2020


ANSWER:

    A[5] = 2020

    EA = R2
       = 1000


Step 2:

    R1 ← Memory[1000]


Step 3:

    R2 ← R2 + 4

    R2 = 1004


ANSWER:

    Operand address = 1000
    New R2 = 1004

11.42 SPEED COMPARISON
============================================================

Generally:

    Register
       ↓
    Very fast


    Immediate
       ↓
    Very fast


    Register Indirect
       ↓
    Requires memory access


    Direct
       ↓
    Requires memory access


    Indirect
       ↓
    May require additional memory access


BUT:

Actual performance depends on the processor,
cache hierarchy, pipeline, instruction encoding,
and microarchitecture.


Do NOT memorize a universal exact speed ranking.


============================================================
11.43 INSTRUCTION SIZE COMPARISON
============================================================

Immediate addressing:

    Instruction must contain the constant.


Direct addressing:

    Instruction must contain an address/field.


Register addressing:

    Usually needs only a register identifier.


Register identifiers generally require fewer bits than
full memory addresses.


Therefore:

    Register-based instructions can often be compact.


But actual instruction sizes depend on the ISA.


============================================================
11.44 FLEXIBILITY COMPARISON
============================================================

IMMEDIATE:

    Good for constants.


REGISTER:

    Good for fast CPU data.


DIRECT:

    Simple memory access.


INDIRECT:

    Useful when addresses are stored in memory.


REGISTER INDIRECT:

    Excellent for pointers.


INDEXED:

    Excellent for arrays.


BASE:

    Useful for structures and memory regions.


RELATIVE:

    Excellent for branches and nearby targets.


AUTO-INCREMENT:

    Useful for sequential data.


AUTO-DECREMENT:

    Useful for reverse traversal and stack-like operations.


============================================================
11.45 ADDRESSING MODES AND HIGH-LEVEL LANGUAGES
============================================================

Addressing modes help implement common programming
constructs.


High-level:

    A[i]


May become conceptually:

    Base address
         +
    Index × element size


For:

    if(condition)
        jump to LABEL


The processor may use:

    PC-relative addressing


For:

    *pointer


The processor may use:

    Register indirect addressing


Therefore:

    Addressing modes connect programming concepts
    with machine-level memory access.


============================================================
11.46 ADDRESSING MODES AND ARRAYS
============================================================

Suppose:

    Base = 1000
    Element size = 4


For:

    A[0]:

        1000 + (0 × 4)
        = 1000


    A[1]:

        1000 + (1 × 4)
        = 1004


    A[2]:

        1000 + (2 × 4)
        = 1008


    A[3]:

        1000 + (3 × 4)
        = 1012


This is why indexed/base-plus-offset addressing is
extremely useful.


============================================================
11.47 ADDRESSING MODES AND POINTERS
============================================================

Suppose:

    Pointer P contains:

        5000


and:

    Memory[5000] = 80


Then:

    P → 5000

    *P → Memory[5000] → 80


This corresponds conceptually to:

    Register Indirect Addressing


So:

    Pointer ≈ register containing an address


============================================================
11.48 ADDRESSING MODES AND STACKS
============================================================

The Stack Pointer (SP) contains the location of the
stack.


Stack operations may use:

    Auto-increment
    Auto-decrement


Conceptually:

    PUSH:

        Decrease SP
        Store value


    POP:

        Read value
        Increase SP


Exact ordering depends on the architecture.


============================================================
11.49 IMPORTANT DIFFERENCE:
     IMMEDIATE VS DIRECT
============================================================

IMMEDIATE:

    Value itself is in the instruction.


Example:

    ADD R1, #25

    Use:

        25


DIRECT:

    Instruction contains an address.


Example:

    ADD R1, 25

    Conceptually:

        Use Memory[25]


Therefore:

    Immediate → 25 is DATA

    Direct    → 25 is ADDRESS


This is one of the most important distinctions.


============================================================
11.50 IMPORTANT DIFFERENCE:
     DIRECT VS INDIRECT
============================================================

DIRECT:

    A = 1000

    EA = 1000


INDIRECT:

    A = 1000
    Memory[1000] = 5000

    EA = 5000


Therefore:

    Direct:
        Address field → Data


    Indirect:
        Address field → Address → Data


============================================================
11.51 IMPORTANT DIFFERENCE:
     REGISTER VS REGISTER INDIRECT
============================================================

REGISTER:

    R1 = 50

    Operand = 50


REGISTER INDIRECT:

    R1 = 5000

    Memory[5000] = 50

    Operand = 50


Therefore:

    Register:
        Register contains DATA


    Register indirect:
        Register contains ADDRESS


============================================================
11.52 COMMON MISTAKES
============================================================

MISTAKE 1:

    "Immediate addressing accesses memory."

CORRECT:

    The operand value is contained in the instruction.


MISTAKE 2:

    "Direct and indirect addressing are the same."

CORRECT:

    Direct:
        EA = A

    Indirect:
        EA = Memory[A]


MISTAKE 3:

    "Register indirect means the register contains data."

CORRECT:

    It contains the address of the data.


MISTAKE 4:

    "Indexed addressing always means array indexing."

CORRECT:

    It is commonly useful for arrays, but can be used
    for other address calculations.


MISTAKE 5:

    "Relative addressing always uses an absolute address."

CORRECT:

    The target is calculated relative to a reference,
    commonly the PC.


MISTAKE 6:

    "All processors support exactly these addressing modes."

CORRECT:

    Addressing modes are ISA-dependent.

    │ Relative             │ EA = PC + Offset            │
    │ Auto-Increment       │ Access, then increment      │
    │ Auto-Decrement       │ Decrement, then access      │
    └──────────────────────┴──────────────────────────────┘


============================================================
11.56 MOST IMPORTANT FORMULAS
============================================================

DIRECT:

    EA = A


INDIRECT:

    EA = Memory[A]


REGISTER INDIRECT:

    EA = R


INDEXED:

    EA = A + XR


BASE:

    EA = BR + A


RELATIVE:

    EA = PC + A


ARRAY:

    Address(A[i])
        = Base + (i × element_size)
