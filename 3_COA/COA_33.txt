CHAPTER 33 — COMPUTER PERFORMANCE

============================================================
CHAPTER 33 — COMPUTER PERFORMANCE
============================================================

LEVEL:
B.Tech 1st Year → University Foundation → Competitive Exam
→ Intermediate → Advanced

GOAL:
Understand how computer performance is measured, calculated,
compared, and improved.

============================================================
33.1 WHAT IS COMPUTER PERFORMANCE?
============================================================

Computer performance tells us:

    "How quickly a computer completes a given task."

In simple words:

    Better performance
        ↓
    Less time to complete the same work


Example:

    Computer A completes a program in 5 seconds.

    Computer B completes the same program in 10 seconds.

    Computer A is faster for that program.


IMPORTANT:

    Performance is NOT simply:

        "Higher clock speed = faster computer"

Performance depends on many factors:

    • Instruction count
    • CPI
    • Clock cycle time
    • Clock rate
    • Memory performance
    • Cache behavior
    • Pipeline efficiency
    • Branch prediction
    • I/O
    • Program characteristics


============================================================
33.2 PERFORMANCE VS EXECUTION TIME
============================================================

Execution time:

    Time taken to execute a program.


Performance:

    Amount of work completed per unit time.


For the same task:

    Performance ∝ 1 / Execution Time


Therefore:

    Higher performance
        =
    Lower execution time


Example:

    Computer A:
        Execution time = 4 s

    Computer B:
        Execution time = 8 s


Performance ratio:

    Performance(A) / Performance(B)

        = 8 / 4

        = 2


Therefore:

    A is 2× as fast as B.


============================================================
33.3 RESPONSE TIME
============================================================

Response time is the total time between:

    Request
       ↓
    Completion


Example:

    You click "Open File"
       ↓
    File becomes available


The elapsed time is the response time.


Response time is especially important for:

    • Interactive applications
    • Web applications
    • Operating systems
    • Databases


============================================================
33.4 LATENCY
============================================================

Latency is the delay before an operation completes or before
its result is available.


Example:

    Network request:
        Request → response

    The delay is network latency.


CPU/memory/storage systems also have latency.


Generally:

    Lower latency
        ↓
    Faster response


============================================================
33.5 THROUGHPUT
============================================================

Throughput measures how much work can be completed per unit
of time.


Examples:

    • Requests per second
    • Instructions per second
    • Transactions per second
    • GB/s
    • Jobs per hour


Example:

    Server processes:

        10,000 requests/second


Its throughput is:

        10,000 requests/s


============================================================
33.6 LATENCY VS THROUGHPUT
============================================================

LATENCY:

    Time required for one operation.


THROUGHPUT:

    Amount of work completed per unit time.


Example:

    A factory may take 1 hour to produce one special product
    but produce 100 products per hour once the assembly line
    is operating continuously.


Therefore:

    Low latency does not always mean maximum throughput.


============================================================
33.7 RESPONSE TIME VS THROUGHPUT
============================================================

Response time:

    How long one task takes.


Throughput:

    How many tasks can be completed per unit time.


Example:

    Server A:
        20 ms response time

    Server B:
        30 ms response time


A may have lower latency.

But B could potentially have greater throughput if it processes
many requests in parallel.


============================================================
33.8 CPU PERFORMANCE
============================================================

For CPU execution, a very important relationship is:

    CPU Time
    =
    CPU Clock Cycles
    ×
    Clock Cycle Time


Since:

    Clock Cycle Time = 1 / Clock Rate


We get:

    CPU Time
    =
    CPU Clock Cycles / Clock Rate


This is one of the most important formulas in COA.


============================================================
33.9 CPU PERFORMANCE EQUATION
============================================================

CPU execution time can be written as:

    CPU Time
    =
    Instruction Count
    ×
    CPI
    ×
    Clock Cycle Time


Where:

    Instruction Count = number of executed instructions

    CPI = Cycles Per Instruction

    Clock Cycle Time = time per clock cycle


Since:

    Clock Cycle Time = 1 / Clock Rate


Therefore:

    CPU Time
    =
    Instruction Count × CPI
    --------------------------------
             Clock Rate


============================================================
33.10 THE THREE MAIN FACTORS
============================================================

CPU TIME depends on:

    1. Instruction Count
    2. CPI
    3. Clock Cycle Time


Therefore:

    CPU Time
    =
    IC × CPI × Cycle Time


or:

    CPU Time
    =
    IC × CPI / Clock Rate


To improve performance:

    Instruction Count ↓
    CPI ↓
    Clock Cycle Time ↓

or:

    Clock Rate ↑


But changing one factor can affect the others.


============================================================
33.11 INSTRUCTION COUNT
============================================================

Instruction Count (IC) is the number of instructions executed
by the CPU for a program.


Example:

    Program executes:

        1,000,000 instructions


Then:

    IC = 1,000,000


Instruction count depends on:

    • Program
    • ISA
    • Compiler
    • Optimization
    • Algorithm


============================================================
33.12 CPI
============================================================

CPI = Cycles Per Instruction


It tells us the average number of clock cycles required per
executed instruction.


Example:

    Program executes:

        1,000 instructions

    Total CPU cycles:

        2,000


Then:

    CPI = 2000 / 1000

        = 2


Therefore:

    Average CPI = 2 cycles/instruction


============================================================
33.13 CLOCK CYCLE
============================================================

A CPU operates using clock cycles.


If:

    Clock frequency = 1 GHz


Then:

    1 GHz = 1,000,000,000 cycles/second


Clock cycle time:

    = 1 / 1 GHz

    = 1 ns


Therefore:

    1 GHz → 1 ns per cycle


============================================================
33.14 CLOCK RATE
============================================================

Clock rate is the number of clock cycles per second.


Units:

    Hz
    kHz
    MHz
    GHz


Examples:

    1 MHz = 10^6 Hz

    1 GHz = 10^9 Hz

    3 GHz = 3 × 10^9 Hz


Higher clock rate can potentially improve performance,
but it is NOT sufficient by itself to compare processors.


============================================================
33.15 CLOCK RATE VS CLOCK CYCLE TIME
============================================================

They are inversely related.


Formula:

    Cycle Time = 1 / Clock Rate


and:

    Clock Rate = 1 / Cycle Time


Example:

    Clock rate = 2 GHz


Cycle time:

    = 1 / (2 × 10^9)

    = 0.5 ns


Therefore:

    2 GHz → 0.5 ns/cycle


============================================================
33.16 EXAMPLE — CPU TIME
============================================================

Given:

    Instruction Count = 1,000,000

    CPI = 2

    Clock Rate = 1 GHz


Formula:

    CPU Time
    =
    IC × CPI / Clock Rate


Substitute:

    = (1,000,000 × 2)
      / 1,000,000,000

    = 2,000,000 / 1,000,000,000

    = 0.002 s

    = 2 ms


ANSWER:

    CPU Time = 2 ms


============================================================
33.17 EXAMPLE — FIND CPI
============================================================

Given:

    Instruction Count = 2,000,000

    CPU Time = 4 ms

    Clock Rate = 1 GHz


Formula:

    CPU Time
    =
    IC × CPI / Clock Rate


Therefore:

    CPI
    =
    CPU Time × Clock Rate
    ----------------------
    Instruction Count


Substitute:

    CPI
    =
    (0.004)(10^9)
    ----------------
       2 × 10^6

    = 2


ANSWER:

    CPI = 2


============================================================
33.18 EXAMPLE — FIND CLOCK RATE
============================================================

Given:

    IC = 10^6

    CPI = 2

    CPU Time = 4 ms


Formula:

    Clock Rate
    =
    IC × CPI / CPU Time


    = (10^6 × 2) / 0.004

    = 500 × 10^6 Hz

    = 500 MHz


ANSWER:

    Clock Rate = 500 MHz


============================================================
33.19 CPU CYCLES
============================================================

CPU cycles can be calculated using:

    CPU Cycles
    =
    Instruction Count × CPI


Example:

    IC = 5 million

    CPI = 3


Then:

    CPU Cycles
    =
    5 × 10^6 × 3

    = 15 × 10^6 cycles


============================================================
33.20 DIFFERENT INSTRUCTION TYPES
============================================================

Not every instruction necessarily takes the same number of
cycles.


Example:

    Arithmetic instruction → 1 cycle
    Load instruction       → 3 cycles
    Branch instruction     → 2 cycles


Therefore, we use:

    Average CPI


Formula:

    Average CPI
    =
    Total CPU Cycles
    ----------------
    Total Instructions


============================================================
33.21 WEIGHTED AVERAGE CPI
============================================================

Suppose:

    Instruction Type A:
        50% of instructions
        CPI = 1

    Instruction Type B:
        30% of instructions
        CPI = 2

    Instruction Type C:
        20% of instructions
        CPI = 4


Average CPI:

    = (0.50 × 1)
      + (0.30 × 2)
      + (0.20 × 4)

    = 0.50 + 0.60 + 0.80

    = 1.90


ANSWER:

    Average CPI = 1.9


============================================================
33.22 PERFORMANCE AND CPU TIME
============================================================

For the same workload:

    Performance ∝ 1 / CPU Time


If:

    CPU Time decreases by 2×

Then:

    Performance increases by 2×


Example:

    Old time = 10 s

    New time = 5 s


Speedup:

    = Old Time / New Time

    = 10 / 5

    = 2


Therefore:

    New system is 2× faster.


============================================================
33.23 SPEEDUP
============================================================

Speedup measures how much faster a new system/design is than
an old system/design.


Formula:

    Speedup
    =
    Old Execution Time
    ------------------
    New Execution Time


If:

    Old = 20 seconds

    New = 10 seconds


Then:

    Speedup = 20 / 10

            = 2


Therefore:

    2× speedup


============================================================
33.24 SPEEDUP INTERPRETATION
============================================================

Speedup = 1:

    No improvement.


Speedup > 1:

    Improvement.


Speedup < 1:

    New system is slower.


Example:

    Speedup = 1.5

Means:

    New system is 1.5× as fast.


============================================================
33.25 PERCENTAGE PERFORMANCE IMPROVEMENT
============================================================

A common formula is:

    Improvement
    =
    (Old Time - New Time)
    ----------------------
         Old Time
    × 100%


Example:

    Old = 10 s

    New = 8 s


    Improvement
    =
    (10 - 8) / 10 × 100

    = 20%


Therefore:

    Execution time improved by 20%.


IMPORTANT:

    "20% faster" and "20% less execution time" are not always
    mathematically identical statements.


============================================================
33.26 BENCHMARKING
============================================================

A benchmark is a program or workload used to measure system
performance.


Examples of benchmark categories:

    • CPU benchmarks
    • Memory benchmarks
    • Storage benchmarks
    • Database benchmarks
    • Graphics benchmarks


Benchmarking helps compare systems under controlled workloads.


============================================================
33.27 WHY BENCHMARKS ARE NEEDED
============================================================

A processor may be faster for one type of workload and slower
for another.


Example:

    CPU A:
        Excellent integer performance


    CPU B:
        Excellent floating-point performance


Depending on the application:

    A or B may be faster.


Therefore:

    No single benchmark can represent all possible workloads.


============================================================
33.28 BENCHMARK CHARACTERISTICS
============================================================

A useful benchmark should be:

    • Representative
    • Reproducible
    • Relevant
    • Measurable
    • Fair


Results should be compared under similar conditions.


============================================================
33.29 SYNTHETIC VS REAL-WORLD BENCHMARKS
============================================================

SYNTHETIC BENCHMARK:

    Specifically designed to measure particular properties.


REAL-WORLD / APPLICATION BENCHMARK:

    Uses actual applications or realistic workloads.


Both can be useful.


============================================================
33.30 CPU PERFORMANCE EQUATION — COMPLETE VIEW
============================================================

                  Instruction Count
                          |
                          ↓
Program  ─────────────→  Instructions
                          |
                          ↓
                         CPI
                          |
                          ↓
                     CPU Cycles
                          |
                          ↓
                      Clock Rate
                          |
                          ↓
                      CPU Time


Formula:

    CPU Time
    =
    IC × CPI × Cycle Time


or:

    CPU Time
    =
    IC × CPI
    ----------
    Clock Rate


============================================================
33.31 PERFORMANCE EQUATION
============================================================

Since:

    Performance ∝ 1 / CPU Time


Then:

    Performance
    ∝
    Clock Rate
    -----------------
    IC × CPI


Therefore:

    To improve performance:

        Clock Rate ↑
        IC ↓
        CPI ↓


============================================================
33.32 IMPORTANT TRADE-OFF
============================================================

Suppose CPU A has:

    Clock rate = 4 GHz
    CPI = 2


CPU B has:

    Clock rate = 3 GHz
    CPI = 1


Do NOT immediately conclude:

    A is faster because 4 GHz > 3 GHz.


Compare:

    CPU time ∝ CPI / Clock Rate


A:

    2 / 4 = 0.5


B:

    1 / 3 ≈ 0.333


Therefore:

    B can execute the same number of instructions faster.


KEY LESSON:

    Clock rate alone does not determine performance.


============================================================
33.33 INSTRUCTION COUNT TRADE-OFF
============================================================

Compiler A:

    Instruction count = 1 billion
    CPI = 1


Compiler B:

    Instruction count = 500 million
    CPI = 2


Assume same clock rate.


CPU cycles:

    A:
        1B × 1 = 1B cycles


    B:
        500M × 2 = 1B cycles


Therefore:

    Both require the same number of cycles.


This demonstrates why:

    IC and CPI must be considered together.


============================================================
33.34 CPU TIME VS ELAPSED TIME
============================================================

CPU time:

    Time during which CPU executes a program.


Elapsed time:

    Total time from start to completion.


Elapsed time may include:

    • CPU time
    • Waiting for memory
    • I/O
    • OS scheduling
    • Other system delays


Therefore:

    Elapsed time ≥ CPU execution time


in typical situations.


============================================================
33.35 USER CPU TIME
============================================================

User CPU time:

    Time CPU spends executing user-level application code.


Example:

    Browser/application computation.


============================================================
33.36 SYSTEM CPU TIME
============================================================

System CPU time:

    Time CPU spends executing operating-system/kernel code
    on behalf of the application.


Therefore:

    Total CPU time
    =
    User CPU time
    +
    System CPU time


============================================================
33.37 CPU UTILIZATION
============================================================

CPU utilization indicates the percentage of time CPU resources
are busy doing useful work.


Conceptually:

    CPU Utilization
    =
    Busy Time
    ------------
    Total Time
    × 100%


Example:

    CPU busy = 8 s

    Total = 10 s


    Utilization
    =
    8 / 10 × 100

    = 80%


============================================================
33.38 THROUGHPUT EXAMPLE
============================================================

Suppose a server completes:

    600 requests

in:

    10 seconds


Throughput:

    = 600 / 10

    = 60 requests/s


============================================================
33.39 THROUGHPUT IMPROVEMENT
============================================================

Suppose:

    Old throughput = 100 jobs/s

    New throughput = 150 jobs/s


Increase:

    = 150 - 100
    = 50 jobs/s


Percentage increase:

    = 50 / 100 × 100

    = 50%


============================================================
33.40 AVERAGE EXECUTION TIME
============================================================

Suppose several programs have execution times:

    Program A = 2 s
    Program B = 4 s
    Program C = 6 s


Arithmetic mean:

    = (2 + 4 + 6) / 3

    = 4 s


But simply averaging times is not always the best way to
compare systems because workloads may have different
importance or frequencies.


============================================================
33.41 WEIGHTED AVERAGE
============================================================

Suppose workloads occur with frequencies:

    A:
        Time = 2 s
        Weight = 60%

    B:
        Time = 5 s
        Weight = 40%


Weighted time:

    = (0.6 × 2) + (0.4 × 5)

    = 1.2 + 2

    = 3.2 s


============================================================
33.42 GEOMETRIC MEAN
============================================================

For comparing normalized benchmark ratios, geometric mean is
often useful.


For n values:

    Geometric Mean
    =
    (x1 × x2 × ... × xn)^(1/n)


It is commonly used when combining normalized performance
ratios.


============================================================
33.43 NORMALIZED PERFORMANCE
============================================================

Suppose a reference system has:

    Performance = 1


Another system has:

    Performance = 2


Normalized performance:

    = 2 / 1

    = 2


Therefore:

    2× the reference performance.


============================================================
33.44 AMDAHL'S LAW
============================================================

Amdahl's Law describes the maximum overall speedup obtainable
when only part of a system/program is improved.


Very important for COA.


Suppose:

    A fraction P of execution benefits from an improvement
    by factor S.


Then:

    Overall Speedup
    =
    1
    -------------------------
    (1 - P) + (P / S)


Where:

    P = fraction improved

    S = speedup of improved part


============================================================
33.45 AMDAHL'S LAW INTUITION
============================================================

Imagine a program takes:

    100 seconds


Suppose:

    80 seconds → part that can be improved
    20 seconds → part that cannot be improved


Even if the 80-second portion becomes infinitely fast:

    80 seconds → 0 seconds

Remaining:

    20 seconds


Therefore:

    Maximum possible speedup
    =
    100 / 20

    = 5×


This is the central idea of Amdahl's Law.


============================================================
33.46 AMDAHL'S LAW FORMULA
============================================================

    Speedup
    =
              1
    ----------------------
    (1 - P) + P/S


Where:

    P = fraction improved

    S = speedup of improved portion


============================================================
33.47 AMDAHL'S LAW EXAMPLE
============================================================

Suppose:

    60% of program can be accelerated.

Therefore:

    P = 0.6


The improved part becomes:

    5× faster.

Therefore:

    S = 5


Formula:

    Overall Speedup
    =
    1
    ----------------
    0.4 + 0.6/5


    =
    1
    ----------------
    0.4 + 0.12


    =
    1 / 0.52

    ≈ 1.923


ANSWER:

    Overall speedup ≈ 1.92×


Even though one part became:

    5× faster

the whole program improved by only:

    ≈ 1.92×


============================================================
33.48 AMDAHL'S LAW — INFINITE SPEEDUP
============================================================

If:

    S → ∞


Then:

    P/S → 0


So:

    Speedup
    =
    1 / (1 - P)


Therefore maximum speedup is:

    1 / (1 - P)


Example:

    P = 0.9


Maximum:

    = 1 / 0.1

    = 10×


Even infinite improvement of 90% of the program gives only:

    10× overall speedup.


============================================================
33.49 AMDAHL'S LAW — IMPORTANT LESSON
============================================================

To obtain large overall speedup:

    Improve the portion that consumes a large fraction
    of execution time.


Therefore:

    Optimize the bottleneck first.


This idea appears throughout computer architecture.


============================================================
33.50 CPU PERFORMANCE AND MEMORY
============================================================

A CPU may be extremely fast but still spend significant time
waiting for memory.


Example:

    CPU
     |
    Cache
     |
    RAM
     |
    Storage


If cache misses are frequent:

    CPU may stall.


Therefore:

    Effective system performance depends on memory hierarchy.


============================================================
33.51 CACHE AND PERFORMANCE
============================================================

Cache improves performance by exploiting:

    Temporal locality

    Spatial locality


If data is found in cache:

    CACHE HIT


If data is not found:

    CACHE MISS


A miss causes additional delay:

    MISS PENALTY


Therefore:

    Higher hit ratio
        ↓
    Usually better performance


============================================================
33.52 PIPELINING AND PERFORMANCE
============================================================

Pipelining increases:

    Instruction throughput


It does not necessarily reduce the latency of an individual
instruction by the same amount.


Example:

    Without pipeline:

        Instruction 1
        Instruction 2
        Instruction 3


    With pipeline:

        IF → ID → EX → MEM → WB


Multiple instructions can occupy different stages
simultaneously.


============================================================
33.53 PERFORMANCE AND HAZARDS
============================================================

Pipeline hazards can reduce performance.


Types:

    Structural hazard
    Data hazard
    Control hazard


Solutions include:

    • Forwarding
    • Stalling
    • Branch prediction
    • Pipeline flushing


Therefore:

    Ideal pipeline performance
    ≠
    Real pipeline performance


============================================================
33.54 PERFORMANCE EQUATION WITH STALLS
============================================================

A simplified model:

    CPU Cycles
    =
    Ideal CPU Cycles
    +
    Stall Cycles


Therefore:

    CPU Time
    =
    Total CPU Cycles × Cycle Time


If stalls increase:

    CPU time increases.


============================================================
33.55 CPI WITH STALLS
============================================================

A simplified relationship:

    Actual CPI
    =
    Ideal CPI
    +
    Stall cycles per instruction


Example:

    Ideal CPI = 1

    Memory stalls = 0.3 cycles/instruction

    Branch stalls = 0.2 cycles/instruction


Then:

    Actual CPI
    =
    1 + 0.3 + 0.2

    = 1.5


============================================================
33.56 BENCHMARK PERFORMANCE
============================================================

Benchmark results can be influenced by:

    • Compiler
    • Compiler optimization
    • Memory size
    • Cache size
    • Operating system
    • Background processes
    • Thermal throttling
    • Power limits
    • Input dataset
    • Hardware configuration


Therefore benchmark comparisons must be made carefully.


============================================================
33.57 PERFORMANCE BOTTLENECK
============================================================

A bottleneck is the part of a system that limits overall
performance.


Examples:

    CPU bottleneck
    Memory bottleneck
    Storage bottleneck
    Network bottleneck
    I/O bottleneck


Example:

    Very fast CPU
        +
    Very slow storage


The storage may become the bottleneck.


============================================================
33.58 CPU-BOUND VS MEMORY-BOUND
============================================================

CPU-BOUND:

    Performance is mainly limited by CPU computation.


MEMORY-BOUND:

    Performance is mainly limited by memory accesses.


CPU-bound workload:

    Complex calculations
    Heavy computation


Memory-bound workload:

    Large data structures
    Frequent memory accesses


============================================================
33.59 PERFORMANCE TRADE-OFFS
============================================================

Improving one metric may hurt another.


Examples:

    Higher clock rate
        → More power/heat


    Larger cache
        → More area/cost


    More complex hardware
        → More design complexity


    More aggressive speculation
        → More energy and hardware complexity


    Larger storage
        → Potentially higher cost


Architecture is therefore about:

    BALANCING TRADE-OFFS


============================================================
33.60 POWER VS PERFORMANCE
============================================================

Higher performance often requires more:

    • Transistors
    • Power
    • Cooling
    • Hardware complexity


Modern architecture therefore focuses on:

    Performance per watt


Formula:

    Performance per Watt
    =
    Performance / Power


Higher is generally better.


============================================================
33.61 ENERGY VS POWER
============================================================

POWER:

    Rate of energy consumption.


Unit:

    Watt


ENERGY:

    Total amount of energy used.


Unit:

    Joule


Relationship:

    Energy = Power × Time


Therefore:

    A faster computer may consume more power instantaneously
    but potentially use less total energy for the same task if
    it finishes much sooner.


============================================================
33.62 EXAMPLE — ENERGY
============================================================

Computer A:

    Power = 100 W

    Time = 10 s


Energy:

    = 100 × 10

    = 1000 J


Computer B:

    Power = 150 W

    Time = 5 s


Energy:

    = 150 × 5

    = 750 J


Even though B uses more power:

    B uses less total energy for this task.


============================================================
33.63 PERFORMANCE/WATT
============================================================

Suppose:

    System A:
        Performance = 100 units
        Power = 50 W


    Performance/Watt
    = 100 / 50

    = 2 units/W


System B:

    Performance = 120 units
    Power = 80 W


    = 120 / 80

    = 1.5 units/W


Therefore:

    A has better performance per watt.


============================================================
33.64 IMPORTANT PERFORMANCE METRICS
============================================================

Remember:

    Execution Time
        → How long task takes


    Response Time
        → Delay experienced by requester


    Latency
        → Delay for an operation


    Throughput
        → Work per unit time


    CPI
        → Cycles per instruction


    Clock Rate
        → Cycles per second


    Speedup
        → Relative performance improvement


    CPU Utilization
        → Fraction of time CPU is busy


============================================================
33.65 B.TECH NUMERICAL — FULL CPU TIME
============================================================

Given:

    Instruction Count = 2 × 10^9

    CPI = 1.5

    Clock Rate = 3 GHz


Formula:

    CPU Time
    =
    IC × CPI / Clock Rate


    =
    (2 × 10^9)(1.5)
    ----------------
       3 × 10^9


    =
    3 × 10^9 / 3 × 10^9


    = 1 second


ANSWER:

    CPU Time = 1 second


============================================================
33.66 B.TECH NUMERICAL — COMPARE TWO CPUs
============================================================

CPU A:

    IC = 10^9
    CPI = 2
    Clock = 2 GHz


CPU B:

    IC = 10^9
    CPI = 1.5
    Clock = 2 GHz


CPU A:

    Time
    =
    (10^9 × 2) / (2 × 10^9)

    = 1 s


CPU B:

    Time
    =
    (10^9 × 1.5) / (2 × 10^9)

    = 0.75 s


Speedup of B over A:

    = 1 / 0.75

    = 1.333×


ANSWER:

    CPU B is approximately 1.33× faster.


============================================================
33.67 B.TECH NUMERICAL — EFFECT OF CLOCK RATE
============================================================

Same program:

    IC = 10^9
    CPI = 2


CPU A:

    2 GHz


CPU B:

    4 GHz


CPU A:

    Time = (10^9 × 2)/(2 × 10^9)

         = 1 s


CPU B:

    Time = (10^9 × 2)/(4 × 10^9)

         = 0.5 s


Speedup:

    = 1 / 0.5

    = 2×


============================================================
33.68 B.TECH NUMERICAL — AMDAHL'S LAW
============================================================

Suppose:

    80% of execution can be improved.

    P = 0.8


Improvement:

    4×


    S = 4


Overall speedup:

    = 1 / [(1 - 0.8) + (0.8/4)]

    = 1 / [0.2 + 0.2]

    = 1 / 0.4

    = 2.5


ANSWER:

    Overall speedup = 2.5×

Q1. Which quantity is inversely proportional to performance

    A. Execution time
    B. Clock rate
    C. Throughput
    D. Instruction count

33.70 COMMON EXAM TRAPS
============================================================

TRAP 1:

    "Higher GHz always means faster."

FALSE.

Correct:

    Performance depends on IC, CPI and clock rate.


------------------------------------------------------------

TRAP 2:

    "CPI is always an integer."

FALSE.

Average CPI can be fractional.

Example:

    CPI = 1.4


------------------------------------------------------------

TRAP 3:

    "Speedup = New Time / Old Time."

Usually FALSE.

Correct:

    Speedup
    =
    Old Time / New Time


------------------------------------------------------------

TRAP 4:

    "Throughput and latency are the same."

FALSE.


------------------------------------------------------------

TRAP 5:

    "If one part becomes infinitely fast, the entire program
     becomes infinitely fast."

FALSE.

Amdahl's Law limits overall speedup.


------------------------------------------------------------

TRAP 6:

    "CPU time equals elapsed time in every case."

FALSE.

Elapsed time can include I/O and waiting.

33.71 HIGH-VALUE FORMULAS
============================================================

1. CPU Time:

    CPU Time
    =
    IC × CPI × Cycle Time


2. Using clock rate:

    CPU Time
    =
    IC × CPI
    ----------
    Clock Rate


3. CPU Cycles:

    CPU Cycles
    =
    IC × CPI


4. Clock Cycle Time:

    Cycle Time
    =
    1 / Clock Rate


5. CPI:

    CPI
    =
    CPU Cycles / Instruction Count


6. Speedup:

    Speedup
    =
    Old Time / New Time


7. Throughput:

    Throughput
    =
    Work / Time


8. CPU Utilization:

    Utilization
    =
    Busy Time / Total Time × 100%


9. Energy:

    Energy
    =
    Power × Time


10. Amdahl's Law:

    Speedup
    =
    1 / [(1-P) + P/S]


11. Maximum Amdahl Speedup:

    Speedup_max
    =
    1 / (1-P)

33.73 FINAL REVISION
============================================================

Remember these five ideas:

    1. Performance is inversely related to execution time.

    2. CPU Time =
           Instruction Count × CPI / Clock Rate

    3. Speedup =
           Old Time / New Time

    4. Throughput =
           Work / Time

    5. Amdahl's Law:
           Improving only one part of a system limits
           the overall speedup.

    +---------------------------------------------+
