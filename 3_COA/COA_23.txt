------------------------------------------------------------
23.1 WHAT IS AN I/O INTERFACE?
------------------------------------------------------------

An I/O interface is the hardware/software mechanism that
allows the CPU/system to communicate with an external device.

Basic structure:

        +-------------+
        |    CPU      |
        +-------------+
               |
               ↓
          System Bus
               |
               ↓
        +-------------+
        | I/O Interface|
        +-------------+
               |
               ↓
          I/O Device


Examples:

    CPU ↔ USB interface ↔ Keyboard
    CPU ↔ PCIe interface ↔ GPU
    CPU ↔ SATA interface ↔ HDD
    CPU ↔ PCIe/NVMe ↔ SSD


------------------------------------------------------------
23.2 WHY DO WE NEED I/O INTERFACES?
------------------------------------------------------------

Different devices have different:

    • Speeds
    • Data formats
    • Timing requirements
    • Communication protocols
    • Electrical characteristics
    • Transfer methods

The interface provides a standard method of communication.

Example:

    CPU works with digital data.

    Keyboard has its own communication protocol.

The interface translates/manages the communication between
them.


------------------------------------------------------------
23.3 BASIC I/O COMMUNICATION
------------------------------------------------------------

A typical data path:

    Application
         ↓
    Operating System
         ↓
    Device Driver
         ↓
    I/O Controller/Interface
         ↓
    Bus
         ↓
    Device


At the hardware level:

    CPU
     |
     ↓
    Bus
     |
     ↓
    Controller
     |
     ↓
    Device


------------------------------------------------------------
23.4 WHAT IS A BUS?
------------------------------------------------------------

A bus is a communication pathway used to transfer information
between components of a computer system.

A bus may carry:

    • Data
    • Addresses
    • Control information

Simple analogy:

    Bus = Highway
    Data = Vehicles
    Devices = Locations
    Bus controller = Traffic management


------------------------------------------------------------
23.5 TYPES OF BUS SIGNALS
------------------------------------------------------------

Traditional system buses contain:

    1. Address bus
    2. Data bus
    3. Control bus


ADDRESS BUS:

    Carries address information.

    Example:
        "Which memory location/device?"


DATA BUS:

    Carries actual data.

    Example:
        10110110


CONTROL BUS:

    Carries control and timing information.

    Examples:
        Read
        Write
        Interrupt
        Bus request
        Bus acknowledge


------------------------------------------------------------
23.6 BUS WIDTH
------------------------------------------------------------

Bus width = number of bits that can be transferred in
parallel in one bus transfer.

Example:

    8-bit bus
        → 8 bits

    16-bit bus
        → 16 bits

    32-bit bus
        → 32 bits

    64-bit bus
        → 64 bits


A wider bus can transfer more bits per transfer, assuming other
conditions are comparable.


------------------------------------------------------------
23.7 SERIAL COMMUNICATION
------------------------------------------------------------

In serial communication, bits are transmitted sequentially
over a communication link.

Example:

    Data:

    10110110

    Sent as:

    1 → 0 → 1 → 1 → 0 → 1 → 1 → 0


Conceptually:

    Sender
      |
      | 1 → 0 → 1 → 1 → 0 → 1 → 1 → 0
      ↓
    Receiver


Only a small number of signal paths may be needed.


------------------------------------------------------------
23.8 PARALLEL COMMUNICATION
------------------------------------------------------------

In parallel communication, multiple bits are transmitted
simultaneously using multiple signal lines.

Example:

    10110110


Conceptually:

    Bit 1 ───────────────→
    Bit 2 ───────────────→
    Bit 3 ───────────────→
    Bit 4 ───────────────→
    Bit 5 ───────────────→
    Bit 6 ───────────────→
    Bit 7 ───────────────→
    Bit 8 ───────────────→


Multiple bits travel at the same time.


------------------------------------------------------------
23.9 SERIAL VS PARALLEL
------------------------------------------------------------

+----------------------+-----------------------+
| Serial              | Parallel             |
+----------------------+-----------------------+
| Bits sent            | Multiple bits sent   |
| sequentially         | simultaneously       |
+----------------------+-----------------------+
| Fewer signal lines   | More signal lines    |
+----------------------+-----------------------+
| Good for longer/     | Useful in suitable   |
| high-speed links     | short-distance       |
| in modern systems    | applications         |
+----------------------+-----------------------+
| Example: USB, SATA,  | Example: older       |
| PCIe                 | parallel buses       |
+----------------------+-----------------------+


IMPORTANT:

Do not assume:

    Parallel = always faster
    Serial = always slower

Modern serial links can be extremely fast.

Examples:

    USB
    SATA
    PCI Express


------------------------------------------------------------
23.10 WHY MODERN SYSTEMS USE HIGH-SPEED SERIAL LINKS
------------------------------------------------------------

Parallel buses face problems such as:

    • Signal synchronization
    • Skew between lines
    • Crosstalk
    • More physical connections
    • Increasing difficulty at high frequencies

High-speed serial communication can reduce these problems.

Therefore modern computers heavily use serial technologies.


------------------------------------------------------------
23.11 SYNCHRONOUS COMMUNICATION
------------------------------------------------------------

In synchronous communication, sender and receiver operate
according to a shared or coordinated timing mechanism.

A clock may be used.

Conceptually:

    Clock:
    ↑ ↓ ↑ ↓ ↑ ↓ ↑ ↓

    Data:
    1  0  1  1  0  1


The receiver knows when to sample the data.


------------------------------------------------------------
23.12 ASYNCHRONOUS COMMUNICATION
------------------------------------------------------------

Asynchronous communication does not require a continuously
shared clock in the same way.

Timing information may be incorporated into the protocol.

A common conceptual example is:

    Start bit
    Data bits
    Optional parity
    Stop bit


The receiver uses the protocol to determine how to interpret
the incoming data.


------------------------------------------------------------
23.13 WHAT IS AN I/O BUS?
------------------------------------------------------------

An I/O bus is a communication pathway used to connect
processors/memory/controllers with I/O devices.

Examples:

    USB
    PCI
    PCIe
    SATA


Different buses are designed for different purposes.


------------------------------------------------------------
23.14 BUS PROTOCOL
------------------------------------------------------------

A bus protocol defines the rules for communication over a bus.

It specifies things such as:

    • How devices communicate
    • How transfers begin
    • How addresses are sent
    • How data is transferred
    • How errors are handled
    • How devices gain access to the bus


Think:

    Bus = road

    Bus protocol = traffic rules


------------------------------------------------------------
23.15 BUS TRANSACTION
------------------------------------------------------------

A bus transaction is a complete communication operation over
the bus.

For example:

    READ operation:

    1. Master requests a read.
    2. Address is provided.
    3. Device responds.
    4. Data is transferred.


Conceptually:

    Master
      |
      | Address + READ
      ↓
     BUS
      |
      ↓
    Device
      |
      | Data
      ↓
     BUS
      |
      ↓
    Master


------------------------------------------------------------
23.16 BUS MASTER AND BUS SLAVE
------------------------------------------------------------

A bus master is a component that initiates a bus transaction.

Examples:

    CPU
    DMA controller
    Other bus-mastering devices


A slave/target responds to the transaction.

Example:

    CPU → requests data from device

    CPU = Master
    Device = Target/Slave


Important:

A modern system may allow multiple components to act as bus
masters.


------------------------------------------------------------
23.17 BUS ARBITRATION
------------------------------------------------------------

Suppose multiple devices want to use the bus at the same time.

Example:

    CPU ─────┐
    DMA ─────┤
    GPU ─────┤→ BUS
    Other ───┘


They cannot all necessarily control the bus simultaneously.

Therefore, a mechanism is needed to decide:

    WHO GETS THE BUS?


This process is called:

    BUS ARBITRATION


------------------------------------------------------------
23.18 WHY IS BUS ARBITRATION NEEDED?
------------------------------------------------------------

Without arbitration:

    CPU writes data
    DMA writes data
    Another device writes data

at the same time.

This could cause:

    • Data corruption
    • Signal conflicts
    • Incorrect transfers


Arbitration ensures controlled access.


------------------------------------------------------------
23.19 CENTRALIZED BUS ARBITRATION
------------------------------------------------------------

In centralized arbitration, one central arbiter controls
access to the bus.

Conceptually:

              +----------------+
              | Bus Arbiter    |
              +----------------+
                ↑    ↑    ↑
                |    |    |
               CPU  DMA  Device
                \    |    /
                 \   |   /
                    BUS


The arbiter decides which requester gets bus access.


------------------------------------------------------------
23.20 CENTRALIZED ARBITRATION PROCESS
------------------------------------------------------------

Suppose:

    CPU requests bus.
    DMA requests bus.


Process:

    1. CPU sends bus request.
    2. DMA sends bus request.
    3. Arbiter receives requests.
    4. Arbiter applies priority policy.
    5. One requester receives bus grant.
    6. That device uses the bus.
    7. Bus is released.
    8. Another requester may be granted access.


------------------------------------------------------------
23.21 DISTRIBUTED BUS ARBITRATION
------------------------------------------------------------

In distributed arbitration, there is no single central
arbiter making every decision.

Multiple devices participate in determining who gets the bus.

Conceptually:

    Device A ─┐
    Device B ─┤
    Device C ─┤→ Arbitration logic
    Device D ─┘


The arbitration responsibility is distributed among
participants.


------------------------------------------------------------
23.22 CENTRALIZED VS DISTRIBUTED ARBITRATION
------------------------------------------------------------

+----------------------+------------------------+
| Centralized         | Distributed            |
+----------------------+------------------------+
| Central arbiter     | No single central     |
| controls decision   | arbiter                |
+----------------------+------------------------+
| Simpler concept     | More distributed logic|
+----------------------+------------------------+
| Arbiter can become  | No single central     |
| a central point     | decision point        |
+----------------------+------------------------+


------------------------------------------------------------
23.23 ARBITRATION METHODS
------------------------------------------------------------

Common priority approaches include:

    • Fixed priority
    • Round-robin
    • Dynamic priority


FIXED PRIORITY:

    One device always has higher priority.


Example:

    CPU > DMA > Device


Problem:

    Low-priority device may experience starvation.


------------------------------------------------------------
23.24 ROUND-ROBIN ARBITRATION
------------------------------------------------------------

Round-robin gives devices turns.

Example:

    Device A
       ↓
    Device B
       ↓
    Device C
       ↓
    Device D
       ↓
    Device A
       ↓
    ...


This can provide fairer access.


------------------------------------------------------------
23.25 STARVATION
------------------------------------------------------------

Starvation occurs when a low-priority requester waits for a
very long time because higher-priority requesters repeatedly
get access.

Example:

    High-priority device
        ↓
    High-priority device
        ↓
    High-priority device
        ↓
    High-priority device
        ↓
    Low-priority device
        ↓
        WAIT...


Round-robin can help reduce this problem.

USB is a widely used serial interface for connecting

Examples:

23.27 USB CHARACTERISTICS
------------------------------------------------------------

USB provides:

    • Serial communication
    • Device connectivity
    • Data transfer
    • Power delivery in supported versions/modes
    • Plug-and-play support


USB has evolved through many generations and connector types.

Important:

    USB version
    ≠
    USB connector shape

For example, connector types and protocol generations are
separate concepts.


------------------------------------------------------------
23.28 USB APPLICATIONS
------------------------------------------------------------

USB is commonly used for:

    Input devices
    External storage
    Cameras
    Audio devices
    Phones
    Printers
    Other peripherals


Advantages:

    + Widely supported
    + Convenient
    + Can carry data
    + Can provide power
    + Hot-plugging is supported by the standard


------------------------------------------------------------
23.29 PCI
============================================================

PCI = Peripheral Component Interconnect

PCI is a computer expansion bus/interface historically used
to connect peripheral devices to the system.

Examples:

    Network cards
    Sound cards
    Expansion cards


PCI allowed peripherals to communicate with the processor and
memory subsystem.


------------------------------------------------------------
23.30 PCI CHARACTERISTICS
------------------------------------------------------------

Traditional PCI is:

    • Parallel
    • Expansion-oriented
    • Shared-bus based

A simplified structure:

    CPU / Memory
          |
         PCI
          |
     +----+----+----+
     |    |    |    |
    NIC  Sound Other


PCI has largely been replaced by PCI Express in modern
high-performance systems.


------------------------------------------------------------
23.31 PCI EXPRESS (PCIe)
============================================================

PCIe = PCI Express

PCIe is a modern high-speed serial expansion interconnect.

It is widely used for:

    GPUs
    NVMe SSDs
    Network adapters
    High-speed expansion cards


Conceptually:

    CPU/Chipset
         |
        PCIe
     +---+---+
     |       |
    GPU     SSD


------------------------------------------------------------
23.32 PCIe LANES
------------------------------------------------------------

PCIe uses lanes.

Common configurations include:

    x1
    x2
    x4
    x8
    x16


A lane provides a communication path.

More lanes generally provide greater aggregate bandwidth.

Example:

    PCIe x1
        → 1 lane

    PCIe x4
        → 4 lanes

    PCIe x16
        → 16 lanes


------------------------------------------------------------
23.33 PCIe POINT-TO-POINT
============================================================

Unlike traditional shared PCI, PCIe uses point-to-point links.

Conceptually:

    CPU/Root Complex
        |
        +-------- GPU
        |
        +-------- SSD
        |
        +-------- Network


Each link has dedicated communication paths rather than all
devices sharing one traditional parallel bus.


------------------------------------------------------------
23.34 PCI VS PCIe
============================================================

+----------------------+-------------------------+
| PCI                  | PCIe                    |
+----------------------+-------------------------+
| Parallel             | Serial                  |
+----------------------+-------------------------+
| Shared bus model     | Point-to-point links    |
+----------------------+-------------------------+
| Older technology     | Modern technology       |
+----------------------+-------------------------+
| Lower scalability    | Highly scalable         |
+----------------------+-------------------------+
| Expansion cards      | GPUs, SSDs, NICs, etc. |
+----------------------+-------------------------+


------------------------------------------------------------
23.35 SATA
============================================================

SATA = Serial ATA

SATA is a serial interface commonly used to connect storage
devices.

Examples:

    HDD
    SATA SSD
    Optical drives


Conceptually:

    Motherboard
         |
        SATA
         |
    +----+----+
    |         |
   HDD      SATA SSD


------------------------------------------------------------
23.36 SATA CHARACTERISTICS
============================================================

SATA:

    • Uses serial communication
    • Designed primarily for storage devices
    • Replaced older parallel ATA/PATA interfaces
    • Common in HDDs and SATA SSDs


------------------------------------------------------------
23.37 SATA SSD
============================================================

A SATA SSD uses flash memory internally but communicates with
the host using the SATA interface.

Therefore:

    SSD
      ≠
    NVMe automatically


There are different SSD interfaces.

Examples:

    SATA SSD
    NVMe SSD


------------------------------------------------------------
23.38 NVMe
============================================================

NVMe = Non-Volatile Memory Express

NVMe is a protocol designed specifically for non-volatile
memory storage such as modern flash-based SSDs.

NVMe commonly operates over:

    PCI Express (PCIe)


Basic path:

    CPU
     |
    PCIe
     |
    NVMe SSD
     |
    NAND Flash


------------------------------------------------------------
23.39 WHY NVMe?
============================================================

Older storage protocols were designed around older storage
technologies and may have greater overhead.

NVMe was designed for modern flash storage.

Advantages include:

    • Low latency
    • High parallelism
    • High throughput
    • Efficient command processing
    • Designed for modern SSD characteristics


------------------------------------------------------------
23.40 SATA SSD VS NVMe SSD
============================================================

SATA SSD:

    CPU
     ↓
    SATA controller/interface
     ↓
    SSD


NVMe SSD:

    CPU/PCIe fabric
     ↓
    PCIe
     ↓
    NVMe SSD


Generally:

    NVMe SSDs can provide much higher performance than SATA
    SSDs when the workload and hardware support it.


------------------------------------------------------------
23.41 SATA VS NVMe
============================================================

+----------------------+-------------------------+
| SATA SSD             | NVMe SSD                |
+----------------------+-------------------------+
| SATA interface       | Usually PCIe interface  |
+----------------------+-------------------------+
| Older storage        | Modern flash-oriented   |
| protocol approach    | protocol                |
+----------------------+-------------------------+
| Lower bandwidth      | Higher bandwidth        |
| ceiling              | potential               |
+----------------------+-------------------------+
| Higher protocol      | Lower overhead for      |
| overhead for modern  | modern flash storage   |
| flash workloads      |                         |
+----------------------+-------------------------+


============================================================
23.42 USB VS SATA VS PCIe VS NVMe
============================================================

USB:

    General-purpose external/peripheral connectivity.


SATA:

    Storage interface.


PCIe:

    High-speed expansion interconnect.


NVMe:

    Storage protocol designed for non-volatile memory,
    commonly carried over PCIe.


IMPORTANT:

    PCIe = INTERCONNECT

    NVMe = PROTOCOL

They are related but are NOT the same thing.


============================================================
23.43 IMPORTANT DISTINCTION
============================================================

Do NOT memorize:

    "NVMe is a type of cable."

More accurately:

    NVMe is a storage protocol.

It commonly uses PCIe as the transport/interconnect.


Similarly:

    SATA = interface/standard for storage communication.

    USB = general-purpose peripheral interface.

    PCIe = high-speed expansion interconnect.

23.45 BUS ARBITRATION EXAMPLE
============================================================

Suppose:

    CPU wants bus
    DMA wants bus
    GPU wants bus


A centralized arbiter receives:

    CPU  → Request
    DMA  → Request
    GPU  → Request


Suppose priority is:

    DMA > CPU > GPU


Then:

    DMA gets bus first.

After DMA finishes:

    CPU may get bus.

Then:

    GPU may get bus.


============================================================
23.46 ROUND-ROBIN EXAMPLE
============================================================

Suppose:

    CPU
    DMA
    GPU
    NIC


Round-robin:

    CPU → DMA → GPU → NIC → CPU → DMA → ...


This promotes fairness.


============================================================
23.47 BUS BANDWIDTH
============================================================

Bus bandwidth is the amount of data that can be transferred
per unit time.

Simplified formula:

    Bandwidth
    =
    Transfer size × Transfers per second


Example:

    64 bits per transfer
    100 million transfers/sec


Convert:

    64 bits = 8 bytes

Therefore:

    Bandwidth
    = 8 bytes × 100,000,000
    = 800,000,000 bytes/sec

    ≈ 800 MB/s

This is a simplified calculation.


============================================================
23.48 BUS LATENCY
============================================================

Latency is the time between requesting an operation and
getting the required response/result.

Example:

    Request
      |
      | ← latency →
      |
      ↓
    Response


High bandwidth does NOT automatically mean low latency.

These are different performance measures.


============================================================
23.49 THROUGHPUT VS LATENCY
============================================================

THROUGHPUT:

    Amount of work/data transferred per unit time.


LATENCY:

    Time required for an individual operation.


Example:

    Highway:

    Throughput
        = number of cars transported per hour

    Latency
        = time taken by one car to reach destination

    11010110


Serial:

    Time →

Parallel:

    At one instant:

    1
    1

Multiple lines carry bits simultaneously.


============================================================
23.51 COMMON MISTAKES
============================================================

MISTAKE 1:

    Serial means slow.

CORRECT:

    Modern serial interfaces such as PCIe and USB can be
    extremely fast.


MISTAKE 2:

    PCI and PCIe are identical.

CORRECT:

    PCI is an older parallel shared-bus technology.
    PCIe is a modern serial point-to-point interconnect.


MISTAKE 3:

    NVMe and PCIe are the same.

CORRECT:

    PCIe is an interconnect.
    NVMe is a storage protocol commonly transported over PCIe.


MISTAKE 4:

    SATA SSD and NVMe SSD use the same interface.

CORRECT:

    SATA SSD → SATA interface.
    NVMe SSD → commonly PCIe/NVMe.


MISTAKE 5:

    More bus width always means more performance.

CORRECT:

    Performance also depends on clock/transfer rate,
    protocol, latency, overhead and other factors.


MISTAKE 6:

    Bus arbitration is only needed for CPU.

CORRECT:

    Multiple bus masters can request access, such as CPU,
    DMA and other devices.


MISTAKE 7:

    Parallel communication always beats serial communication.

CORRECT:

    Modern high-speed serial links can outperform older
    parallel buses.
