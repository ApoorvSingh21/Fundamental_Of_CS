CHAPTER 20 — VIRTUAL MEMORY

============================================================
CHAPTER 20 — VIRTUAL MEMORY
============================================================

LEVEL: B.Tech 1st Year
STARTING LEVEL: Absolute Beginner
GOAL: Understand Virtual Memory, Paging, Page Tables, TLB,
      Page Faults, Page Replacement and Memory Protection.
============================================================


------------------------------------------------------------
20.1 WHAT IS VIRTUAL MEMORY?
------------------------------------------------------------

Imagine your computer has:

    RAM = 8 GB

But a program needs:

    12 GB

Can the program run?

YES, using Virtual Memory.

Virtual memory allows a program to use an address space that
can be larger than the physically available RAM.

The operating system uses secondary storage as backing storage
when necessary.

Basic idea:

        PROGRAM
           |
           ↓
    Virtual Addresses
           |
           ↓
    +---------------+
    | Memory Mgmt   |
    | Hardware/OS   |
    +---------------+
       /         \
      ↓           ↓
   RAM          Storage
 Physical       Backing
 Memory         Store


REAL-WORLD ANALOGY
------------------

Imagine a study table.

Your table has space for only 5 books.

But you have 20 books.

You keep:

    5 books → On the table
    15 books → Bookshelf

When you need another book:

    1. Put away a book you don't need.
    2. Bring the required book from the shelf.

Similarly:

    RAM → Fast working area
    Disk/SSD → Larger but slower backing storage


FORMAL DEFINITION
-----------------

Virtual memory is a memory-management technique that provides
a process with a large logical/virtual address space while
using physical RAM and secondary storage together.


------------------------------------------------------------
20.2 WHY DO WE NEED VIRTUAL MEMORY?
------------------------------------------------------------

There are several reasons.

1. Programs can be larger than physical RAM.

2. Each process can get its own virtual address space.

3. Memory can be used efficiently.

4. Processes can be isolated from one another.

5. Only required portions of a program need to be in RAM.

6. Multiple programs can run even when their total virtual
   memory requirements exceed physical RAM.


Example:

    RAM = 4 GB

    Program A = 2 GB
    Program B = 3 GB
    Program C = 2 GB

Total:

    2 + 3 + 2 = 7 GB

They may still execute through virtual memory because not all
parts of all programs must be in RAM simultaneously.


------------------------------------------------------------
20.3 VIRTUAL ADDRESS VS PHYSICAL ADDRESS
------------------------------------------------------------

This is one of the MOST IMPORTANT concepts.

When a program runs, it generally works with:

    Virtual Address

RAM hardware uses:

    Physical Address


The conversion is:

    Virtual Address
          |
          ↓
    Address Translation
          |
          ↓
    Physical Address


Example:

Program generates:

    Virtual Address = 0x1234

Memory-management hardware translates it to:

    Physical Address = 0x5678


The program normally does not directly need to know the
physical RAM location.


------------------------------------------------------------
20.4 VIRTUAL ADDRESS SPACE
------------------------------------------------------------

The virtual address space is the range of addresses that a
process can use.

Suppose a CPU uses 16-bit virtual addresses.

Number of possible addresses:

    2^16
    = 65,536 addresses

If byte-addressable:

    Virtual address space = 65,536 bytes
                          = 64 KB


Important:

    Virtual address space
    ≠
    Physical RAM size


Example:

    Virtual address space = 64 GB
    Physical RAM = 8 GB

The virtual address space can be larger than RAM.


------------------------------------------------------------
20.5 PHYSICAL ADDRESS SPACE
------------------------------------------------------------

Physical address space refers to the actual locations in
physical memory.

For example:

    Physical RAM = 8 GB

The physical memory contains actual storage locations.

The Memory Management Unit (MMU) helps translate virtual
addresses into physical addresses.


------------------------------------------------------------
20.6 MEMORY MANAGEMENT UNIT (MMU)
------------------------------------------------------------

MMU = Memory Management Unit

The MMU is hardware responsible for memory-address translation
and related memory protection functions.

Basic flow:

    CPU
     |
     | Virtual Address
     ↓
    MMU
     |
     | Physical Address
     ↓
    RAM


Conceptually:

             CPU
              |
              | VA
              ↓
        +-----------+
        |    MMU    |
        +-----------+
              |
              | PA
              ↓
            RAM


VA = Virtual Address

PA = Physical Address


------------------------------------------------------------
20.7 PAGING
------------------------------------------------------------

Paging is one of the most important techniques used to
implement virtual memory.

The virtual address space is divided into fixed-size blocks
called:

    PAGES

Physical memory is divided into fixed-size blocks called:

    FRAMES


Therefore:

    Virtual Memory
         ↓
       Pages

    Physical Memory
         ↓
       Frames


Important:

    Page size = Frame size


------------------------------------------------------------
20.8 PAGE
------------------------------------------------------------

A page is a fixed-size block of virtual memory.

Example:

    Page size = 4 KB

Then:

    Virtual memory is divided into
    4 KB pages.


Conceptually:

Virtual Memory:

+--------+--------+--------+--------+
| Page 0 | Page 1 | Page 2 | Page 3 |
+--------+--------+--------+--------+


------------------------------------------------------------
20.9 FRAME
------------------------------------------------------------

A frame is a fixed-size block of physical memory.

If:

    Page size = 4 KB

then:

    Frame size = 4 KB


Physical Memory:

+---------+---------+---------+---------+
| Frame 0 | Frame 1 | Frame 2 | Frame 3 |
+---------+---------+---------+---------+


Pages are loaded into frames.


------------------------------------------------------------
20.10 PAGE-FRAME RELATIONSHIP
------------------------------------------------------------

Suppose:

    Virtual pages:
        P0
        P1
        P2
        P3

Physical frames:
        F0
        F1
        F2
        F3


Possible mapping:

    P0 → F2
    P1 → F0
    P2 → F3
    P3 → F1


Notice:

    Page number does NOT have to equal frame number.


This mapping is stored in the:

    PAGE TABLE


------------------------------------------------------------
20.11 PAGE TABLE
------------------------------------------------------------

A page table stores the mapping between virtual pages and
physical frames.

Example:

    Page Table

    +-------+--------+
    | Page  | Frame  |
    +-------+--------+
    |   0   |   2    |
    |   1   |   0    |
    |   2   |   3    |
    |   3   |   1    |
    +-------+--------+


Meaning:

    Page 0 → Frame 2
    Page 1 → Frame 0
    Page 2 → Frame 3
    Page 3 → Frame 1


------------------------------------------------------------
20.12 VIRTUAL ADDRESS STRUCTURE
------------------------------------------------------------

A virtual address is divided into two major parts:

    Virtual Address
    +-------------------+
    | Page No. | Offset |
    +-------------------+


PAGE NUMBER
-----------

Identifies which virtual page contains the required address.


OFFSET
------

Identifies the exact byte/word within that page.


The page number is translated.

The offset remains unchanged.


Very important:

    Virtual Page Number
          ↓
    Page Table
          ↓
    Physical Frame Number

    Offset
       ↓
    unchanged


------------------------------------------------------------
20.13 ADDRESS TRANSLATION
------------------------------------------------------------

Suppose:

    Virtual address:

    +-------------+---------+
    | Page Number | Offset  |
    +-------------+---------+

Step 1:

    Extract page number.

Step 2:

    Look up page number in page table.

Step 3:

    Obtain frame number.

Step 4:

    Combine:

    Frame Number + Offset

to form the physical address.


Diagram:

    Virtual Address
    +---------+--------+
    | Page No | Offset |
    +---------+--------+
         |
         ↓
     Page Table
         |
         ↓
     Frame No.
         |
         +---------+
                   |
                   ↓
    Physical Address
    +---------+--------+
    |Frame No | Offset |
    +---------+--------+


------------------------------------------------------------
20.14 EXAMPLE OF ADDRESS TRANSLATION
------------------------------------------------------------

Suppose:

    Page size = 1 KB

Virtual address:

    2500

Find:

    Page number
    Offset


Since:

    1 KB = 1024 bytes

Use:

    Page Number = floor(2500 / 1024)

    = 2


Offset:

    2500 - (2 × 1024)

    = 2500 - 2048

    = 452


Therefore:

    Page number = 2
    Offset      = 452


If page table says:

    Page 2 → Frame 7

Then physical address:

    Frame base + offset

Frame size = 1024 bytes

    Physical address
    = 7 × 1024 + 452

    = 7168 + 452

    = 7620


ANSWER:

    Physical Address = 7620


------------------------------------------------------------
20.15 POWER-OF-2 PAGE SIZE METHOD
------------------------------------------------------------

Suppose:

    Virtual address = 16 bits

    Page size = 1 KB = 2^10 bytes

Then:

    Offset bits = 10


Virtual address:

    16 bits

Therefore:

    Page number bits
    = 16 - 10
    = 6


So:

    +----------+----------+
    | Page No. | Offset   |
    |  6 bits  | 10 bits  |
    +----------+----------+


Number of pages:

    2^6 = 64 pages


------------------------------------------------------------
20.16 IMPORTANT FORMULAS FOR PAGING
------------------------------------------------------------

If:

    Virtual address size = n bits

    Page size = 2^p bytes


Then:

    Offset bits = p

    Page number bits = n - p


Number of virtual pages:

    2^(n-p)


If physical address = m bits:

    Frame number bits = m - p


Number of physical frames:

    2^(m-p)


------------------------------------------------------------
20.17 PAGE TABLE ENTRY
------------------------------------------------------------

A page table entry (PTE) may contain more than just the frame
number.

Typical information may include:

    • Frame number
    • Valid/present bit
    • Protection bits
    • Dirty/modified bit
    • Reference/accessed bit
    • Other control information


Conceptually:

    +--------------------------------+
    | Frame | Valid | R/W | Dirty  |
    +--------------------------------+


------------------------------------------------------------
20.18 VALID / PRESENT BIT
------------------------------------------------------------

The valid or present bit indicates whether the required page
is currently present in physical memory.

Example:

    Page 0 → Frame 3 → Valid = 1
    Page 1 → Frame 7 → Valid = 1
    Page 2 → Not in RAM → Valid = 0


If CPU requests Page 2:

    Valid = 0
        ↓
    PAGE FAULT


------------------------------------------------------------
20.19 PAGE FAULT
------------------------------------------------------------

A page fault occurs when a process references a page that is
not currently present in physical memory.

Example:

    CPU requests Page 5

    Page table:

    Page 5 → Not in RAM

Therefore:

    PAGE FAULT


Important:

    Page fault is NOT necessarily a program error.

It is a normal virtual-memory mechanism.


------------------------------------------------------------
20.20 PAGE FAULT HANDLING
------------------------------------------------------------

Suppose CPU references a page that is not in RAM.

Sequence:

    1. CPU generates virtual address.
    2. MMU checks page table.
    3. Page is not present.
    4. Page fault occurs.
    5. Control transfers to OS.
    6. OS finds the required page on storage.
    7. OS finds a free frame OR chooses a victim frame.
    8. Required page is loaded into RAM.
    9. Page table is updated.
   10. Faulting instruction is restarted.


Diagram:

        CPU
         |
         ↓
    Virtual Address
         |
         ↓
    Page Table
         |
      Page absent
         |
         ↓
    PAGE FAULT
         |
         ↓
        OS
         |
         ↓
    Secondary Storage
         |
         ↓
        RAM
         |
         ↓
    Update Page Table
         |
         ↓
    Restart instruction


------------------------------------------------------------
20.21 WHY PAGE FAULTS ARE EXPENSIVE
------------------------------------------------------------

RAM access is much faster than secondary-storage access.

Therefore:

    Page fault
        ↓
    Storage access
        ↓
    Very high delay


Hence:

    Too many page faults
        ↓
    Poor performance


------------------------------------------------------------
20.22 PAGE REPLACEMENT
------------------------------------------------------------

What happens if a page fault occurs but RAM is already full?

The OS must choose a page to remove.

This is called:

    PAGE REPLACEMENT


The selected page is called:

    VICTIM PAGE


Then:

    Victim page
        ↓
    Remove from frame
        ↓
    Load required page


Common page-replacement algorithms:

    • FIFO
    • LRU
    • Optimal


------------------------------------------------------------
20.23 FIFO PAGE REPLACEMENT
------------------------------------------------------------

FIFO = First-In, First-Out

The page that entered memory first is removed first.

Analogy:

    Queue at a ticket counter.

The person who entered first leaves first.


Example:

Pages in memory:

    [1] [2] [3]

If page 4 is needed:

    Remove page 1.

Result:

    [4] [2] [3]


------------------------------------------------------------
20.24 FIFO EXAMPLE
------------------------------------------------------------

Suppose there are 3 frames.

Reference string:

    1 2 3 4

Initial:

    1 → [1]
    2 → [1 2]
    3 → [1 2 3]

Need 4:

    Remove oldest page = 1

    Result:

    [4 2 3]


FIFO does not care how frequently a page is used.


------------------------------------------------------------
20.25 LRU PAGE REPLACEMENT
------------------------------------------------------------

LRU = Least Recently Used

Replace the page that has not been used for the longest time.

Analogy:

Your desk has limited space.

You remove the book that you have not used for the longest
time.


Example:

Frames:

    [1] [2] [3]

Suppose recent usage order:

    2 → most recent
    3
    1 → least recent

If page 4 is needed:

    Remove page 1.

Result:

    [4] [2] [3]


------------------------------------------------------------
20.26 OPTIMAL PAGE REPLACEMENT
------------------------------------------------------------

Optimal replacement removes the page whose next use is farthest
in the future.

Example:

Current pages:

    [1] [2] [3]

Suppose future references are:

    1, 2, 5, 2, 1, 3...

If page 5 is needed and:

    Page 1 → used soon
    Page 2 → used soon
    Page 3 → used much later

Then:

    Replace Page 3.


IMPORTANT:

Optimal replacement requires knowledge of future references.

Therefore, it is mainly used as a theoretical benchmark.

It provides the minimum possible number of page faults for a
given reference string and number of frames.


------------------------------------------------------------
20.27 FIFO VS LRU VS OPTIMAL
------------------------------------------------------------

+------------+-------------------------------+
| Algorithm  | Replacement Rule              |
+------------+-------------------------------+
| FIFO       | Oldest page                   |
| LRU        | Least recently used page      |
| Optimal    | Used farthest in the future   |
+------------+-------------------------------+


Performance idea:

    Optimal → theoretical best
    LRU     → often good practical approximation
    FIFO    → simple but may perform poorly


------------------------------------------------------------
20.28 TLB
------------------------------------------------------------

TLB = Translation Lookaside Buffer

The TLB is a small, fast cache that stores recently used
virtual-page-to-physical-frame translations.

Why is it needed?

Without TLB:

    CPU
     ↓
    Page Table
     ↓
    RAM

The page table itself is stored in memory, so address
translation can require an additional memory access.

TLB helps avoid repeated page-table lookups for frequently
used pages.


------------------------------------------------------------
20.29 TLB BASIC STRUCTURE
------------------------------------------------------------

        TLB
    +-------------------+
    | Virtual Page      |
    | Frame Number      |
    +-------------------+
    | VP → Frame        |
    | VP → Frame        |
    | VP → Frame        |
    +-------------------+


CPU provides:

    Virtual Page Number

TLB searches for it.


------------------------------------------------------------
20.30 TLB HIT
------------------------------------------------------------

A TLB hit occurs when the required page translation is found
in the TLB.

Flow:

    CPU
     |
     ↓
    TLB
     |
    HIT
     |
     ↓
    Frame Number
     |
     ↓
    Physical Address
     |
     ↓
    RAM


Result:

    Faster address translation.


------------------------------------------------------------
20.31 TLB MISS
------------------------------------------------------------

A TLB miss occurs when the required translation is NOT in the
TLB.

Flow:

    CPU
     |
     ↓
    TLB
     |
    MISS
     |
     ↓
    Page Table
     |
     ↓
    Frame Number
     |
     ↓
    Update TLB
     |
     ↓
    RAM


Important:

    TLB miss does NOT automatically mean page fault.


This distinction is extremely important.


------------------------------------------------------------
20.32 TLB MISS VS PAGE FAULT
------------------------------------------------------------

TLB MISS:

    Translation not found in TLB.

PAGE FAULT:

    Required page not currently in physical memory.


Possible situation:

    TLB miss
       ↓
    Page table lookup
       ↓
    Page is present in RAM
       ↓
    No page fault


Another situation:

    TLB miss
       ↓
    Page table lookup
       ↓
    Page absent
       ↓
    Page fault


------------------------------------------------------------
20.33 COMPLETE ADDRESS TRANSLATION WITH TLB
------------------------------------------------------------

                CPU
                 |
                 | Virtual Address
                 ↓
             +-------+
             |  TLB  |
             +-------+
              /     \
           HIT       MISS
            |          |
            ↓          ↓
        Frame No.   Page Table
            |          |
            |       +--+--+
            |       |     |
            |      Present Absent
            |       |     |
            |       ↓     ↓
            |    Frame   Page Fault
            |       |
            +-------+
                 |
                 ↓
        Physical Address
                 |
                 ↓
                RAM


------------------------------------------------------------
20.34 TLB AND PERFORMANCE
------------------------------------------------------------

Suppose:

    TLB lookup = 10 ns
    Memory access = 100 ns

If TLB hit:

    TLB lookup + memory access

    = 10 + 100
    = 110 ns


If TLB miss, simplified model:

    TLB lookup
    + page table memory access
    + actual memory access

    = 10 + 100 + 100
    = 210 ns


Actual systems can be more complex, but the concept is
important for exam problems.


------------------------------------------------------------
20.35 TLB EFFECTIVE ACCESS TIME
------------------------------------------------------------

Suppose:

    TLB lookup time = t
    Memory access time = m
    TLB hit ratio = h


Simplified EAT:

    EAT = h(t + m)
          +
          (1-h)(t + 2m)


Why?

TLB hit:

    TLB lookup + memory access


TLB miss:

    TLB lookup
    + page table access
    + actual memory access


This formula is frequently used in numerical problems.


------------------------------------------------------------
20.36 EXAMPLE: TLB EAT
------------------------------------------------------------

Given:

    TLB lookup = 10 ns
    Memory access = 100 ns
    TLB hit ratio = 90%

Therefore:

    h = 0.9

    EAT =
    0.9(10 + 100)
    +
    0.1(10 + 100 + 100)

    = 0.9(110)
      + 0.1(210)

    = 99 + 21

    = 120 ns


ANSWER:

    Effective access time = 120 ns


------------------------------------------------------------
20.37 MULTI-LEVEL PAGE TABLE
------------------------------------------------------------

A large virtual address space can require a very large page
table.

A solution is:

    MULTI-LEVEL PAGE TABLE


Instead of one huge page table:

    Virtual Address
          |
          ↓
    Outer Page Table
          |
          ↓
    Inner Page Table
          |
          ↓
       Frame


Example conceptual address:

    +----------+----------+---------+
    | Level 1  | Level 2  | Offset  |
    +----------+----------+---------+


This can reduce memory overhead for sparse address spaces.


------------------------------------------------------------
20.38 PAGE SIZE
------------------------------------------------------------

Page size is an important design parameter.

Common conceptual sizes include:

    4 KB
    8 KB
    16 KB
    2 MB
    etc.

Larger pages:

    + Fewer page-table entries
    + Better sequential transfer efficiency
    - More internal fragmentation
    - Potentially more unnecessary data transferred


Smaller pages:

    + Less internal fragmentation
    + More fine-grained allocation
    - Larger page tables
    - More translation overhead


------------------------------------------------------------
20.39 INTERNAL FRAGMENTATION
------------------------------------------------------------

With fixed-size pages, a process may not use every byte of its
last allocated page.

Example:

    Page size = 4 KB

Program needs:

    6 KB


Pages required:

    Page 1 = 4 KB
    Page 2 = 2 KB used + 2 KB unused


Unused:

    2 KB


This is internal fragmentation.


------------------------------------------------------------
20.40 MEMORY PROTECTION
------------------------------------------------------------

Virtual memory also helps provide protection between processes.

Example:

    Process A
       ↓
    Virtual Address Space A


    Process B
       ↓
    Virtual Address Space B


Process A should normally not be able to access arbitrary
memory belonging to Process B.


Protection information can include:

    • Read
    • Write
    • Execute


Example:

    Code page:
        Read + Execute

    Data page:
        Read + Write

    Protected page:
        No access


------------------------------------------------------------
20.41 USER MODE AND KERNEL MODE
------------------------------------------------------------

Modern operating systems typically separate privileges.

USER MODE:

    Applications run with restricted privileges.


KERNEL MODE:

    Operating-system code runs with higher privileges.


Virtual memory and hardware protection help enforce these
boundaries.


Conceptually:

    Application
         |
      User Mode
         |
    ---- protection ----
         |
     Kernel Mode
         |
         ↓
       Hardware


------------------------------------------------------------

------------------------------------------------------------

Virtual memory is a collaboration between:

    CPU

    Operating system


Overall:

               CPU

------------------------------------------------------------
20.43 COMPLETE EXAMPLE
------------------------------------------------------------

Given:

    Virtual address = 13 bits
    Physical address = 12 bits
    Page size = 1 KB

Find:

    1. Number of offset bits
    2. Virtual page number bits
    3. Number of virtual pages
    4. Physical frame number bits
    5. Number of physical frames


Step 1:

    Page size = 1 KB
              = 1024 bytes
              = 2^10 bytes

Therefore:

    Offset bits = 10


Step 2:

    Virtual address = 13 bits

    Page number bits:

    = 13 - 10
    = 3 bits


Step 3:

    Virtual pages:

    = 2^3
    = 8 pages


Step 4:

    Physical address = 12 bits

    Frame number bits:

    = 12 - 10
    = 2 bits


Step 5:

    Physical frames:

    = 2^2
    = 4 frames


FINAL:

    Offset bits          = 10
    Virtual page bits    = 3
    Virtual pages        = 8
    Frame bits           = 2
    Physical frames      = 4

20.44 ANOTHER NUMERICAL
------------------------------------------------------------

Given:

    Virtual address = 16 bits
    Page size = 4 KB

Find the number of pages.

Step 1:

    4 KB = 4096 bytes
         = 2^12 bytes

Therefore:

    Offset = 12 bits


Step 2:

    Virtual page bits:

    = 16 - 12
    = 4


Step 3:

    Number of virtual pages:

    = 2^4
    = 16


ANSWER:

    16 virtual pages


------------------------------------------------------------
20.45 ANOTHER NUMERICAL
------------------------------------------------------------

A system has:

    32-bit virtual addresses
    Page size = 4 KB

Find number of virtual pages.

    4 KB = 2^12

Offset bits:

    12


Virtual page number bits:

    32 - 12
    = 20


Number of virtual pages:

    2^20


ANSWER:

    1,048,576 virtual pages


------------------------------------------------------------
20.46 PAGE TABLE SIZE
------------------------------------------------------------

Suppose:

    Number of virtual pages = 2^20

Each page table entry = 4 bytes

Then page table size:

    = 2^20 × 4 bytes

    = 2^22 bytes

    = 4 MB


ANSWER:

    Page table size = 4 MB


------------------------------------------------------------
20.47 PAGE FAULT VS TLB MISS
------------------------------------------------------------

VERY IMPORTANT EXAM TABLE:

+----------------+-------------------------------------------+
| TLB Miss       | Translation not found in TLB             |
+----------------+-------------------------------------------+
| Page Fault     | Page not present in physical memory       |
+----------------+-------------------------------------------+

TLB miss:

    May require page-table lookup.

Page fault:

    Requires OS intervention and usually storage access.


------------------------------------------------------------
20.48 ADVANTAGES OF VIRTUAL MEMORY
------------------------------------------------------------

1. Allows programs larger than RAM to execute.

2. Provides process isolation.

3. Improves memory-management flexibility.

4. Allows efficient use of physical memory.

5. Supports multitasking.

6. Provides memory protection.

7. Allows processes to have large virtual address spaces.


------------------------------------------------------------
20.49 DISADVANTAGES OF VIRTUAL MEMORY
------------------------------------------------------------

1. Address translation adds overhead.

2. Page tables consume memory.

3. TLB misses reduce performance.

4. Page faults are extremely expensive.

5. Excessive paging can cause thrashing.


------------------------------------------------------------
20.50 THRASHING
------------------------------------------------------------

Thrashing occurs when the system spends excessive time moving
pages between RAM and storage instead of executing useful work.

Example:

    Too many active processes
            ↓
    Not enough RAM
            ↓
    Frequent page faults
            ↓
    Constant page swapping
            ↓
    CPU spends less time doing useful work
            ↓
        THRASHING


Performance becomes extremely poor.


------------------------------------------------------------
20.51 IMPORTANT COMPARISON
------------------------------------------------------------

+------------------+-----------------------------------+
| Concept          | Meaning                           |
+------------------+-----------------------------------+
| Page             | Block of virtual memory           |
| Frame            | Block of physical memory         |
| Page Table       | Maps pages to frames              |
| TLB              | Caches recent translations        |
| Page Fault       | Required page absent from RAM     |
| Victim Page      | Page selected for replacement     |
| FIFO             | Replace oldest page               |
| LRU              | Replace least recently used       |
| Optimal          | Replace farthest future use       |
| MMU              | Performs address translation      |
+------------------+-----------------------------------+


------------------------------------------------------------
20.52 COMMON MISTAKES
------------------------------------------------------------

MISTAKE 1:
    Page = Frame

CORRECT:

    Page → Virtual memory
    Frame → Physical memory


MISTAKE 2:
    TLB stores complete pages.

CORRECT:

    TLB primarily stores address translations.


MISTAKE 3:
    TLB miss = page fault.

CORRECT:

    TLB miss only means translation is absent from TLB.


MISTAKE 4:
    Page fault means program crashed.

CORRECT:

    A page fault is normally handled by the operating system.


MISTAKE 5:
    Offset changes during translation.

CORRECT:

    Offset remains unchanged.


MISTAKE 6:
    Page size and frame size can be different.

CORRECT:

    Page size = Frame size.


MISTAKE 7:
    Optimal replacement is normally directly implementable.

CORRECT:

    Optimal requires future knowledge, so it is mainly a
    theoretical benchmark.

20.54 COMPETITIVE EXAM HIGH-VALUE POINTS
------------------------------------------------------------

MEMORIZE:

    Page size = Frame size


    n-bit virtual address
    + page size = 2^p
    ↓
    Offset = p bits


    Page number bits:
    n - p


    Number of pages:
    2^(n-p)


    m-bit physical address
    + page size = 2^p
    ↓
    Frame number bits:
    m - p


    Number of frames:
    2^(m-p)


    TLB = Translation cache


    TLB MISS ≠ PAGE FAULT


    Page fault:
    Page absent from physical memory.


    FIFO:
    Oldest page removed.


    LRU:
    Least recently used removed.


    OPTIMAL:
    Page used farthest in future removed.


    Offset:
    DOES NOT CHANGE during translation.


------------------------------------------------------------
20.55 QUICK REVISION
------------------------------------------------------------

VIRTUAL MEMORY
    ↓
Provides large virtual address space using RAM + backing storage.

VIRTUAL ADDRESS
    ↓
Address generated/used by a process.

PHYSICAL ADDRESS
    ↓
Actual address in physical memory.

MMU
    ↓
Translates virtual addresses to physical addresses.

PAGING
    ↓
Virtual memory → Pages
Physical memory → Frames

PAGE TABLE
    ↓
Maps page numbers to frame numbers.

PAGE OFFSET
    ↓
Exact location inside a page.

TLB
    ↓
Caches recent page-to-frame translations.

TLB HIT
    ↓
Translation found quickly.

TLB MISS
    ↓
Translation not found in TLB.

PAGE FAULT
    ↓
Required page is not in RAM.

FIFO
    ↓
Remove oldest.

LRU
    ↓
Remove least recently used.

OPTIMAL
    ↓
Remove page needed farthest in future.

MEMORY PROTECTION
    ↓
Prevents unauthorized memory access.

THRASHING
    ↓
Excessive page movement causes severe performance loss.
