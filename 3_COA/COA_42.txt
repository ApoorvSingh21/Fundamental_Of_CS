42.1 FROM SOURCE CODE TO MACHINE CODE
============================================================

First understand the basic idea.

A programmer normally writes:

    Human-readable program
             ↓
          Source Code
             ↓
       Translation tools
             ↓
       Machine Code
             ↓
           CPU
             ↓
        Execution


The CPU does not directly execute normal C/C++/Java/Python
source code as written by the programmer.

It ultimately executes instructions represented in a form
defined by the processor's ISA.


------------------------------------------------------------
42.1.1 SOURCE CODE
------------------------------------------------------------

Example:

    int C;

    C = A + B;


This is source code.

It is designed for humans/programmers.


------------------------------------------------------------
42.1.2 COMPILER
------------------------------------------------------------

A compiler translates a high-level programming language
into lower-level representation/code.

Conceptually:

    Source Code
         ↓
      Compiler
         ↓
    Assembly / Object Code
         ↓
    Machine Code


A compiler may perform:

    Lexical analysis
    Syntax analysis
    Semantic analysis
    Intermediate representation
    Optimization
    Code generation


From a COA perspective, the important point is:

    Compiler
       ↓
    generates instructions
       ↓
    processor ISA
       ↓
    CPU executes them


------------------------------------------------------------
42.1.3 ASSEMBLY LANGUAGE
------------------------------------------------------------

Assembly is a human-readable representation of
machine instructions.

Example:

    ADD R1, R2, R3


Conceptually:

    ADD R1,R2,R3
          ↓
    Machine encoding
          ↓
    Binary instruction


Assembly is much closer to the processor than
high-level source code.


------------------------------------------------------------
42.1.4 MACHINE CODE
------------------------------------------------------------

Machine code consists of encoded instructions that
the processor can interpret according to its ISA.

Conceptually:

    101100...
    010011...
    110010...


The exact encoding depends on the processor architecture.


------------------------------------------------------------
42.1.5 ISA AS THE BRIDGE
------------------------------------------------------------

The Instruction Set Architecture is the interface
between software and processor implementation.

    Software
       |
       ↓
      ISA
       |
       ↓
    Hardware


The ISA specifies things such as:

    Instructions
    Registers
    Instruction formats
    Data types
    Addressing modes
    Programmer-visible behavior


Examples:

    x86-64
    ARM
    RISC-V


------------------------------------------------------------
42.1.6 LINKING AND LOADING
------------------------------------------------------------

For many compiled programs, the process involves
more than just compilation.

Simplified flow:

    Source Code
         ↓
      Compiler
         ↓
     Object File
         ↓
      Linker
         ↓
    Executable
         ↓
       Loader
         ↓
       Memory
         ↓
        CPU


LINKER:

Combines object files and libraries and resolves
references as appropriate.

LOADER:

Loads the executable/program into memory and prepares
it for execution.


Important:

    Compiler ≠ Linker ≠ Loader

============================================================
42.2 INSTRUCTION EXECUTION
============================================================

Now we follow ONE instruction inside the CPU.

Suppose CPU must execute:

    ADD R1, R2, R3


Meaning:

    R1 ← R2 + R3


The CPU performs several steps.


------------------------------------------------------------
42.2.1 PROGRAM COUNTER
------------------------------------------------------------

PC = Program Counter.

It holds the address of the next instruction to fetch.


Example:

    PC = 1000


Memory:

    Address 1000 → ADD R1,R2,R3
    Address 1004 → SUB R4,R5,R6
    Address 1008 → ...


CPU uses PC to locate the next instruction.


------------------------------------------------------------
42.2.2 FETCH
------------------------------------------------------------

Conceptual process:

    PC
     ↓
    Address
     ↓
   Memory/Cache
     ↓
 Instruction
     ↓
    IR


IR = Instruction Register.

It holds the instruction currently being processed.


Simplified microoperations:

    MAR ← PC
    Memory Read
    IR ← Memory Data
    PC ← PC + instruction length


The exact internal implementation depends on the architecture.


------------------------------------------------------------
42.2.3 WHY CACHE MATTERS DURING FETCH
------------------------------------------------------------

The CPU first looks through the memory hierarchy.

Conceptually:

    CPU
     ↓
    L1
     ↓
    L2
     ↓
    L3
     ↓
    RAM
     ↓
    Storage


Usually the processor obtains data/instructions from
the nearest appropriate cache level when available.

If the required block is not present:

    Cache miss
         ↓
    Next memory level


This is why cache affects CPU performance.


------------------------------------------------------------
42.2.4 DECODE
------------------------------------------------------------

The instruction is interpreted.

For:

    ADD R1,R2,R3


CPU determines:

    Operation:
        ADD

    Source:
        R2
        R3

    Destination:
        R1


The Control Unit generates the required control signals.


------------------------------------------------------------
42.2.5 REGISTER READ
------------------------------------------------------------

The processor obtains:

    R2
    R3


Conceptually:

    R2 ──────┐
             ↓
           ALU
             ↑
    R3 ──────┘


------------------------------------------------------------
42.2.6 EXECUTE
------------------------------------------------------------

ALU performs:

    R2 + R3


Suppose:

    R2 = 10
    R3 = 20


Then:

    ALU = 10 + 20
        = 30


------------------------------------------------------------
42.2.7 WRITE BACK
------------------------------------------------------------

Result:

    30

is written to:

    R1


Therefore:

    R1 = 30


Complete:

    R1 ← R2 + R3


------------------------------------------------------------
42.2.8 LOAD INSTRUCTION
------------------------------------------------------------

Consider:

    LOAD R1, [1000]


Meaning:

    R1 ← Memory[1000]


Flow:

    Instruction
         ↓
       Decode
         ↓
    Effective Address
         ↓
      Cache/Memory
         ↓
       Data
         ↓
        R1


------------------------------------------------------------
42.2.9 STORE INSTRUCTION
------------------------------------------------------------

Consider:

    STORE R1, [1000]


Meaning:

    Memory[1000] ← R1


Flow:

    R1
     ↓
   Cache/Memory
     ↓
  Address 1000


------------------------------------------------------------
42.2.10 BRANCH INSTRUCTION
------------------------------------------------------------

Consider:

    BEQ R1,R2,LABEL


Meaning conceptually:

    if R1 == R2:
        PC ← LABEL


The CPU:

    Reads registers
         ↓
    Evaluates condition
         ↓
    Determines branch target
         ↓
    Changes PC if branch is taken


Branches create control hazards in pipelines.


============================================================
42.3 MEMORY INTERACTION
============================================================

CPU and memory continuously interact.

Basic system:

               CPU
                |
                ↓
          Cache Hierarchy
                |
                ↓
               RAM
                |
                ↓
             Storage


------------------------------------------------------------
42.3.1 CPU REQUESTS DATA
------------------------------------------------------------

Suppose:

    LOAD R1,[A]


CPU needs data at address A.

Flow:

    CPU
     ↓
    L1 Cache
     |
   Hit? ── YES → Data
     |
    NO
     ↓
    L2
     |
   Hit? ── YES → Data
     |
    NO
     ↓
    L3
     |
    NO
     ↓
    RAM
     ↓
    Data


The exact hierarchy differs across processors.


------------------------------------------------------------
42.3.2 CACHE HIT
------------------------------------------------------------

If requested block exists in cache:

    CACHE HIT


Example:

    CPU requests A.

    L1 contains A.

Therefore:

    L1 HIT

The CPU obtains the data relatively quickly.


------------------------------------------------------------
42.3.3 CACHE MISS
------------------------------------------------------------

If requested block is not in the cache:

    CACHE MISS


The system obtains the block from a lower level.

This adds latency.


Important formula:

    AMAT =
    Hit Time + Miss Rate × Miss Penalty


------------------------------------------------------------
42.3.4 CACHE ADDRESS
------------------------------------------------------------

For a typical cache:

    ┌────────┬────────┬────────┐
    │  TAG   │ INDEX  │ OFFSET │
    └────────┴────────┴────────┘


TAG:

    Identifies memory block.


INDEX:

    Selects cache line/set.


OFFSET:

    Selects data within the block.


------------------------------------------------------------
42.3.5 MAIN MEMORY
------------------------------------------------------------

Main memory is usually RAM.

It holds:

    Running program
    Program data
    Stack
    Heap
    Other active memory contents


Simplified process memory:

    High Address
    ┌──────────────────┐
    │      Stack       │
    ├──────────────────┤
    │                  │
    │      Heap        │
    │                  │
    ├──────────────────┤
    │ Data / Globals   │
    ├──────────────────┤
    │ Code / Text      │
    └──────────────────┘
    Low Address


The exact layout and direction can vary by system.


------------------------------------------------------------
42.3.6 VIRTUAL MEMORY
------------------------------------------------------------

Programs normally operate using virtual addresses.

Conceptually:

    CPU generates
    Virtual Address
          ↓
        MMU
          ↓
        TLB
          ↓
    Page Table
          ↓
    Physical Address
          ↓
      Main Memory


Virtual address:

    ┌─────────────┬────────────┐
    │ Page Number │   Offset   │
    └─────────────┴────────────┘


Physical address:

    ┌──────────────┬────────────┐
    │ Frame Number │   Offset   │
    └──────────────┴────────────┘


Important:

    Page offset normally remains unchanged.


------------------------------------------------------------
42.3.7 PAGE FAULT
------------------------------------------------------------

If the required virtual page is not currently
in physical memory:

    PAGE FAULT


Simplified flow:

    CPU
     ↓
    Virtual Address
     ↓
    TLB/Page Table
     ↓
  Page present?
    /       \
  YES       NO
   |         |
 Memory    Page Fault
             ↓
       OS handles it
             ↓
       Bring page into RAM
             ↓
        Update mapping
             ↓
        Restart/continue


A page fault is much more expensive than a normal
cache hit.


------------------------------------------------------------
42.3.8 STORAGE
------------------------------------------------------------

Storage such as SSD/HDD provides persistent data.

Typical relationship:

    CPU
     ↓
   Cache
     ↓
    RAM
     ↓
   SSD/HDD


Storage is slower than RAM but retains data
when power is removed.

42.4 I/O INTERACTION
============================================================

A computer needs to communicate with external devices.

Examples:

    Keyboard
    Mouse
    Display
    Disk
    Network
    USB device
    Sensors


Basic flow:

    CPU
     |
     ↓
 I/O Interface
     |
     ↓
 Device Controller
     |
     ↓
   Device


------------------------------------------------------------
42.4.1 PROGRAMMED I/O
------------------------------------------------------------

CPU repeatedly checks device status.

Example:

    CPU:
    "Ready?"

    Device:
    "No."

    CPU:
    "Ready?"

    Device:
    "No."

    CPU:
    "Ready?"

    Device:
    "Yes."


Then data is transferred.


Problem:

    CPU wastes processing time while waiting.


------------------------------------------------------------
42.4.2 INTERRUPT-DRIVEN I/O
------------------------------------------------------------

Instead:

    CPU does useful work.

When device needs attention:

    Device
      ↓
    Interrupt
      ↓
     CPU
      ↓
    ISR
      ↓
    Handle event
      ↓
    Return


ISR:

    Interrupt Service Routine


------------------------------------------------------------
42.4.3 DMA
------------------------------------------------------------

DMA:

    Direct Memory Access


For large data transfers:

    Device
       |
       ↓
      DMA
       |
       ↓
      RAM


CPU configures DMA, and the DMA mechanism performs
the transfer with limited CPU involvement.


After completion:

    DMA → Interrupt → CPU


Therefore:

    DMA and interrupts can work together.


------------------------------------------------------------
42.4.4 COMPLETE I/O FLOW
------------------------------------------------------------

Example:

A disk needs to transfer a block of data.

    CPU
     |
     | configure transfer
     ↓
    DMA
     |
     ↓
   Storage
     |
     | data transfer
     ↓
    DMA
     |
     ↓
    RAM
     |
     ↓
   Interrupt
     |
     ↓
    CPU


CPU does not need to manually move every byte/word.


------------------------------------------------------------
42.4.5 MEMORY-MAPPED I/O
------------------------------------------------------------

In memory-mapped I/O:

    Device registers
        ↓
    occupy addresses in the memory address space


CPU can access device registers using normal
memory-style instructions, subject to the architecture.


Conceptually:

    Address Space
    ┌───────────────────┐
    │ RAM                │
    ├───────────────────┤
    │ Device Registers   │
    └───────────────────┘

42.5.7 COMPLETE BRANCH JOURNEY
============================================================

      ↓
    Decode
      ↓
    Read R1,R2

    Compare
      ↓

============================================================
42.5.8 COMPLETE PIPELINE
============================================================

Multiple instructions can be processed simultaneously.

Stages:

    IF → ID → EX → MEM → WB


Example:

Cycle 1:

    I1 IF

Cycle 2:

    I1 ID | I2 IF

Cycle 3:

    I1 EX | I2 ID | I3 IF

Cycle 4:

    I1 MEM | I2 EX | I3 ID | I4 IF

Cycle 5:

    I1 WB | I2 MEM | I3 EX | I4 ID | I5 IF


The CPU can therefore have several instructions
in different stages at the same time.

Solutions include:

    Forwarding

============================================================
42.5.9 PERFORMANCE CONNECTION
============================================================

Computer performance depends on many factors.

Important equation:

    CPU Time
    =
    Instruction Count × CPI
    -----------------------
       Clock Rate


Therefore performance can be improved by:

    Lower instruction count
    Lower CPI
    Higher clock rate


But improving one factor may affect another.


Example:

    Larger cache
       ↓
    fewer cache misses
       ↓
    lower memory stalls
       ↓
    potentially lower CPI
       ↓
    better performance


============================================================
42.5.10 AMDahl'S LAW CONNECTION
============================================================

If only one part of a system is improved,
the entire system's speedup is limited.

Formula:

    Speedup =
    1 / [(1-f) + (f/S)]


Where:

    f = fraction improved
    S = speedup of improved part


Example:

If 90% of execution can be improved by 10×:

    Speedup =
    1 / [0.1 + 0.9/10]

    = 1 / [0.1+0.09]

    = 1/0.19

    ≈ 5.26×


Even though one part became 10× faster,
the whole system becomes only about 5.26× faster.

    CPU

    ├── Core 2

Multiple cores enable:

But introduce issues such as:

    Memory consistency
    Synchronization
    Race conditions
    False sharing

42.6.5 REAL COMPUTER: END-TO-END EXAMPLE
============================================================

Suppose the user runs a program:

    Calculate:
        C = A + B


STEP 1 — USER STARTS PROGRAM

Operating system loads the program.


STEP 2 — LOADER

Executable is mapped/loaded into the process's
virtual address space.


STEP 3 — MEMORY

Program contains:

    Code
    Data
    Stack
    Heap


STEP 4 — CPU

PC points to the first instruction.


STEP 5 — FETCH

CPU fetches instruction through the instruction
memory hierarchy.


STEP 6 — DECODE

Control/front-end logic identifies the instruction.


STEP 7 — OPERANDS

Required values may be obtained from:

    Registers
    Cache
    RAM

depending on where the data currently resides.


STEP 8 — EXECUTE

ALU performs:

    A + B


STEP 9 — RESULT

Result is placed in a register or memory,
depending on the generated instructions.


STEP 10 — CONTINUE

CPU executes the remaining instructions.


STEP 11 — I/O

If program needs input/output:

    Program
       ↓
       OS
       ↓
     Driver
       ↓
   I/O Controller
       ↓
     Device


STEP 12 — OUTPUT

Result is presented to the user.

42.8 THE MOST IMPORTANT QUESTIONS
============================================================

Q1. What is the role of ISA?

ANSWER:

    ISA defines the programmer-visible interface
    between software and processor hardware.


Q2. What does the PC store?

ANSWER:

    It holds the address of the next instruction
    to be fetched, subject to the architecture's
    execution rules.


Q3. What does the IR store?

ANSWER:

    The instruction currently being processed.


Q4. What does the ALU do?

ANSWER:

    Arithmetic, logical and related data-processing
    operations.


Q5. What does the Control Unit do?

ANSWER:

    Coordinates operations by generating control signals.


Q6. Why is cache needed?

ANSWER:

    To reduce average memory-access latency by keeping
    useful data/instructions closer to the processor.


Q7. What is TLB?

ANSWER:

    A cache of recent virtual-to-physical address
    translations.


Q8. What happens on a page fault?

ANSWER:

    The required page is not currently resident in
    physical memory, so the operating system handles
    the fault and arranges for the page to be brought
    into memory.


Q9. Why is pipelining used?

ANSWER:

    To increase instruction throughput by overlapping
    instruction stages.


Q10. What is DMA?

ANSWER:

    A mechanism that allows data transfer between
    an I/O device and memory with limited CPU
    involvement.


Q11. Architecture vs organization?

ANSWER:

    Architecture = what is visible/defined by the
    machine interface.

    Organization = how the hardware implements it.


Q12. Why do modern processors use multicore designs?

ANSWER:

    To obtain more parallel processing capability
    while managing power and thermal constraints
    associated with simply increasing clock frequency.

42.11 MASTER FORMULA SHEET
============================================================

SIGNED INTEGER:

    n-bit signed 2's complement range:

    -2^(n-1) to 2^(n-1)-1


CACHE:

    Lines =
    Cache Size / Block Size


    Offset =
    log₂(Block Size)


    Index =
    log₂(Number of Lines)


    Tag =
    Address Bits - Index Bits - Offset Bits


DIRECT MAPPING:

    Line =
    Memory Block Number MOD Number of Cache Lines


CACHE:

    Hit Rate =
    Hits / Total Accesses


    Miss Rate =
    1 - Hit Rate


AMAT:

    Hit Time + Miss Rate × Miss Penalty


VIRTUAL MEMORY:

    Offset Bits =
    log₂(Page Size)


    Number of Pages =
    Virtual Address Space / Page Size


CPU:

    CPU Cycles =
    Instruction Count × CPI


    CPU Time =
    IC × CPI / Clock Rate


    Clock Cycle Time =
    1 / Clock Rate


CPI:

    Average CPI =
    Σ(fi × CPIi)


SPEEDUP:

    Speedup =
    Old Execution Time / New Execution Time


PIPELINE:

    Pipelined Cycles =
    k + N - 1


    Non-pipelined Cycles =
    kN


    Ideal Speedup =
    kN / (k+N-1)


AMDahl:

    Speedup =
    1 / [(1-f)+(f/S)]

42.12 FINAL COMMON MISTAKES
============================================================

1. Saying CPU = ALU.

   WRONG.

   ALU is one component of CPU.


2. Saying cache and RAM are the same.

   WRONG.


3. Saying TLB stores program data.

   WRONG.

   TLB stores address translations.


4. Saying virtual address is physical address.

   WRONG.


5. Saying pipeline makes individual instructions
   automatically faster.

   Not necessarily.

   Its primary benefit is throughput.


6. Saying interrupt = DMA.

   WRONG.

   Interrupt = event notification.

   DMA = data-transfer mechanism.


7. Saying higher GHz always means higher performance.

   WRONG.


8. Saying RISC simply means "fewer instructions".

   WRONG.

   It describes an ISA/design philosophy.


9. Saying CISC cannot be pipelined.

   WRONG.


10. Confusing architecture and organization.

       Architecture = WHAT
       Organization = HOW


11. Confusing cache coherence with memory consistency.

   Coherence concerns the visibility/consistency of
   a particular memory location across caches.

   Memory consistency concerns ordering rules for
   memory operations.


12. Assuming every computer has exactly the same
   CPU/cache/memory structure.

   WRONG.

   The exact implementation depends on the architecture
   and processor design.

2. The executable is loaded/mapped into memory.

6. The Control Unit/front end decodes the instruction.

7. Registers provide operands when required.

8. The ALU or another execution unit performs the operation.

    available.

14. The pipeline allows multiple instructions to be in

16. Out-of-order execution may execute independent

17. Multiple cores may execute different threads.

18. I/O devices communicate through controllers/interfaces.

19. Interrupts can notify the CPU about events.

20. DMA can transfer large blocks of data between devices
    and memory efficiently.

21. The CPU continues executing instructions until the
    program completes.

22. The result may be stored in memory or sent to an I/O device.

42.17 FINAL COA INTERVIEW ANSWER
============================================================

If an interviewer asks:

"Explain Computer Organization and Architecture."

A strong answer can be:

    Computer Organization and Architecture explains how
    a computer system is designed and how its hardware
    executes software instructions.

    At the architectural level, the ISA defines the
    programmer-visible interface, including instructions,
    registers and addressing mechanisms.

    At the organizational level, the processor implements
    those instructions using components such as the ALU,
    Control Unit, registers, datapath, caches and memory
    systems.

    When a program runs, instructions are fetched from
    memory, decoded and executed by the CPU. Modern
    processors use caches, pipelining, branch prediction,
    out-of-order execution and multiple cores to improve
    performance.

    The CPU communicates with memory through the memory
    hierarchy and with external devices through I/O
    mechanisms such as interrupts and DMA.

    Therefore, COA connects software instructions,
    processor organization, memory, I/O and performance
    into one complete computer system.
