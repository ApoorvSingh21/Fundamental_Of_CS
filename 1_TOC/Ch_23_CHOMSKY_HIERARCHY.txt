1. INTRODUCTION TO CHOMSKY HIERARCHY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The Chomsky Hierarchy is a classification system for formal grammars
and formal languages.

It tells us:

    "How powerful is a particular type of grammar?"

and therefore:

    "What kinds of languages can this grammar describe?"

The hierarchy was introduced by linguist Noam Chomsky.

The four major levels are:

    Type 3 → Regular
    Type 2 → Context-Free
    Type 1 → Context-Sensitive
    Type 0 → Unrestricted

As we move from Type 3 toward Type 0:

    Grammar restrictions decrease
              ↓
    Grammar becomes more powerful
              ↓
    Language class becomes more powerful
              ↓
    Required computational machine becomes more powerful


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. WHY DO WE NEED THE CHOMSKY HIERARCHY?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Not every language can be recognized by the same computational model.

For example:

A simple pattern such as:

    strings ending in 01

can be handled by a finite automaton.

But a language such as:

    L = { aⁿbⁿ | n ≥ 0 }

requires remembering how many 'a's occurred.

A finite automaton does not have enough memory for this.

A PDA, with a stack, can handle it.

An even more complex language such as:

    L = { aⁿbⁿcⁿ | n ≥ 0 }

cannot be handled by an ordinary PDA.

A more powerful computational model is required.

Therefore we organize languages according to their expressive power.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3. THE BIG PICTURE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The entire hierarchy can be visualized as:

                     MORE POWERFUL
                           ↑
                           │
              ┌─────────────────────────┐
              │ TYPE 0                   │
              │ RECURSIVELY ENUMERABLE   │
              │ Turing Machine           │
              └─────────────────────────┘
                           ↑
              ┌─────────────────────────┐
              │ TYPE 1                   │
              │ CONTEXT-SENSITIVE       │
              │ Linear Bounded Automaton │
              └─────────────────────────┘
                           ↑
              ┌─────────────────────────┐
              │ TYPE 2                   │
              │ CONTEXT-FREE            │
              │ Pushdown Automaton       │
              └─────────────────────────┘
                           ↑
              ┌─────────────────────────┐
              │ TYPE 3                   │
              │ REGULAR                 │
              │ Finite Automaton         │
              └─────────────────────────┘

                     LESS POWERFUL


Therefore:

    REGULAR
       ⊆
    CONTEXT-FREE
       ⊆
    CONTEXT-SENSITIVE
       ⊆
    RECURSIVELY ENUMERABLE


IMPORTANT:

These inclusions are proper:

    REGULAR ⊊ CFL ⊊ CSL ⊊ RE

4. FORMAL GRAMMAR — QUICK FOUNDATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Before understanding the hierarchy, remember what a grammar is.

A grammar is a set of rules used to generate strings belonging to
a language.

A formal grammar can generally be represented as:

    G = (V, T, P, S)

where:

    V = set of variables/non-terminals
    T = set of terminals
    P = production rules
    S = start symbol

Example:

    S → aS
    S → b

Starting from S:

    S
    ↓
    aS
    ↓
    aaS
    ↓
    aab

Therefore:

    aab

is generated by the grammar.

The important point is that different types of grammars impose
different restrictions on their production rules.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
23.1 TYPE 3 — REGULAR GRAMMAR
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A Type 3 grammar is called a REGULAR GRAMMAR.

It is the most restricted grammar in the Chomsky hierarchy.

Its corresponding machine model is:

    FINITE AUTOMATON

Its corresponding language class is:

    REGULAR LANGUAGE


──────────────────────────────────────────────────────────────────────
5. REGULAR GRAMMAR
──────────────────────────────────────────────────────────────────────

A regular grammar generally has productions of forms such as:

    A → aB
    A → a

for a right-linear grammar.

Here:

    A, B = non-terminals
    a    = terminal

Example:

    S → aA
    A → bS
    A → b

This grammar is regular.

A left-linear grammar can instead use forms such as:

    A → Ba
    A → a

A grammar should normally maintain one consistent linear direction
for regularity.


──────────────────────────────────────────────────────────────────────
6. REGULAR GRAMMAR EXAMPLE
──────────────────────────────────────────────────────────────────────

Consider:

    S → 0S
    S → 1

Derivation:

    S
    ↓
    0S
    ↓
    00S
    ↓
    001

Therefore:

    001

belongs to the language.

Other generated strings include:

    1
    01
    001
    0001
    00001
    ...

So the language is:

    L = { 0ⁿ1 | n ≥ 0 }


──────────────────────────────────────────────────────────────────────
7. FINITE AUTOMATA AND TYPE 3
──────────────────────────────────────────────────────────────────────

Regular grammars correspond to finite automata.

The relationship is:

    Regular Grammar
          ↕
    Regular Language
          ↕
    DFA / NFA / ε-NFA


ASCII representation:

    Regular Grammar
           │
           ▼
    Regular Language
           │
       ┌───┴───┐
       ▼       ▼
      DFA      NFA
       │
       ▼
   Finite Memory


A finite automaton has only a finite number of states.

Therefore it cannot remember an arbitrarily large amount of information.


──────────────────────────────────────────────────────────────────────
8. TYPE 3 SUMMARY
──────────────────────────────────────────────────────────────────────

    Type 3
       ↓
    Regular Grammar
       ↓
    Regular Language
       ↓
    Finite Automaton

Examples:

    L = { strings ending in 1 }

    L = { 0ⁿ1 | n ≥ 0 }

    L = strings containing "101"


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
23.2 TYPE 2 — CONTEXT-FREE LANGUAGE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Type 2 grammars are called:

    CONTEXT-FREE GRAMMARS (CFGs)

Their corresponding languages are:

    CONTEXT-FREE LANGUAGES (CFLs)

Their corresponding machine model is:

    PUSHDOWN AUTOMATA (PDA)


──────────────────────────────────────────────────────────────────────
9. CONTEXT-FREE GRAMMAR
──────────────────────────────────────────────────────────────────────

A CFG has productions of the form:

    A → α

where:

    A = exactly one non-terminal
    α = a string of terminals and/or non-terminals

The left side contains exactly one non-terminal.

Example:

    S → aSb
    S → ε

This grammar generates:

    ε
    ab
    aabb
    aaabbb
    aaaabbbb
    ...

Therefore:

    L = { aⁿbⁿ | n ≥ 0 }


──────────────────────────────────────────────────────────────────────
10. WHY IS THIS NOT REGULAR?
──────────────────────────────────────────────────────────────────────

Consider:

    L = { aⁿbⁿ | n ≥ 0 }

Examples:

    ε
    ab
    aabb
    aaabbb
    aaaabbbb

The number of a's must equal the number of b's.

A finite automaton has only finite memory.

A PDA has a stack.

The PDA can:

    read a
       ↓
    push something onto stack

Then:

    read b
       ↓
    pop something from stack

ASCII:

    Input:
       a a a b b b
       ↓ ↓ ↓ ↓ ↓ ↓

    Stack:
       push push push
                   pop pop pop

This allows the machine to compare the two quantities.


──────────────────────────────────────────────────────────────────────
11. CFG AND PDA RELATIONSHIP
──────────────────────────────────────────────────────────────────────

    Context-Free Grammar
             ↕
    Context-Free Language
             ↕
    Pushdown Automaton

Therefore:

    CFG ⇔ PDA

in expressive power for context-free languages.


──────────────────────────────────────────────────────────────────────
12. TYPE 2 EXAMPLES
──────────────────────────────────────────────────────────────────────

Examples of CFLs include:

    L = { aⁿbⁿ | n ≥ 0 }

Balanced parentheses:

    ()
    (())
    ()()
    (()())

Programming-language syntax is another important application.

For example, nested structures:

    if
       if
          statement
       else
          statement

require a richer mechanism than a simple finite automaton.


──────────────────────────────────────────────────────────────────────
13. TYPE 2 SUMMARY
──────────────────────────────────────────────────────────────────────

    Type 2
       ↓
    Context-Free Grammar
       ↓
    Context-Free Language
       ↓
    Pushdown Automaton
       ↓
    Stack memory


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
23.3 TYPE 1 — CONTEXT-SENSITIVE LANGUAGE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Type 1 grammars are called:

    CONTEXT-SENSITIVE GRAMMARS (CSGs)

Their languages are:

    CONTEXT-SENSITIVE LANGUAGES (CSLs)

Their corresponding machine model is:

    LINEAR BOUNDED AUTOMATON (LBA)


──────────────────────────────────────────────────────────────────────
14. CONTEXT-SENSITIVE GRAMMAR
──────────────────────────────────────────────────────────────────────

A context-sensitive grammar generally uses productions where the
replacement may depend on surrounding context.

A common form is:

    αAβ → αγβ

where:

    A = non-terminal
    α, β = surrounding context
    γ = replacement string

An important property is:

    The production generally does not decrease string length.

Therefore:

    |RHS| ≥ |LHS|

except for certain special treatment involving the start symbol in
formal definitions.

Such grammars are also called:

    NON-CONTRACTING GRAMMARS


──────────────────────────────────────────────────────────────────────
15. EXAMPLE OF A CONTEXT-SENSITIVE LANGUAGE
──────────────────────────────────────────────────────────────────────

Consider:

    L = { aⁿbⁿcⁿ | n ≥ 1 }

Examples:

    abc
    aabbcc
    aaabbbccc
    aaaabbbbcccc
    ...

The language requires:

    number of a's
       =
    number of b's
       =
    number of c's


A normal PDA cannot generally handle this language.

A more powerful model is required:

    Linear Bounded Automaton


──────────────────────────────────────────────────────────────────────
16. LINEAR BOUNDED AUTOMATON
──────────────────────────────────────────────────────────────────────

An LBA is a restricted form of Turing Machine.

The key restriction is:

    Its usable tape is bounded by a linear function of the
    input length.

If the input has length n, the machine can use approximately:

    O(n)

space.

ASCII:

    Input:

    a a a b b b c c c
    ┌─────────────────┐
    │                 │
    └─────────────────┘
       bounded tape

Unlike an ordinary TM, the machine cannot freely use an unlimited
amount of tape relative to the input.


──────────────────────────────────────────────────────────────────────
17. TYPE 1 RELATIONSHIP
──────────────────────────────────────────────────────────────────────

    Context-Sensitive Grammar
              ↕
    Context-Sensitive Language
              ↕
    Linear Bounded Automaton


──────────────────────────────────────────────────────────────────────
18. TYPE 1 SUMMARY
──────────────────────────────────────────────────────────────────────

    Type 1
       ↓
    Context-Sensitive Grammar
       ↓
    Context-Sensitive Language
       ↓
    Linear Bounded Automaton


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
23.4 TYPE 0 — RECURSIVELY ENUMERABLE LANGUAGES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Type 0 is the most general grammar class in the Chomsky hierarchy.

It is called:

    UNRESTRICTED GRAMMAR

Its corresponding language class is:

    RECURSIVELY ENUMERABLE LANGUAGES

Its corresponding machine model is:

    TURING MACHINE


──────────────────────────────────────────────────────────────────────
19. UNRESTRICTED GRAMMAR
──────────────────────────────────────────────────────────────────────

A Type 0 grammar has essentially no restriction on the form of
production rules, apart from the standard requirement that the
left-hand side contains at least one non-terminal.

A general production may look like:

    α → β

where α contains at least one non-terminal.

The right side can be a string of terminals and/or non-terminals.


──────────────────────────────────────────────────────────────────────
20. TURING MACHINE
──────────────────────────────────────────────────────────────────────

A Turing Machine has:

    • Tape
    • Read/write head
    • States
    • Transition function
    • Input alphabet
    • Tape alphabet

ASCII:

             Read/Write Head
                    ↓
    ─────────────────────────────────────
    ... | 0 | 1 | 1 | 0 | □ | □ | □ | ...
    ─────────────────────────────────────
                    ↑
                  Tape

The tape provides much more computational power than:

    finite-state memory

or

    a single stack.


──────────────────────────────────────────────────────────────────────
21. RECURSIVELY ENUMERABLE LANGUAGE
──────────────────────────────────────────────────────────────────────

A language is recursively enumerable (RE), also called
Turing-recognizable, if some Turing Machine recognizes it.

The machine has two important possibilities:

For a string in the language:

    TM eventually accepts.

For a string not in the language:

    TM may reject
    OR
    TM may run forever.


This is an important distinction from a decider.

A decider must halt on every input.


──────────────────────────────────────────────────────────────────────
22. TYPE 0 RELATIONSHIP
──────────────────────────────────────────────────────────────────────

    Unrestricted Grammar
             ↕
    Recursively Enumerable Language
             ↕
       Turing Machine

23.5 COMPLETE COMPARISON
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The four levels can be memorized using this table:

    ┌────────┬────────────────────────┬────────────────────────────┐
    │ Type   │ Grammar                │ Machine                    │
    ├────────┼────────────────────────┼────────────────────────────┤
    │ Type 3 │ Regular Grammar        │ Finite Automaton            │
    │ Type 2 │ Context-Free Grammar   │ Pushdown Automaton          │
    │ Type 1 │ Context-Sensitive      │ Linear Bounded Automaton    │
    │        │ Grammar                │                            │
    │ Type 0 │ Unrestricted Grammar   │ Turing Machine              │
    └────────┴────────────────────────┴────────────────────────────┘


Corresponding languages:

    Type 3 → Regular Languages

    Type 2 → Context-Free Languages

    Type 1 → Context-Sensitive Languages

    Type 0 → Recursively Enumerable Languages

24. EXPRESSIVE POWER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

"Expressive power" means:

    How many different languages can this computational model
    recognize or generate?

As we move downward from Type 0 to Type 3:

    Computational power decreases.

As we move upward from Type 3 to Type 0:

    Computational power increases.


ASCII:

    MORE EXPRESSIVE
          ↑
          │
    Type 0 ──────────────────── Most powerful
          │
    Type 1
          │
    Type 2
          │
    Type 3 ──────────────────── Least powerful
          │
          ↓
    LESS EXPRESSIVE


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
25. INCLUSION RELATIONSHIP
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The fundamental relationship is:

    REGULAR
       ⊊
    CONTEXT-FREE
       ⊊
    CONTEXT-SENSITIVE
       ⊊
    RECURSIVELY ENUMERABLE


Or:

    R ⊊ CFL ⊊ CSL ⊊ RE


This means:

Every regular language is context-free.

Every context-free language is context-sensitive.

Every context-sensitive language is recursively enumerable.

BUT the reverse is not generally true.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
26. EXAMPLE OF THE INCLUSION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Consider:

    L₁ = { 0*1* }

This is regular.

Therefore:

    L₁ ∈ REGULAR

and consequently:

    L₁ ∈ CFL
    L₁ ∈ CSL
    L₁ ∈ RE


Now consider:

    L₂ = { aⁿbⁿ | n ≥ 0 }

This is context-free but not regular.

Therefore:

    L₂ ∈ CFL

but:

    L₂ ∉ REGULAR


Now consider:

    L₃ = { aⁿbⁿcⁿ | n ≥ 1 }

This is context-sensitive but not context-free.

Therefore:

    L₃ ∈ CSL

but:

    L₃ ∉ CFL


This demonstrates why the hierarchy is useful.

    Type 3:
        MOST RESTRICTED

        ↓

    Type 2:
        LESS RESTRICTED

        ↓

    Type 1:
        EVEN LESS RESTRICTED

        ↓

    Type 0:
        LEAST RESTRICTED

    More restrictions
          ↓
    Less expressive power

and:

    Fewer restrictions
          ↓
    More expressive power

29. REAL-WORLD ANALOGY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Imagine four people trying to solve increasingly difficult tasks.

TYPE 3 — Person with only a small checklist

    Can recognize simple patterns.

TYPE 2 — Person with a stack of papers

    Can remember nested information.

TYPE 1 — Person with a workspace proportional to the task size

    Can perform more complex comparisons.

TYPE 0 — Person with a large general-purpose workspace

    Can perform general computation.

This is not a formal definition, but it gives the intuition.

31. VERY IMPORTANT DIFFERENCES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

REGULAR vs CONTEXT-FREE

Regular:
    Machine → Finite Automaton
    Memory  → Finite states

Context-Free:
    Machine → PDA
    Memory  → Stack

Example:

    { aⁿbⁿ }

is not regular but is context-free.


CONTEXT-FREE vs CONTEXT-SENSITIVE

Context-Free:
    PDA

Context-Sensitive:
    LBA

Important example:

    { aⁿbⁿcⁿ }

is context-sensitive but not context-free.


CONTEXT-SENSITIVE vs RECURSIVELY ENUMERABLE

Context-Sensitive:
    LBA

Recursively Enumerable:
    Turing Machine

Type 0 is more general and more powerful.

32. B.TECH EXAM IMPORTANT POINTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

You should remember:

1. Chomsky hierarchy has four types.

2. Type 3 = Regular Grammar.

3. Type 2 = Context-Free Grammar.

4. Type 1 = Context-Sensitive Grammar.

5. Type 0 = Unrestricted Grammar.

6. Type 3 corresponds to finite automata.

7. Type 2 corresponds to PDA.

8. Type 1 corresponds to LBA.

9. Type 0 corresponds to Turing Machine.

10. The inclusion is:

       REGULAR ⊊ CFL ⊊ CSL ⊊ RE

11. Computational power increases from Type 3 to Type 0.

12. Grammar restrictions decrease from Type 3 to Type 0.

33. GATE / COMPETITIVE EXAM POINTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

VERY IMPORTANT:

    Every regular language is CFL.

    Every CFL is CSL.

    Every CSL is RE.

But:

    Not every CFL is regular.

    Not every CSL is CFL.

    Not every RE language is CSL.


Typical examples:

    { aⁿbⁿ | n ≥ 0 }

        → CFL
        → not Regular


    { aⁿbⁿcⁿ | n ≥ 1 }

        → CSL
        → not CFL


Be careful:

    "More powerful machine" does NOT mean every language it
    recognizes is exclusive to that machine.

For example, a Turing Machine can recognize a regular language too.

The hierarchy describes classes and their minimum corresponding
formal models, not exclusive machine usage.

The Chomsky hierarchy organizes formal grammars into four levels:

    TYPE 3
        Regular Grammar
        Regular Language
        Finite Automaton

            ↓

    TYPE 2
        Context-Free Grammar
        Context-Free Language
        Pushdown Automaton

            ↓

    TYPE 1
        Context-Sensitive Grammar
        Context-Sensitive Language
        Linear Bounded Automaton

            ↓

    TYPE 0
        Unrestricted Grammar
        Recursively Enumerable Language
        Turing Machine


The central relationship is:

    REGULAR ⊊ CFL ⊊ CSL ⊊ RE


The key idea:

    As we go from Type 3 → Type 0:

        Grammar restrictions decrease
                    ↓
        Memory/computational power increases
                    ↓
        Expressive power increases
