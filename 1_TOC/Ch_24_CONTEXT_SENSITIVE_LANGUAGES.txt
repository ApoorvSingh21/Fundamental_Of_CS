24.1 WHY DO WE NEED CONTEXT-SENSITIVE GRAMMARS?
============================================================

Before CSG, remember the basic language hierarchy.

                    More expressive
                         ↑
                         |
             Type 0     │  Recursively Enumerable
                         |
             Type 1     │  Context-Sensitive
                         |
             Type 2     │  Context-Free
                         |
             Type 3     │  Regular
                         |
                         ↓
                    Less expressive


The important inclusion is:

    Regular
       ⊂
    Context-Free
       ⊂
    Context-Sensitive
       ⊂
    Recursively Enumerable


The symbol "⊂" means:

    "is a proper subset of"

Therefore:

    Every regular language is context-free.

    Every context-free language is context-sensitive.

    But the reverse is NOT always true.


------------------------------------------------------------
Why is CFG not enough?
------------------------------------------------------------

A Context-Free Grammar can easily generate:

    L = { a^n b^n | n >= 0 }

Example strings:

    ε
    ab
    aabb
    aaabbb
    aaaabbbb
    ...


But consider:

    L = { a^n b^n c^n | n >= 1 }

Examples:

    abc
    aabbcc
    aaabbbccc
    aaaabbbbcccc
    ...


Here we need THREE quantities to remain equal:

    number of a's
        =
    number of b's
        =
    number of c's


This language is NOT context-free.

Therefore, we need a more powerful grammar.

That grammar is called:

    CONTEXT-SENSITIVE GRAMMAR


============================================================
24.2 WHAT IS A CONTEXT-SENSITIVE GRAMMAR?
============================================================

Simple definition:

A Context-Sensitive Grammar (CSG) is a grammar in which
a production can depend on the surrounding context of a
non-terminal.

In simple words:

    The replacement of a symbol may depend on what is
    around that symbol.

This is the reason for the name:

    CONTEXT + SENSITIVE


------------------------------------------------------------
Formal definition
------------------------------------------------------------

A grammar is generally represented as:

    G = (V, Σ, P, S)

where:

    V = set of variables/non-terminals

    Σ = set of terminals

    P = set of production rules

    S = start symbol


For a context-sensitive grammar, productions generally have
the form:

    αAβ → αγβ

where:

    A is a non-terminal
    α and β represent the surrounding context
    γ is a non-empty string


The important idea is:

    The replacement of A can depend on α and β.


------------------------------------------------------------
Very important restriction
------------------------------------------------------------

For a standard CSG:

    |LHS| <= |RHS|

That means:

    Length of left-hand side
        <=
    Length of right-hand side


In other words:

    A CSG production normally DOES NOT DECREASE
    the length of the string.


Such grammars are therefore called:

    NON-CONTRACTING GRAMMARS


Example:

    AB → ABC

Length:

    LHS = 2
    RHS = 3

Therefore:

    2 <= 3

Allowed.


Another example:

    ABC → ABDC

Length:

    LHS = 3
    RHS = 4

Allowed.


But:

    ABC → A

Length:

    LHS = 3
    RHS = 1

This decreases the length.

Therefore it is NOT allowed in a standard
non-contracting CSG.


============================================================
24.3 WHAT DOES "CONTEXT-SENSITIVE" MEAN?
============================================================

Let's understand the word "context".

Suppose we have:

    xAy

Here:

    A = symbol being replaced

    x = left context

    y = right context


A context-sensitive rule could look like:

    xAy → xBy


Notice that A is changed to B while the surrounding context
remains unchanged.


ASCII representation:

        left context       right context
             |                  |
             v                  v

             x   A   y
                 |
                 |
                 v
             x   B   y


The surrounding symbols x and y represent the context.


------------------------------------------------------------
Comparison with CFG
------------------------------------------------------------

CFG rule:

    A → B

The replacement of A does not depend on surrounding symbols.


CSG-style rule:

    xAy → xBy

The replacement can depend on the context.


Therefore:

    CFG:
        A → B

    CSG:
        xAy → xBy


IMPORTANT:

Context-sensitive grammars are more powerful than
context-free grammars.


============================================================
24.4 NON-CONTRACTING GRAMMAR
============================================================

This is one of the most important concepts in this chapter.


Definition:

A grammar is non-contracting if every production satisfies:

    |α| <= |β|

for a production:

    α → β


That means the RHS cannot be shorter than the LHS.


Example 1:

    A → ab

Length:

    1 → 2

Allowed.


Example 2:

    AB → abc

Length:

    2 → 3

Allowed.


Example 3:

    ABC → ABCD

Length:

    3 → 4

Allowed.


Example 4:

    AB → A

Length:

    2 → 1

NOT allowed.


------------------------------------------------------------
Why is this restriction important?
------------------------------------------------------------

Because a context-sensitive grammar is intended to
describe computations where the amount of information
does not suddenly shrink.


This property also connects CSG with:

    Linear Bounded Automata (LBA)


------------------------------------------------------------
Special case: ε-production
------------------------------------------------------------

There is an important technical exception involving ε.

Normally, CSG productions are non-contracting.

However, in some formal definitions, a rule such as:

    S → ε

is permitted provided that:

    S does not occur on the RHS of any production.


Different textbooks may present slightly different
formal conventions.

For university/GATE preparation, remember:

    Main rule:
        |LHS| <= |RHS|

    Special handling of ε may depend on the definition
    being used.


============================================================
24.5 CONTEXT-SENSITIVE LANGUAGE
============================================================

Definition:

A language is called a Context-Sensitive Language (CSL)
if it can be generated by a Context-Sensitive Grammar.


Therefore:

    CSG
      ↓ generates
    CSL


Notation:

    L(G)

means:

    the language generated by grammar G.


If G is a CSG, then:

    L(G)

is a context-sensitive language.


------------------------------------------------------------
Example
------------------------------------------------------------

Consider:

    L = { a^n b^n c^n | n >= 1 }


Some strings:

    abc
    aabbcc
    aaabbbccc
    aaaabbbbcccc
    ...


This language is context-sensitive.


It requires equality between three groups:

    a-count = b-count = c-count


This is beyond the power of CFG.


============================================================
24.6 INTUITION USING a^n b^n c^n
============================================================

Let's understand why this language is difficult.

Suppose:

    n = 3

Then:

    a^3 b^3 c^3

becomes:

    aaabbbccc


We need:

    3 a's
    3 b's
    3 c's


For:

    n = 5

we need:

    aaaaa bbbbb ccccc


Again:

    5 = 5 = 5


The grammar must maintain a relationship between
THREE different groups.


A useful conceptual picture is:

    aaa | bbb | ccc
     |     |     |
     |     |     |
     +-----+-----+
       equal counts


A CSG is powerful enough to describe such dependencies.


============================================================
24.7 EXAMPLE OF A CONTEXT-SENSITIVE GRAMMAR
============================================================

Consider the language:

    L = { a^n b^n c^n | n >= 1 }


One possible grammar construction can use auxiliary
non-terminals to keep track of the matching process.


For teaching purposes, we focus on the idea rather than
memorizing one particular construction.

Conceptually:

    S
    |
    v
    a A B c
       |
       v
    a A B B c
       |
       v
    a a A B B c
       |
       v
    ...
    |
    v
    a^n b^n c^n


The grammar introduces additional symbols and uses
context-sensitive rules to move/transform these symbols
while preserving the required relationships.


IMPORTANT:

Do not try to memorize a CSG construction mechanically.

Instead understand:

    1. Introduce markers/non-terminals.
    2. Generate the required structure.
    3. Move markers through the string.
    4. Convert markers into terminals.
    5. Ensure equal quantities.
    6. Never violate the non-contracting condition.


============================================================
24.8 ANOTHER IMPORTANT EXAMPLE
============================================================

Consider:

    L = { ww | w ∈ {0,1}* }


Examples:

    ε
    00
    11
    0101
    0110
    101101
    ...


The language requires two copies of exactly the same string.

For example:

    w = 101

then:

    ww = 101101


This type of copying dependency is much more difficult than
ordinary regular patterns.


CSGs can express substantially more complex dependencies
than CFGs.


============================================================
24.9 LINEAR BOUNDED AUTOMATON (LBA)
============================================================

Now we connect CSG with an automaton.


First remember:

    DFA
      ↓
    finite amount of memory


    PDA
      ↓
    stack memory


    Turing Machine
      ↓
    unbounded tape


LBA lies between PDA and unrestricted TM in computational
power.


------------------------------------------------------------
Simple definition
------------------------------------------------------------

A Linear Bounded Automaton (LBA) is a restricted
Turing Machine whose tape usage is limited to a linear
function of the input size.


In simple words:

    An LBA is a Turing Machine that cannot use unlimited
    tape space.


If input length is:

    n


then the machine can use at most:

    O(n)

tape cells, up to the convention used for the model.


------------------------------------------------------------
ASCII diagram
------------------------------------------------------------

Input:

    a a b b c c

Tape:

    +---+---+---+---+---+---+
    | a | a | b | b | c | c |
    +---+---+---+---+---+---+
          ^
        head


The LBA must operate within a bounded region related
to the input.


Unlike an ordinary TM:

    Ordinary TM:
    
    <--- potentially unlimited tape --->


    LBA:

    |<------ O(n) cells ------>|


============================================================
24.10 WHY IS LBA RELATED TO CSG?
============================================================

This is one of the most important relationships in
Theory of Computation.

The fundamental correspondence is:

    Context-Sensitive Languages
                ↕
    Linear Bounded Automata


In standard theory:

    CSL = languages accepted by LBA


Therefore:

    CSG
      ↓
    CSL
      ↕
    LBA


This is an important part of the Chomsky hierarchy.


============================================================
24.11 LBA VS TURING MACHINE
============================================================

               Turing Machine       LBA
------------------------------------------------------------
Tape           Unbounded            Linearly bounded
Memory         Unbounded            O(n)
Power          More powerful        Restricted
Language       RE languages         CSL
Model          General computation  Restricted computation


ASCII:


TURING MACHINE

    ----------------------------------------------->
    potentially unbounded tape


LBA

    +-------------------------------+
    |          bounded tape         |
    +-------------------------------+


The LBA has a restricted amount of workspace.

24.14 CSG VS CFG
============================================================

This distinction is VERY IMPORTANT.


+----------------------+----------------------+----------------------+
| Property             | CFG                  | CSG                  |
+----------------------+----------------------+----------------------+
| Chomsky type         | Type 2               | Type 1               |
| Production           | A → α                | α → β                 |
| Context dependence   | No                   | Yes                  |
| Length restriction   | Not generally        | |LHS| <= |RHS|       |
| Memory model         | PDA                  | LBA                  |
| Language class       | CFL                  | CSL                  |
| Power                | Less                 | More                 |
+----------------------+----------------------+----------------------+


Simple memory trick:

    CFG → PDA

    CSG → LBA


And:

    Type 2 → Context-Free

    Type 1 → Context-Sensitive


============================================================
24.15 CFG VS CSG WITH EXAMPLES
============================================================

CFG can generate:

    { a^n b^n | n >= 0 }


Example:

    S → aSb
    S → ε


Derivation:

    S
    ↓
    aSb
    ↓
    aaSbb
    ↓
    aaεbb
    ↓
    aabb


So:

    aabb


is generated.


But:

    { a^n b^n c^n | n >= 1 }


is NOT context-free.


It is context-sensitive.


Therefore:

    CFG cannot express every CSL.

    CSG can express languages beyond CFL.


============================================================
24.16 IMPORTANT PROPERTIES OF CSL
============================================================

Important properties to remember:

1. Every regular language is context-sensitive.

2. Every context-free language is context-sensitive.

3. Some context-sensitive languages are not context-free.

4. CSGs are generally non-contracting.

5. CSLs are associated with LBAs.

6. LBA uses linearly bounded tape.

7. CSL is Type 1 in the Chomsky hierarchy.


============================================================
24.17 WHAT DOES "MORE POWERFUL" MEAN?
============================================================

This is a common source of confusion.


When we say:

    CSG is more powerful than CFG


we do NOT mean:

    CSG always runs faster.


We mean:

    CSG can describe/generate a larger class of languages.


For example:

    CFG:
        can generate a^n b^n


    CSG:
        can generate a^n b^n c^n


Therefore:

    More expressive power
        ≠
    faster computation

    A rule describing how symbols can be replaced.

24.21 STEP-BY-STEP WAY TO IDENTIFY A CSG
============================================================

Suppose an exam gives production rules.

Use this procedure:


STEP 1:
    Identify the grammar.

STEP 2:
    Look at every production.

STEP 3:
    Check whether the RHS is shorter than the LHS.

STEP 4:
    If:

        |LHS| <= |RHS|

    the rule satisfies the non-contracting condition.

STEP 5:
    Check special ε-production conventions.

STEP 6:
    Determine whether the grammar fits Type 1.


Example:


    AB → ABC

Lengths:

    |AB| = 2
    |ABC| = 3

Therefore:

    2 <= 3

Allowed.


Another:


    ABC → AB

Lengths:

    |ABC| = 3
    |AB| = 2

Therefore:

    3 > 2

Not non-contracting.

24.26 COMMON MISTAKES
============================================================

MISTAKE 1:

Thinking:

    Context-sensitive = every rule must explicitly
    contain left and right context.


Correction:

    The formal definition is more general than this
    intuitive picture. The important standard property
    is the non-contracting condition, with the usual
    formal restrictions.


------------------------------------------------------------

MISTAKE 2:

Thinking:

    CSG means context is required in every production.


Correction:

    Not necessarily in the informal sense.

    Focus on the formal definition and non-contracting
    property used in your syllabus.


------------------------------------------------------------

MISTAKE 3:

Thinking:

    CSG = CFG


Correction:

    No.

    CFG = Type 2
    CSG = Type 1


------------------------------------------------------------

MISTAKE 4:

Thinking:

    LBA = ordinary Turing Machine


Correction:

    LBA is a restricted Turing Machine whose tape
    usage is linearly bounded by input size.


------------------------------------------------------------

MISTAKE 5:

Thinking:

    More powerful means faster.


Correction:

    More powerful means more expressive.

    It can describe a larger class of languages.


------------------------------------------------------------

MISTAKE 6:

Confusing:

    Context-sensitive language

with:

    Context-free language


Remember:

    CFL → Type 2
    CSL → Type 1

24.33 CHAPTER 24 SUMMARY
============================================================

Context-Sensitive Grammar:

    A Type 1 grammar capable of generating
    context-sensitive languages.


Main production property:

    |LHS| <= |RHS|


Non-contracting:

    Production cannot reduce the length of
    the sentential form.


Context-Sensitive Language:

    A language generated by a CSG.


Classic example:

    {a^n b^n c^n | n >= 1}


Machine associated with CSL:

    Linear Bounded Automaton.


LBA:

    A restricted Turing Machine using tape space
    linearly bounded by the input size.


Hierarchy:

    Regular
       ⊂
    Context-Free
       ⊂
    Context-Sensitive
       ⊂
    Recursively Enumerable


Automata correspondence:

    Regular       → FA
    Context-Free  → PDA
    Context-Sensitive → LBA
    Type 0        → TM
