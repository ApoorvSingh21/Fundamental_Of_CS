1. WHAT IS COMPUTATION?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Before understanding Theory of Computation, we must understand the
word "computation".

SIMPLE MEANING
--------------

Computation means performing a systematic process to obtain an answer
from given information.

In simple words:

    INPUT
      ↓
    PROCESSING
      ↓
    OUTPUT

Example:

    Input:
        5 + 3

    Processing:
        Perform addition

    Output:
        8


REAL-WORLD EXAMPLES
-------------------

Example 1: Calculator

    Input       Processing       Output
    ─────       ──────────       ──────
     5, 3   →   addition    →      8


Example 2: ATM

    Input:
        Card + PIN + withdrawal amount

    Processing:
        Verify card
        Verify PIN
        Check balance
        Deduct money

    Output:
        Cash / Error message


Example 3: Google Search

    Input:
        Search query

    Processing:
        Search and ranking algorithms

    Output:
        Search results


FORMAL IDEA
-----------

A computation is a sequence of well-defined steps performed according
to some rules to transform input into output or determine an answer.

The important phrase is:

    "well-defined steps"

This means the process should not depend on guessing.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. WHAT IS A COMPUTATIONAL PROBLEM?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A computational problem is a problem that can potentially be solved
by a computational process.

Examples:

    Problem 1:
    Is 17 an even number?

    Problem 2:
    What is 25 × 13?

    Problem 3:
    Is a password valid?

    Problem 4:
    Does a particular string belong to a language?

    Problem 5:
    Can a computer program eventually stop?


IMPORTANT IDEA
--------------

Not every problem that can be described is necessarily solvable by
a computer.

This is one of the most important reasons we study TOC.

TOC asks questions such as:

    Can this problem be solved?

    If it can be solved,
    what kind of machine can solve it?

    How much time does the solution require?

    How much memory does it require?

    Are there problems that NO algorithm can solve?

3. WHAT IS THEORY OF COMPUTATION?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

SIMPLE DEFINITION
-----------------

Theory of Computation (TOC) is the area of Computer Science that
studies the mathematical foundations of computation.

In simpler words:

    TOC studies:

    "What can computers compute?"

    "What can computers NOT compute?"

    "How can computation be formally described?"

    "How efficiently can problems be solved?"


FORMAL DEFINITION
-----------------

Theory of Computation is a branch of theoretical computer science
concerned with the study of abstract computational models, formal
languages, computability, and computational complexity.


BREAKING THE DEFINITION
-----------------------

The definition contains several important ideas.

1. ABSTRACT

   We often study simplified mathematical models of computers.

2. COMPUTATIONAL MODELS

   We create mathematical machines that describe computation.

3. FORMAL LANGUAGES

   We study mathematically defined collections of strings.

4. COMPUTABILITY

   We study whether a problem can be solved algorithmically.

5. COMPLEXITY

   We study the resources required to solve problems.

4. WHY DOES THEORY OF COMPUTATION EXIST?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Suppose someone asks:

    "Can a computer solve every possible problem?"

The answer is:

    NO.

This immediately creates important questions.

    ┌──────────────────────────────────────────────┐
    │              COMPUTATION QUESTIONS           │
    ├──────────────────────────────────────────────┤
    │ Can a problem be solved?                     │
    │ What machine can solve it?                   │
    │ How much memory is required?                 │
    │ How much time is required?                   │
    │ Are some problems impossible to solve?       │
    └──────────────────────────────────────────────┘

TOC provides mathematical tools for answering these questions.


WHY NOT JUST STUDY REAL COMPUTERS?
-----------------------------------

Because real computers are complicated.

A real computer contains:

    CPU
    RAM
    Cache
    Storage
    Operating system
    Programming language
    Hardware
    Network
    etc.

Studying all these details makes it difficult to understand the
fundamental limits of computation.

Therefore, TOC uses simplified mathematical machines.

For example:

    Real Computer
         │
         │ simplify
         ▼
    Mathematical Model
         │
         ▼
    Study computation


This is similar to physics.

A physicist may study an idealized object such as:

    "frictionless surface"

even though a perfectly frictionless surface does not exist.

Why?

Because simplification helps us understand fundamental principles.

TOC does the same thing with computation.

6. WHAT IS A COMPUTATIONAL MODEL?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

SIMPLE DEFINITION
-----------------

A computational model is a mathematical or abstract representation
of how computation can be performed.

Instead of studying a physical computer, we study an idealized
mathematical machine.

Example:

    Input
      │
      ▼
    ┌─────────────┐
    │   MACHINE   │
    │             │
    │ computation │
    └─────────────┘
      │
      ▼
    Output


WHY DO WE NEED MODELS?
----------------------

Models allow us to answer precise questions.

For example:

    "Can this machine recognize this pattern?"

    "Can this machine remember an arbitrary amount of information?"

    "Can this machine solve this problem?"

Different computational models have different capabilities.


IMPORTANT MODELS IN TOC
-----------------------

We will study several models.

    Finite Automaton
          │
          ▼
    Regular Languages


    Pushdown Automaton
          │
          ▼
    Context-Free Languages


    Turing Machine
          │
          ▼
    General Computation


Very roughly:

    More memory / power
           ↑
           │
    Turing Machine
           │
    Pushdown Automaton
           │
    Finite Automaton
           │
           └──────────────→ Increasing computational power


Do NOT interpret this diagram as saying that every property is simply
"more memory = better". Each model is useful for a particular class of
problems.

7. WHAT IS A MACHINE IN TOC?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The word "machine" in TOC does NOT necessarily mean a physical
computer.

A machine is an abstract computational system that follows defined
rules.

A basic machine can be viewed as:

             INPUT
               │
               ▼
        ┌───────────────┐
        │    MACHINE    │
        │               │
        │  PROCESSING   │
        │               │
        └───────────────┘
               │
               ▼
             OUTPUT


A machine can:

    read information
    change its internal state
    follow rules
    produce an answer
    accept or reject input
    sometimes continue forever


EXAMPLE
-------

Imagine a machine that checks whether a password ends in "123".

Input:

    abc123

The machine processes the characters.

If the condition is satisfied:

    ACCEPT


If the input is:

    abc456

then:

    REJECT


This simple idea will later lead us to finite automata.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
8. INPUT, PROCESSING, AND OUTPUT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

These three ideas appear throughout TOC.

INPUT
-----

Information provided to the computational system.

Examples:

    10101
    "hello"
    25
    a program
    a mathematical string


PROCESSING
----------

The machine follows a defined set of rules.

OUTPUT
------

The result produced by the computation.

Basic model:

    ┌────────┐
    │ INPUT  │
    └───┬────┘
        │
        ▼
    ┌────────────┐
    │ PROCESSING │
    └─────┬──────┘
          │
          ▼
    ┌─────────┐
    │ OUTPUT  │
    └─────────┘


IMPORTANT
---------

In some TOC models, the output is not necessarily a normal value.

For example, a machine may simply answer:

    ACCEPT

or

    REJECT

9. FORMAL METHODS OF DESCRIBING COMPUTATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Computers execute precise rules.

Therefore, TOC needs precise mathematical descriptions.

We use things such as:

    Sets
    Functions
    Relations
    Mathematical notation
    State diagrams
    Transition tables
    Grammars
    Formal languages


Example of an abstract machine:

        0
    ┌───────┐
    │       ▼
   (q0) ──→ (q1)
     │
     │ 1
     └──────→ (q0)


Here:

    q0 and q1 = states

    0 and 1 = input symbols

    arrows = transitions

We will study these concepts carefully later.


WHY FORMALISM?
--------------

Suppose I say:

    "The machine sometimes moves to another state."

This is vague.

But if I define a transition function mathematically, the behavior
becomes precise.

For example:

    δ(q0, 0) = q1

This means:

    "When the machine is in state q0 and reads input 0,
     it moves to state q1."

The symbol δ (delta) will become very important later.

10. AUTOMATA THEORY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

-----------------

Automata theory studies abstract machines and the problems they can
recognize or process.

The singular form is:

    automaton

Plural:

    automata


IMPORTANT
---------

An automaton is not necessarily a physical robot.

It is a mathematical model of computation.


Examples of automata we will study:

11. FORMAL LANGUAGES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The word "language" in TOC is different from a natural language such
as English or Hindi.

A formal language is a mathematically defined set of strings.

For example:

    L = {0, 1, 01, 10}

is a language.

Here:

    0
    1
    01
    10

are strings belonging to the language.


WHY ARE LANGUAGES IMPORTANT?
----------------------------

Computers process symbols and strings.

For example:

    Programming languages
    Machine instructions
    Network protocols
    Search patterns
    Text formats

can all be described using formal rules.

TOC therefore studies:

    strings
       ↓
    languages
       ↓
    machines that recognize languages


BASIC RELATIONSHIP

    Alphabet
       ↓
    Strings
       ↓
    Language
       ↓
    Machine
       ↓
    Acceptance / rejection


We will study alphabets, symbols, strings, and languages in detail
later.

12. COMPUTABILITY THEORY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Now we reach a deeper question.

Suppose we have a problem.

Can any algorithm solve it?

Computability theory studies the fundamental limits of computation.

In simple words:

    "What can be computed?"

and:

    "What cannot be computed?"


EXAMPLE
-------

Suppose we give a program P and ask:

    "Will P eventually stop?"

This sounds like a reasonable question.

But there are problems for which no general algorithm can always
correctly answer such questions.

The famous example is:

    HALTING PROBLEM


We will study this much later.


COMPUTABILITY QUESTION
----------------------

    Problem
       │
       ▼
    Is there an algorithm
    that always solves it?
       │
       ├───────────────┐
       │               │
      YES              NO
       │               │
       ▼               ▼
   Computable      Uncomputable
   problem          problem


This is one of the central ideas of TOC.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
13. COMPLEXITY THEORY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Suppose a problem CAN be solved.

A second question appears:

    "How efficiently can it be solved?"


Example:

Suppose two algorithms solve the same problem.

Algorithm A:

    10 steps


Algorithm B:

    1,000,000 steps


Both may be correct, but Algorithm A is much more efficient.

Complexity theory studies the resources required for computation.

The two major resources are:

    TIME
    SPACE


TIME COMPLEXITY

14. AUTOMATA vs COMPUTABILITY vs COMPLEXITY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

These three areas are often confused.

AUTOMATA THEORY
---------------

Main idea:

    Study abstract machines and the languages they recognize.

Typical question:

    "Can a finite automaton recognize this pattern?"


COMPUTABILITY THEORY
--------------------

Main idea:

    Study what problems can or cannot be solved algorithmically.

Typical question:

    "Does an algorithm exist for this problem?"


COMPLEXITY THEORY
-----------------

Main idea:

    Study the resources required to solve problems.

Typical question:

    "How efficiently can this problem be solved?"


COMPARISON

    ┌──────────────────┬──────────────────────────────┐
    │ Area             │ Main Question                │
    ├──────────────────┼──────────────────────────────┤
    │ Automata         │ What can this machine do?    │
    │ Computability    │ Can this problem be solved?  │
    │ Complexity       │ How efficiently is it solved?│
    └──────────────────┴──────────────────────────────┘

15. RELATIONSHIP BETWEEN MACHINES AND LANGUAGES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

This is one of the most important ideas in the entire subject.

A machine can process strings.

A language is a set of strings.

Therefore, we can ask:

    "Which strings does this machine accept?"


Example:

Suppose:

    Alphabet = {0,1}

and a machine accepts strings ending in 1.

Then:

    L = {1, 01, 11, 001, 101, 111, ...}


The machine recognizes the language L.


ASCII VIEW

                   strings
                      │
                      ▼
              ┌──────────────┐
              │    MACHINE   │
              └──────┬───────┘
                     │
             ┌───────┴────────┐
             │                │
             ▼                ▼
          ACCEPT            REJECT
             │                │
             ▼                ▼
      String belongs     String does not
      to language        belong to language


This machine-language relationship will appear repeatedly throughout
TOC.

16. REAL-WORLD APPLICATIONS OF TOC
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

TOC is not merely theoretical.

Its concepts appear in many areas of Computer Science.

1. COMPILERS
------------

Formal languages and grammars are used to describe programming
languages.

Example:

    if (x > 5) {
        ...
    }

A compiler must determine whether program syntax follows the rules
of the programming language.

Relevant TOC concepts:

    Grammars
    CFG
    Parsing
    Automata


2. TEXT SEARCH
--------------

Regular expressions are used to search patterns.

Example:

    Find strings containing digits.

TOC concepts:

    Regular expressions
    Finite automata


3. NETWORK PROTOCOLS
--------------------

State machines can model protocol states.

Example:

    CLOSED
       │
       │ connect
       ▼
    CONNECTED
       │
       │ disconnect
       ▼
    CLOSED


4. DIGITAL SYSTEMS
------------------

Finite-state machines are used in the design and analysis of digital
systems.


5. ARTIFICIAL INTELLIGENCE
--------------------------

Some computational problems require analysis of computational
resources and tractability.


6. CYBERSECURITY
----------------

Formal models can be useful for protocol analysis, pattern matching,
and verification.


7. SOFTWARE VERIFICATION
------------------------

Automata and formal methods can help determine whether systems satisfy
specified properties.

17. IMPORTANT BASIC TERMINOLOGY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Learn these words carefully.

COMPUTATION
-----------
A systematic process of performing defined operations to obtain a
result.

ALGORITHM
---------
A finite, well-defined procedure for solving a problem.

MACHINE
-------
An abstract or physical system that performs computation.

AUTOMATON
---------
An abstract mathematical machine used to model computation.

AUTOMATA
--------
Plural of automaton.

ALPHABET
--------
A finite set of symbols.

STRING
------
A finite sequence of symbols from an alphabet.

LANGUAGE
--------
A set of strings over an alphabet.

STATE
-----
A condition or configuration representing the machine's current
situation.

TRANSITION
----------
A change from one state to another according to a rule.

INPUT
-----
Information supplied to a computational system.

OUTPUT
------
The result produced by computation.

ACCEPT
------
The machine determines that the input satisfies the required
condition.

REJECT
------
The machine determines that the input does not satisfy the required
condition.

COMPUTABILITY
-------------
Study of what can and cannot be computed.

COMPLEXITY
----------
Study of the resources required for computation.

18. A SIMPLE COMPLETE EXAMPLE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PROBLEM:

Design a conceptual machine that accepts strings ending in 1.

Alphabet:

    Σ = {0,1}

Some input examples:

    1       → ACCEPT
    01      → ACCEPT
    101     → ACCEPT
    111     → ACCEPT

But:

    0       → REJECT
    10      → REJECT
    100     → REJECT


CONCEPTUAL MACHINE

    ┌─────────────────────────────┐
    │                             │
    │       "Does string end      │
    │             in 1?"          │
    │                             │
    └──────────────┬──────────────┘
                   │
            ┌──────┴──────┐
            │             │
            ▼             ▼
         ACCEPT         REJECT


For the input:

    101

the machine reads:

    1 → 0 → 1

The final symbol is 1.

Therefore:

    ACCEPT


For:

    100

the machine reads:

    1 → 0 → 0

The final symbol is 0.

Therefore:

    REJECT


Later, we will construct the exact DFA for this problem.

19. MATHEMATICAL VIEW OF COMPUTATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

At a high level, computation can be viewed as:

    Input
      │
      ▼
    Function / Procedure
      │
      ▼
    Output


Mathematically, a function may be written as:

    f : A → B

Read this as:

    "f is a function from set A to set B."

For example:

    f(x) = x + 1

Then:

    f(5) = 6


In TOC, we will use mathematical structures to describe machines,
languages, transitions, and computations.

Do not worry if this notation is new.

We will build the mathematical foundation separately in Chapter 2.

QUESTION:

"What is Theory of Computation?"

GOOD BEGINNER ANSWER:

"Theory of Computation is a branch of theoretical computer science
that studies mathematical models of computation, formal languages,
what problems can be solved computationally, and the resources needed
to solve them."


QUESTION:

"Why do we need abstract machines?"

ANSWER:

"Abstract machines simplify real computers into mathematical models,
allowing us to study the fundamental capabilities and limitations of
computation."


QUESTION:

"What is the difference between computability and complexity?"

ANSWER:

"Computability asks whether a problem can be solved at all, while
complexity asks how efficiently it can be solved."

24. COMMON BEGINNER MISTAKES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

MISTAKE 1:

Thinking that "machine" always means a physical computer.

CORRECT:

In TOC, machine usually means an abstract mathematical model.


MISTAKE 2:

Thinking that every problem can be solved by a computer.

CORRECT:

Some problems are undecidable.


MISTAKE 3:

Thinking that computability and complexity are the same.

CORRECT:

    Computability → Can it be solved?

    Complexity   → How efficiently can it be solved?


MISTAKE 4:

Thinking that a formal language must be English, Hindi, etc.

CORRECT:

A formal language is simply a mathematically defined set of strings.


MISTAKE 5:

Trying to memorize DFA/NFA before understanding strings and languages.

CORRECT:

We first build the foundation.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Theory of Computation is the study of the mathematical foundations
and limits of computation.

The major questions are:

    WHAT can be computed?
    WHAT cannot be computed?
    HOW efficiently can something be computed?

The major areas are:

    Automata Theory
    Formal Languages
    Computability Theory
    Complexity Theory

An abstract machine is a mathematical model used to study computation.

A machine can process input according to defined rules.

A formal language is a set of strings.

Automata can be used to recognize languages.

Computability studies whether problems can be solved algorithmically.

Complexity studies the resources required to solve problems.

These concepts form the foundation for the rest of TOC.
