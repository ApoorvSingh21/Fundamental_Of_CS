The lexical analyzer checks:

    "What are the words/tokens?"

    "Are these tokens arranged according to the language grammar?"

    INT

    ASSIGN
    NUM
    SEMICOLON

3. WHAT IS A GRAMMAR?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A grammar is a formal system used to describe how valid strings in a
language can be constructed.

In programming languages, grammar defines syntactic structures such as:

    expressions
    statements
    declarations
    functions
    loops
    conditionals


Example:

    Expression → Expression + Term
    Expression → Term

This says that an Expression can be:

    Expression + Term

or simply:

    Term


A grammar gives rules for constructing valid sentences/strings.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
4. FORMAL DEFINITION OF CONTEXT-FREE GRAMMAR
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A Context-Free Grammar is usually represented as:

    G = (V, T, P, S)

where:

    V = set of non-terminals
    T = set of terminals
    P = set of productions
    S = start symbol


Therefore:

    CFG = (Non-terminals, Terminals, Productions, Start Symbol)


These four components are extremely important for GATE.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
5. COMPONENT 1 — NON-TERMINALS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Non-terminals represent syntactic categories.

Examples:

    E
    T
    F
    Statement
    Expression
    Declaration


They can be replaced using production rules.

For example:

    E → E + T


Here:

    E and T

are non-terminals.


A non-terminal represents a structure that can still be expanded.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
6. COMPONENT 2 — TERMINALS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Terminals are the basic symbols that appear in strings generated by
the grammar.

Examples:

    +
    -
    *
    /
    (
    )
    id
    num


Terminals cannot be further expanded by grammar productions.


Example:

    E → E + T

Here:

    +

is a terminal.

E and T are non-terminals.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
7. TERMINALS VS NON-TERMINALS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

                Grammar Symbols
                      │
             ┌────────┴────────┐
             │                 │
             ▼                 ▼
        Non-terminals       Terminals
             │                 │
             │                 │
       Can be expanded     Cannot be expanded
             │                 │
       E, T, F, S          +, *, (, ), id


Example:

    E → E + T

    E = non-terminal
    T = non-terminal
    + = terminal


Important:

    Terminal symbols form the final generated string.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
8. COMPONENT 3 — PRODUCTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Production rules specify how non-terminals can be replaced.

General form:

    A → α

where:

    A = a non-terminal

    α = a string of terminals and/or non-terminals


Example:

    E → E + T

    T → T * F

    F → (E)

    F → id


These are productions.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
9. COMPONENT 4 — START SYMBOL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The start symbol is the non-terminal from which derivation begins.

It is usually represented by:

    S

or sometimes:

    E

for expression grammars.


Example:

    S → aSb
    S → ε


Here:

    S

is the start symbol.


A generated string begins with the start symbol.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
10. COMPLETE CFG EXAMPLE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Consider:

    G = ({S}, {a,b}, P, S)

where:

    P:
        S → aSb
        S → ε


Components:

    Non-terminal:
        S

    Terminals:
        a, b

    Productions:
        S → aSb
        S → ε

    Start symbol:
        S


This grammar generates:

    ε
    ab
    aabb
    aaabbb
    aaaabbbb
    ...


Therefore the language is:

    L = { aⁿbⁿ | n ≥ 0 }


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
11. WHAT DOES CONTEXT-FREE MEAN?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A production in a CFG has a single non-terminal on its left-hand side.

General form:

    A → α


The replacement of A does not depend on the symbols surrounding A.

That is why it is called:

    CONTEXT-FREE


Example:

    S → aSb


Whenever we see S, we can replace it according to the rule,
regardless of the surrounding context.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
12. CFG DERIVATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A derivation is the process of repeatedly applying production rules
starting from the start symbol.

Consider:

    S → aSb
    S → ε


To generate:

    aabb


Start:

    S


Apply:

    S → aSb


Now:

    aSb


Apply S → aSb again:

    a(aSb)b

which gives:

    aaSbb


Now apply:

    S → ε


Result:

    aabb


Therefore:

    S
    ⇒ aSb
    ⇒ aaSbb
    ⇒ aabb


This is a derivation.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
13. DERIVATION SYMBOL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

We commonly use:

    ⇒

to mean:

    "derives in one or more grammar steps"

Example:

    S ⇒ aSb


For multiple steps:

    S ⇒* aabb


The notation:

    ⇒

usually represents one derivation step.

The notation:

    ⇒*

represents zero or more derivation steps.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
14. SENTENTIAL FORM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A sentential form is any string of terminals and/or non-terminals that
can be derived from the start symbol.

For grammar:

    S → aSb
    S → ε


Derivation:

    S
    ⇒ aSb
    ⇒ aaSbb
    ⇒ aabb


All of these can be sentential forms:

    S
    aSb
    aaSbb
    aabb


Important:

    A sentential form may contain non-terminals.

A SENTENCE is a sentential form containing only terminals.


Therefore:

    Sentential form:
        may contain terminals + non-terminals

    Sentence:
        contains only terminals


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
15. SENTENCE VS SENTENTIAL FORM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Example:

    S ⇒ aSb ⇒ aaSbb ⇒ aabb


Sentential forms:

    S
    aSb
    aaSbb
    aabb


Final:

    aabb

contains only terminals.

Therefore:

    aabb = sentence


Memory:

    Sentential form = may contain N

    Sentence = no non-terminal remains


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
16. LEFTMOST DERIVATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

In a LEFTMOST DERIVATION, at every step we replace the
LEFTMOST non-terminal first.

Notation:

    ⇒lm


Example grammar:

    E → E + T
    E → T
    T → id


Generate:

    id + id


Start:

    E


Step 1:

    E ⇒ E + T


Now there are two non-terminals:

    E + T

The leftmost non-terminal is:

    E


Replace E:

    E + T ⇒ T + T


Now leftmost non-terminal is:

    T


Replace:

    T + T ⇒ id + T


Then:

    id + T ⇒ id + id


Therefore:

    E
    ⇒ E + T
    ⇒ T + T
    ⇒ id + T
    ⇒ id + id


This is a leftmost derivation.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
17. RIGHTMOST DERIVATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

In a RIGHTMOST DERIVATION, at every step we replace the
RIGHTMOST non-terminal first.

Notation:

    ⇒rm


Using:

    E → E + T
    E → T
    T → id


Generate:

    id + id


Start:

    E


    E
    ⇒ E + T


Rightmost non-terminal:

    T


    ⇒ E + id


Now rightmost non-terminal:

    E


    ⇒ T + id


Now:

    ⇒ id + id


Therefore:

    E
    ⇒ E + T
    ⇒ E + id
    ⇒ T + id
    ⇒ id + id


This is a rightmost derivation.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
18. LEFTMOST VS RIGHTMOST DERIVATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

LEFTMOST:

    Always expand the leftmost non-terminal.


RIGHTMOST:

    Always expand the rightmost non-terminal.


Example:

    E + T


Leftmost non-terminal:

    E


Rightmost non-terminal:

    T


Important:

    Both can generate the same sentence.


They differ in the ORDER in which non-terminals are expanded.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
19. WHY DERIVATIONS MATTER IN COMPILER DESIGN
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Derivations explain how a parser can construct a syntactic structure.

Top-down parsing is closely associated with:

    Leftmost derivation


Bottom-up parsing is closely associated with:

    Rightmost derivation in reverse


This becomes extremely important in later chapters.

Remember:

    Top-down:
        attempts to construct a leftmost derivation.


    Bottom-up:
        constructs a rightmost derivation in reverse.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
20. PARSE TREE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A parse tree is a tree representation of a derivation.

It shows:

    • Start symbol
    • Non-terminals
    • Terminals
    • Production relationships


Example grammar:

    E → E + T
    E → T
    T → id


For:

    id + id


Conceptual parse tree:

              E
             /|\
            E + T
            |   |
            T   id
            |
            id


The root is:

    E


Leaves are:

    id + id


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
21. PARTS OF A PARSE TREE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A parse tree has:

    Root:
        Start symbol

    Internal nodes:
        Usually non-terminals

    Leaves:
        Terminals or ε


The left-to-right sequence of terminal leaves is called the:

    YIELD

or:

    FRONTIER


Example:

                E
               /|\
              E + T
              |   |
              id  id


Yield:

    id + id


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
22. DERIVATION VS PARSE TREE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

DERIVATION:

    Sequence of production-rule applications.


PARSE TREE:

    Tree representation of the syntactic structure.


Example:

Derivation:

    E
    ⇒ E + T
    ⇒ T + T
    ⇒ id + T
    ⇒ id + id


Parse tree:

                E
               /|\
              E + T
              |   |
              T   id
              |
              id


Both describe the same generation process.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
23. PARSE TREE AND ABSTRACT SYNTAX TREE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Do not confuse:

    Parse Tree

with:

    AST


Parse tree:

    Contains detailed grammatical structure.


AST:

    Removes many unnecessary grammar details and represents the
    essential program structure.


For:

    a + b * c


A parse tree may contain many grammar-related nodes.

AST focuses on:

             +
            / \
           a   *
              / \
             b   c


The AST is introduced more deeply in the Intermediate Representation
chapter.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
24. AMBIGUOUS GRAMMAR
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A grammar is AMBIGUOUS if there exists at least one string in its
language that has:

    more than one distinct parse tree

or equivalently:

    more than one distinct leftmost derivation

or:

    more than one distinct rightmost derivation.


This is a critical definition.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
25. CLASSIC AMBIGUOUS EXPRESSION GRAMMAR
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Consider:

    E → E + E
    E → E * E
    E → (E)
    E → id


Now consider:

    id + id * id


This grammar allows multiple interpretations.


Interpretation 1:

    id + (id * id)


Interpretation 2:

    (id + id) * id


Therefore the grammar is ambiguous.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
26. WHY AMBIGUITY IS A PROBLEM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Suppose:

    a + b * c


If the grammar permits both:

    a + (b * c)

and:

    (a + b) * c


the compiler cannot uniquely determine the intended structure from
the grammar alone.

This can cause problems in:

    • Parsing
    • Semantic interpretation
    • Code generation
    • Program meaning


Therefore programming-language grammars are generally designed to avoid
unwanted ambiguity.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
27. OPERATOR PRECEDENCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

One way to remove ambiguity is to encode operator precedence in the
grammar.

For example:

    multiplication has higher precedence than addition.


Instead of:

    E → E + E
    E → E * E
    E → (E)
    E → id


we can use:

    E → E + T
    E → T

    T → T * F
    T → F

    F → (E)
    F → id


Now:

    * has higher precedence than +.


For:

    id + id * id


the intended structure becomes:

    id + (id * id)


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
28. WHY E, T, F ARE USED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Common expression grammar:

    E → E + T | T

    T → T * F | F

    F → (E) | id


Meaning:

    E = Expression
    T = Term
    F = Factor


Hierarchy:

    Expression
        ↓
      Terms
        ↓
     Factors


Because:

    E handles +

    T handles *

    F handles basic operands/parenthesized expressions


This hierarchy encodes precedence.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
29. OPERATOR ASSOCIATIVITY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Precedence tells us which operator binds more strongly.

Associativity tells us how operators of the SAME precedence group.

Example:

    a - b - c


Left associativity:

    (a - b) - c


Right associativity:

    a - (b - c)


Grammar design can encode associativity.


For left-associative subtraction, a typical grammar is:

    E → E - T | T


The recursive occurrence on the left helps represent left association.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
30. AMBIGUITY AND ASSOCIATIVITY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Consider:

    a - b - c


If grammar allows:

    (a - b) - c

and:

    a - (b - c)

then the grammar is ambiguous for that string.


A properly designed grammar can encode the desired associativity.


Therefore grammar design controls:

    • Precedence
    • Associativity
    • Structure


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
31. ANOTHER AMBIGUOUS EXAMPLE — IF-ELSE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Consider nested conditional statements:

    if E1 then
        if E2 then
            S1
        else
            S2


Question:

    Which if does the else belong to?


Possibility 1:

    else belongs to inner if.


Possibility 2:

    else belongs to outer if.


This is called the:

    dangling-else problem.


A grammar that does not resolve this properly can be ambiguous.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
32. DANGLING ELSE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A common language convention is:

    ELSE associates with the nearest unmatched IF.


For example:

    if E1 then
        if E2 then
            S1
        else
            S2


The else normally belongs to:

    if E2


Language grammars/parser rules can be designed to enforce this behavior.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
33. REMOVING AMBIGUITY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Ambiguity can sometimes be removed by redesigning the grammar.

Common techniques include:

    1. Encode operator precedence.
    2. Encode associativity.
    3. Separate grammar levels.
    4. Rewrite ambiguous constructs.
    5. Explicitly distinguish matched/unmatched statements
       for dangling-else-style grammars.


Important:

    Not every ambiguous CFG can be converted into an equivalent
    unambiguous CFG.


Some languages are inherently ambiguous.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
34. INHERENTLY AMBIGUOUS LANGUAGE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A context-free language is called inherently ambiguous if:

    Every CFG generating that language is ambiguous.


This is an advanced theoretical concept.

Important distinction:

    Ambiguous grammar
        → a particular grammar is ambiguous.


    Inherently ambiguous language
        → no unambiguous CFG exists for that language.


Therefore:

    Grammar ambiguity and language inherent ambiguity are NOT the same.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
35. CFG AND PROGRAMMING LANGUAGES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

CFGs are useful for describing syntax such as:

    Expressions
    Statements
    Blocks
    Function declarations
    Parameter lists
    Conditional statements
    Loops


Example:

    statement → if (expression) statement
              | while (expression) statement
              | expression ;


A parser uses such grammar rules to determine structure.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
36. LEXICAL RULES VS CFG RULES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

This is extremely important.

LEXICAL STRUCTURE:

    Usually described using:

        Regular Expressions
        Finite Automata


SYNTACTIC STRUCTURE:

    Usually described using:

        Context-Free Grammars


Relationship:

    Characters
       ↓
    Regex / DFA
       ↓
    Tokens
       ↓
    CFG / Parser
       ↓
    Parse tree


Memory:

    REGEX → WORD/TOKEN LEVEL

    CFG → SENTENCE/SYNTAX LEVEL


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
37. EXAMPLE — COMPLETE CONNECTION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Source:

    x + y * z


LEXER:

    ID
    PLUS
    ID
    MUL
    ID


PARSER uses grammar:

    E → E + T | T
    T → T * F | F
    F → id


The parser determines:

    x + (y * z)


Therefore:

    Lexer recognizes tokens.

    Parser determines grammatical structure.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
38. GATE CONCEPT — AMBIGUITY TEST
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

To show that a grammar is ambiguous, it is sufficient to find:

    ONE string

with:

    TWO distinct parse trees.


You do NOT need to prove that every string is ambiguous.


Very important:

    One ambiguous string
          ↓
    Grammar is ambiguous


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
39. GATE CONCEPT — TWO DERIVATIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

For a CFG, if a string has:

    two distinct leftmost derivations

then the grammar is ambiguous.

Similarly:

    two distinct rightmost derivations

also proves ambiguity.


However, merely having different derivation sequences does not
necessarily mean ambiguity if they produce the same parse tree.

The important criterion is:

    distinct parse trees.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
40. GATE CONCEPT — SENTENCE VS SENTENTIAL FORM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Remember:

    Sentential form:
        derived from start symbol and may contain non-terminals.


    Sentence:
        a sentential form containing only terminals.


Example:

    S ⇒ aSb ⇒ aaSbb ⇒ aabb


    aSb
        = sentential form


    aabb
        = sentence


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
41. GATE CONCEPT — LEFTMOST DERIVATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Given:

    E → E + T
    E → T
    T → id


For:

    id + id


Leftmost derivation:

    E
    ⇒ E + T
    ⇒ T + T
    ⇒ id + T
    ⇒ id + id


At every step:

    expand LEFTMOST non-terminal.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
42. GATE CONCEPT — RIGHTMOST DERIVATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Same grammar:

    E → E + T
    E → T
    T → id


Rightmost derivation:

    E
    ⇒ E + T
    ⇒ E + id
    ⇒ T + id
    ⇒ id + id


At every step:

    expand RIGHTMOST non-terminal.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
43. PARSE TREE YIELD
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The yield of a parse tree is obtained by reading terminal leaves:

    LEFT → RIGHT


Example:

            E
           /|\
          E + T
          |   |
         id  id


Yield:

    id + id


Important:

    The yield contains terminals in their left-to-right order.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
44. CFG LANGUAGE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A grammar G generates a language denoted by:

    L(G)


L(G) is the set of all terminal strings that can be derived from
the start symbol.

Formally:

    L(G) = { w ∈ T* | S ⇒* w }


where:

    T* = all finite strings over terminals T

    S = start symbol

    w = terminal string


This is a very important formal definition.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
45. EXAMPLE OF L(G)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Grammar:

    S → aSb
    S → ε


We have:

    S ⇒ ε

so:

    ε ∈ L(G)


Also:

    S ⇒ aSb
      ⇒ ab

so:

    ab ∈ L(G)


Also:

    S ⇒ aSb
      ⇒ aaSbb
      ⇒ aabb


Therefore:

    aabb ∈ L(G)


Generally:

    L(G) = {aⁿbⁿ | n ≥ 0}


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
46. ε (EPSILON)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

ε represents:

    Empty string


Important:

    ε is a string of length 0.

It is NOT:

    a normal terminal character.


Example:

    S → ε


means:

    S can disappear during derivation.


Example:

    S ⇒ aSb
      ⇒ ab


because:

    S ⇒ ε


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
47. ε VS ∅
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Very important exam distinction:

    ε = empty string

    ∅ = empty language / empty set


Lengths:

    |ε| = 0


But:

    ∅ contains no strings.


Example:

    L = {ε}

is NOT the same as:

    L = ∅


The first language contains one string:

    ε


The second contains zero strings.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
48. CFG TERMINOLOGY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Grammar:

    G = (V, T, P, S)


V:

    Non-terminals / variables


T:

    Terminals


P:

    Production rules


S:

    Start symbol


Derivation:

    Application of productions


Sentential form:

    String derived from S that may contain non-terminals


Sentence:

    Sentential form containing only terminals


Parse tree:

    Tree representation of derivation


Ambiguous grammar:

    At least one string has multiple parse trees


Language generated:

    L(G) = {w ∈ T* | S ⇒* w}


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
49. COMMON MISTAKES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

MISTAKE 1:

    Thinking terminals can be expanded.

Correct:

    Terminals cannot be replaced by grammar productions.


MISTAKE 2:

    Thinking every derivation sequence is a different parse tree.

Correct:

    Different application orders can correspond to the same parse tree.


MISTAKE 3:

    Thinking one string must have two derivations for every ambiguous
    grammar.

Correct:

    Only ONE string with two distinct parse trees is sufficient.


MISTAKE 4:

    Confusing ε and ∅.

Correct:

    ε = empty string

    ∅ = empty language/set


MISTAKE 5:

    Confusing lexer and parser.

Correct:

    Lexer → tokens

    Parser → syntactic structure


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
50. IMPORTANT GATE-LEVEL EXAM PATTERNS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

GATE questions may ask:

    • Identify terminals/non-terminals.
    • Find language generated by a CFG.
    • Find leftmost derivation.
    • Find rightmost derivation.
    • Construct parse tree.
    • Determine whether grammar is ambiguous.
    • Count parse trees for a string.
    • Determine yield of parse tree.
    • Identify sentential forms.
    • Distinguish sentence and sentential form.
    • Determine precedence/associativity.
    • Analyze ε-productions.
    • Compare grammar-generated languages.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
51. MINI GATE PRACTICE EXAMPLE 1
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Grammar:

    S → aSb | ε


Question:

    Which strings belong to L(G)?

Options:

    A. ab
    B. aabb
    C. aaabbb
    D. All of the above


Reason:

    S ⇒ aSb ⇒ ab

    S ⇒ aSb ⇒ aaSbb ⇒ aabb

    S ⇒ aSb ⇒ aaSbb ⇒ aaaSbbb ⇒ aaabbb


Answer:

    D


The language is:

    {aⁿbⁿ | n ≥ 0}


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
52. MINI GATE PRACTICE EXAMPLE 2
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Grammar:

    E → E + E
    E → E * E
    E → id


String:

    id + id * id


Possible structures:

    id + (id * id)

and:

    (id + id) * id


Therefore:

    Grammar is ambiguous.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
53. MINI GATE PRACTICE EXAMPLE 3
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Grammar:

    S → aS | b


Possible derivation:

    S
    ⇒ aS
    ⇒ aaS
    ⇒ aab


Therefore:

    aab ∈ L(G)


Possible language:

    {aⁿb | n ≥ 0}


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
54. MINI GATE PRACTICE EXAMPLE 4
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Grammar:

    S → SS | (S) | ε


This grammar can generate balanced parentheses.

Examples:

    ε
    ()
    (())
    ()()
    (()())
    ...


This is a classic CFG example.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
55. WHY CFG IS MORE POWERFUL THAN REGULAR EXPRESSIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Regular expressions/finite automata cannot recognize every
context-free language.

Classic example:

    L = {aⁿbⁿ | n ≥ 0}


A finite automaton cannot generally keep an unbounded count of a's
and compare it with the number of b's.

A CFG can generate it:

    S → aSb | ε


Therefore:

    Regular languages ⊂ Context-free languages


Every regular language is context-free, but not every context-free
language is regular.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
56. CFG AND PDA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

There is a major theoretical relationship:

    Context-Free Languages
             ↕
    Pushdown Automata


A language is context-free if and only if it can be recognized by
some Pushdown Automaton (PDA).

Therefore:

    CFG ↔ PDA


Compare:

    Regular Language
        ↕
    Finite Automaton


    Context-Free Language
        ↕
    Pushdown Automaton


This relationship is important for TOC and compiler theory.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
57. CFG IN THE COMPILER PIPELINE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

              SOURCE CODE

          ┌────────────────┐

          └───────┬────────┘
                  ↓
               TOKENS

The CFG provides the grammatical rules used by the parser.

59. CHAPTER 9 — INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1. What is a CFG?

Answer:

    A CFG is a formal grammar G=(V,T,P,S) in which every production
    has a single non-terminal on the left-hand side.


Q2. What are the four components of CFG?

Answer:

    V = non-terminals
    T = terminals
    P = productions
    S = start symbol


Q3. What is a terminal?

Answer:

    A symbol that cannot be further expanded using grammar productions.


Q4. What is a non-terminal?

Answer:

    A syntactic category that can be expanded using production rules.


Q5. What is a derivation?

Answer:

    A sequence of production-rule applications starting from the
    start symbol.


Q6. What is a leftmost derivation?

Answer:

    A derivation in which the leftmost non-terminal is expanded at
    every step.


Q7. What is a rightmost derivation?

Answer:

    A derivation in which the rightmost non-terminal is expanded at
    every step.


Q8. What is a parse tree?

Answer:

    A tree representation of the syntactic derivation of a string.


Q9. What is an ambiguous grammar?

Answer:

    A grammar is ambiguous if at least one string generated by it has
    two or more distinct parse trees.


Q10. How can ambiguity be reduced in expression grammars?

Answer:

    By designing grammar levels that explicitly encode operator
    precedence and associativity.

60. CHAPTER 9 — MOST IMPORTANT DIFFERENCES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

    TERMINAL vs NON-TERMINAL
    ────────────────────────────────────────
    Terminal:
        Cannot be expanded.

    Non-terminal:
        Can be expanded.


    SENTENCE vs SENTENTIAL FORM
    ────────────────────────────────────────
    Sentence:
        Contains only terminals.

    Sentential form:
        May contain terminals and non-terminals.


    LEFTMOST vs RIGHTMOST
    ────────────────────────────────────────
    Leftmost:
        Expand leftmost non-terminal.

    Rightmost:
        Expand rightmost non-terminal.


    DERIVATION vs PARSE TREE
    ────────────────────────────────────────
    Derivation:
        Sequence of rule applications.

    Parse tree:
        Tree representation of structure.


    ε vs ∅
    ────────────────────────────────────────
    ε:
        Empty string.

    ∅:
        Empty set/language.


    REGEX vs CFG
    ────────────────────────────────────────
    Regex:
        Describes regular languages.

    CFG:
        Describes context-free languages.
