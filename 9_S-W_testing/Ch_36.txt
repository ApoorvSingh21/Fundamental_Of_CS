                         CHAPTER 36
                  CHOOSING A PROGRAMMING LANGUAGE
=======================================================================

OBJECTIVE
---------
The QA syllabus provides three programming-language paths:

    1. Java
    2. Python
    3. JavaScript / TypeScript

The goal is NOT to learn every language.

The goal is to choose one language and become comfortable enough to
build and maintain automation.

The language should support:

    • Programming fundamentals
    • Automation
    • API testing
    • Test frameworks
    • Reusable automation code
    • Interview preparation


=======================================================================
36.1 WHY CHOOSE A PROGRAMMING LANGUAGE?
=======================================================================

Automation tools require programming.

Examples:

    Selenium
        +
    Java / Python / JavaScript

    Playwright
        +
    Python / JavaScript / TypeScript


Therefore:

    Programming Language
            +
    Automation Tool
            +
    Test Framework
            =
    Automation Skill


A common mistake is trying to learn:

    Java
    +
    Python
    +
    JavaScript
    +
    Selenium
    +
    Playwright

all at the same time.

This creates unnecessary complexity.

The syllabus recommends choosing a suitable language and building
strong fundamentals first.

36.4 JAVA — OBJECT-ORIENTED PROGRAMMING
=======================================================================

OOP is important because automation frameworks commonly use
objects and reusable components.

Core OOP concepts include:

    • Classes
    • Objects
    • Encapsulation
    • Inheritance
    • Polymorphism
    • Abstraction


Example concept:

    LoginPage
       |
       +-- username field
       +-- password field
       +-- login action


An automation framework can represent application components as
objects.

This becomes especially useful when building reusable automation
structures.


=======================================================================
36.5 JAVA — COLLECTIONS
=======================================================================

Collections allow programs to work with groups of data.

Examples include concepts such as:

    List
    Set
    Map


QA examples:

    List
    ----
    Store multiple usernames.

    Set
    ---
    Verify unique IDs.

    Map
    ---
    Store field/value information.


Example conceptual data:

    user = {
        "name" : "Apoorv",
        "role" : "Tester"
    }


Collections become very important when processing:

    • Test data
    • API responses
    • Test results
    • Multiple test cases


=======================================================================
36.6 JAVA — EXCEPTIONS
=======================================================================

Java automation code must handle unexpected conditions.

Examples:

    • Element not available
    • Invalid data
    • File problem
    • Runtime failure


Exception handling allows automation code to handle such conditions
in a controlled way.

Concept:

    TRY
      |
      v
    Execute operation
      |
      +---- Success ----> Continue
      |
      +---- Exception -> Handle


The goal is not to hide failures.

The goal is to handle them appropriately and make failures
understandable.


=======================================================================
36.7 JAVA — STREAMS
=======================================================================

Streams provide a way to process collections of data.

Conceptually:

    Collection
        |
        v
      Stream
        |
        v
    Filter / Transform / Process
        |
        v
      Result


Example QA use case:

    Test results
         |
         v
    Filter failed tests
         |
         v
    Process failure information


Streams become useful when automation code needs to process
collections efficiently and expressively.

36.13 PYTHON EXCEPTIONS
=======================================================================

Python provides exception handling for runtime problems.

Concept:

    try:
        operation()

    except:
        handle_problem()


In automation, exception handling can help with:

    • File operations
    • API operations
    • Browser operations
    • Data processing


Again:

    Exception handling ≠ hiding test failures.

It should make failures controlled and understandable.


=======================================================================
36.14 PYTHON MODULES
=======================================================================

A module allows code to be organized and reused.

Concept:

    Module
       |
       +-- Functions
       +-- Classes
       +-- Reusable code


Example conceptual structure:

    login.py
        |
        +-- login()
        +-- logout()


Another test can reuse functionality from the module.


This becomes increasingly important as automation projects grow.


=======================================================================
36.15 PYTHON VIRTUAL ENVIRONMENTS
=======================================================================

A virtual environment provides an isolated environment for a Python
project's dependencies.

Concept:

    Project A
       |
       +-- Environment A
       +-- Dependencies A


    Project B
       |
       +-- Environment B
       +-- Dependencies B


This helps prevent dependency conflicts between projects.


For QA automation projects, this is useful when managing:

    • Automation libraries
    • API-testing libraries
    • Test frameworks
    • Project-specific dependencies

=======================================================================
36.21 JAVASCRIPT PROMISES
=======================================================================

Modern applications and automation often perform asynchronous
operations.

A Promise represents an operation whose result may become available
later.

Conceptually:

    Start operation
          |
          v
    Operation running
          |
          +---- Success → Result
          |
          +---- Failure → Error


This concept is important when working with asynchronous operations.


=======================================================================
36.22 ASYNC / AWAIT
=======================================================================

async/await provides a convenient way to work with asynchronous
operations.

Conceptually:

    async function
          |
          v
       await
          |
          v
    Wait for operation
          |
          v
       Continue


Example conceptual flow:

    login()
       |
       v
    await login()
       |
       v
    verify dashboard


This is particularly important for modern web automation where
operations may be asynchronous.

36.26 IMPORTANT DECISION RULE
=======================================================================

Do NOT choose a language merely because another tester uses it.

Choose based on:

    • Your existing programming background
    • Target automation tool
    • Job requirements
    • Your learning comfort
    • Long-term automation goals


Most importantly:

    ONE LANGUAGE
        ↓
    STRONG FUNDAMENTALS
        ↓
    AUTOMATION
        ↓
    PROJECTS


is better than:

    THREE LANGUAGES
        ↓
    SHALLOW KNOWLEDGE
        ↓
    NO AUTOMATION PROJECT

36.31 COMMON MISTAKES
=======================================================================

MISTAKE 1
---------

Trying to learn all three languages simultaneously.

Better:

    Choose one language.


MISTAKE 2
---------

Learning syntax without understanding programming concepts.

Better:

    Understand variables, conditions, loops, functions, collections,
    exceptions, and reusable code.


MISTAKE 3
---------

Learning a language without applying it to testing.

Better:

    Use the language to create small test/automation programs.


MISTAKE 4
---------

Jumping directly into Selenium/Playwright without programming.

Better:

    Build programming fundamentals first.


MISTAKE 5
---------

Learning tools without understanding code.

Better:

    Understand what your automation code is doing.

36.32 INTERVIEW QUESTIONS
=======================================================================

Q1. Which programming languages can be used for QA automation?
----------------------------------------------------------------
The syllabus provides three paths:

    • Java
    • Python
    • JavaScript / TypeScript


Q2. Should a QA Engineer learn all three?
-----------------------------------------
No. The practical approach is to choose a language and develop
strong fundamentals before expanding.


Q3. Why is OOP important in automation?
---------------------------------------
OOP supports reusable and organized automation components.


Q4. Why are collections important?
-----------------------------------
They allow automation code to store and process multiple values,
such as test data and API results.


Q5. Why is exception handling important?
----------------------------------------
It allows automation code to handle unexpected runtime conditions
in a controlled and understandable way.


Q6. Why are modules useful in Python?
-------------------------------------
They allow reusable code to be organized into separate components.


Q7. What are virtual environments?
----------------------------------
They provide isolated Python environments for project dependencies.


Q8. What are Promises?
----------------------
They represent asynchronous operations whose result becomes
available later.


Q9. Why is async/await important?
---------------------------------
It provides a convenient way to work with asynchronous operations,
which are common in modern web automation.


Q10. What is TypeScript?
------------------------
TypeScript is a language built on JavaScript with additional
type-related capabilities.
