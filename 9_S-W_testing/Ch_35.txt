35.1 WHY PROGRAMMING IS IMPORTANT FOR QA
=======================================================================

Manual testing can often be performed without programming.

Automation testing requires programming skills.

Example:

Manual:

    Open login page
         ↓
    Enter username
         ↓
    Enter password
         ↓
    Click Login
         ↓
    Verify dashboard


Automation:

    openLoginPage();
    enterUsername("apoorv");
    enterPassword("password");
    clickLogin();
    verifyDashboard();


Programming allows the tester to convert repetitive test steps into
automated instructions.

35.3 VARIABLES
=======================================================================

A variable stores a value that a program can use.

Example:

    name = "Apoorv"
    age = 25


Conceptually:

    name
      |
      v
    "Apoorv"


    age
      |
      v
     25


In test automation, variables are frequently used for:

    • Usernames
    • Passwords
    • URLs
    • IDs
    • Tokens
    • Expected values
    • Test data


Example:

    username = "apoorv"
    password = "password123"

Automation can then use:

    enterUsername(username)
    enterPassword(password)


=======================================================================
35.4 CONSTANT VS VARIABLE
=======================================================================

A variable generally represents a value that may change.

Example:

    user_id = 101

Later:

    user_id = 102


A constant represents a value intended to remain fixed.

Conceptually:

    BASE_URL = "https://test.example.com"


Whether a language supports constants and how they are declared
depends on the selected programming language.


=======================================================================
35.5 DATA TYPES
=======================================================================

A data type describes the kind of value stored or processed.

Common categories include:

    • Integer
    • Floating-point number
    • String
    • Boolean
    • Character
    • Collections


Example:

    age = 25

    price = 99.50

    name = "Apoorv"

    isLoggedIn = true


Conceptually:

    Integer
       |
       +-- 25

    Float
       |
       +-- 99.50

    String
       |
       +-- "Apoorv"

    Boolean
       |
       +-- true / false


=======================================================================
35.6 INTEGER
=======================================================================

An integer represents a whole number.

Examples:

    0
    1
    10
    101
    -5


QA example:

    expected_status = 200

    user_id = 101

    quantity = 5


=======================================================================
35.7 FLOATING-POINT VALUES
=======================================================================

Floating-point values represent numbers containing a fractional part.

Examples:

    10.5
    99.99
    3.14


QA examples:

    product_price = 999.50

    response_time = 1.25


Care should be taken with decimal comparisons because programming
languages may represent floating-point values with limited precision.


=======================================================================
35.8 STRING
=======================================================================

A string represents text.

Examples:

    "Apoorv"
    "Login successful"
    "POST"
    "https://example.com"


QA uses:

    username = "apoorv"
    expected_message = "Login successful"


Strings are heavily used in:

    • UI automation
    • API testing
    • Test data
    • Logging
    • File processing


=======================================================================
35.9 BOOLEAN
=======================================================================

Boolean values represent two logical states:

    true
    false


Examples:

    isLoggedIn = true

    testPassed = false

    isAdmin = true


Boolean values are extremely important in test automation.

Example:

    if isLoggedIn:
        verifyDashboard()


=======================================================================
35.10 OPERATORS
=======================================================================

Operators are symbols or constructs used to perform operations.

Major categories:

    • Arithmetic operators
    • Comparison operators
    • Logical operators
    • Assignment operators


=======================================================================
35.11 ARITHMETIC OPERATORS
=======================================================================

Common arithmetic operations:

    +    Addition
    -    Subtraction
    *    Multiplication
    /    Division
    %    Remainder


Example:

    quantity = 5
    price = 100

    total = quantity * price


Result:

    total = 500


QA examples:

    total_pages = records / page_size

    remaining = total % page_size


Exact behavior of division and remainder depends on the programming
language and operand types.


=======================================================================
35.12 COMPARISON OPERATORS
=======================================================================

Comparison operators compare values.

Common concepts:

    Equal
    Not equal
    Greater than
    Less than
    Greater than or equal
    Less than or equal


Example:

    actual_status == expected_status


If:

    actual_status = 200
    expected_status = 200


Then:

    actual_status == expected_status

is true.


Comparison operators are fundamental for assertions and conditions.


=======================================================================
35.13 LOGICAL OPERATORS
=======================================================================

Logical operators combine conditions.

Common operations:

    AND
    OR
    NOT


AND:

    condition1 AND condition2

Both conditions must be true.


OR:

    condition1 OR condition2

At least one condition must be true.


NOT:

    NOT condition

Reverses the logical result.


Example:

    isLoggedIn AND isAdmin


This is useful when a test requires multiple conditions to be
satisfied.


=======================================================================
35.14 ASSIGNMENT
=======================================================================

Assignment stores a value in a variable.

Conceptually:

    variable = value


Example:

    status = 200

    username = "Apoorv"


Assignment is different from comparison.

    Assignment:
        status = 200


    Comparison:
        status == 200

The exact syntax depends on the selected programming language.


=======================================================================
35.15 CONDITIONS
=======================================================================

Conditions allow a program to make decisions.

Basic structure:

    IF condition
        perform action
    ELSE
        perform another action


Example:

    if status == 200:
        print("PASS")
    else:
        print("FAIL")


This is extremely common in test automation.


=======================================================================
35.16 IF / ELSE
=======================================================================

Example:

    if login_successful:
        verify_dashboard()
    else:
        report_login_failure()


Flow:

          Condition
              |
          +---+---+
          |       |
        TRUE    FALSE
          |       |
          v       v
       Action   Other
        action


=======================================================================
35.17 ELSE IF
=======================================================================

Multiple conditions can be checked.

Example:

    if status == 200:
        result = "Success"

    else if status == 401:
        result = "Unauthorized"

    else if status == 404:
        result = "Not Found"

    else:
        result = "Other"


This is useful when different values require different actions.


=======================================================================
35.18 NESTED CONDITIONS
=======================================================================

A condition can contain another condition.

Example:

    if user_logged_in:

        if user_is_admin:
            open_admin_panel()
        else:
            open_user_panel()

    else:
        open_login_page()


This allows automation scripts to model more complex behavior.

However, excessive nesting can make code difficult to understand.


=======================================================================
35.19 LOOPS
=======================================================================

A loop repeats a block of code.

Loops are useful when the same operation must be performed multiple
times.

Example:

    Verify 100 users.

Instead of:

    verify user 1
    verify user 2
    verify user 3
    ...
    verify user 100


Use a loop.


Concept:

    Collection
       |
       v
    Loop
       |
       +--> Process item
       |
       +--> Process item
       |
       +--> Process item
       |
       v
      End


=======================================================================
35.20 FOR LOOP
=======================================================================

A for loop is commonly used when iterating over a known sequence or
range.

Conceptual example:

    for each user:
        verify user


Example:

    users = ["A", "B", "C"]

    for user in users:
        print(user)


Output:

    A
    B
    C


QA use cases:

    • Test multiple users
    • Test multiple URLs
    • Test multiple products
    • Validate multiple records
    • Run the same test with multiple data sets


=======================================================================
35.21 WHILE LOOP
=======================================================================

A while loop repeats while a condition remains true.

Concept:

    while condition:
        perform operation


Example:

    count = 1

    while count <= 5:
        print(count)
        count = count + 1


Output:

    1
    2
    3
    4
    5


Important:

    The condition must eventually become false.

Otherwise, the program may continue indefinitely.


=======================================================================
35.22 FOR VS WHILE
=======================================================================

FOR LOOP
--------

Useful when iterating over a known sequence or range.

Example:

    for user in users:
        test(user)


WHILE LOOP
----------

Useful when repetition depends on a condition.

Example:

    while application_is_running:
        monitor()


Simple rule:

    Known collection/range
          → FOR

    Condition-controlled repetition
          → WHILE


=======================================================================
35.23 BREAK
=======================================================================

break terminates a loop early.

Example:

    for user in users:

        if user == "Apoorv":
            break


Once the condition is met, the loop stops.


QA use case:

    Search through test results until a required record is found.


=======================================================================
35.24 CONTINUE
=======================================================================

continue skips the current iteration and proceeds to the next one.

Example:

    for user in users:

        if user is invalid:
            continue

        test(user)


Invalid users are skipped while the loop continues with the remaining
users.


=======================================================================
35.25 FUNCTIONS
=======================================================================

A function is a reusable block of code that performs a specific task.

Example:

    login(username, password)


Instead of repeating:

    enter username
    enter password
    click login


throughout every test, create a reusable function.


Concept:

    Function
       |
       +-- Input
       |
       +-- Processing
       |
       +-- Output


=======================================================================
35.26 FUNCTION PARAMETERS
=======================================================================

Parameters allow a function to receive input.

Example:

    login(username, password)


Here:

    username
    password

are inputs to the function.


Possible calls:

    login("apoorv", "password1")

    login("admin", "password2")


The same function can therefore work with different data.


=======================================================================
35.27 RETURN VALUES
=======================================================================

A function may return a result.

Example:

    result = login(username, password)


The function could return:

    true

or:

    false


Then:

    if result:
        verify_dashboard()
    else:
        report_failure()


Returning values makes functions reusable and easier to compose.


=======================================================================
35.28 WHY FUNCTIONS MATTER IN AUTOMATION
=======================================================================

Without reusable functions:

    Test 1
       → duplicate login code

    Test 2
       → duplicate login code

    Test 3
       → duplicate login code


With functions:

    login()
       ↑
       |
    Test 1
    Test 2
    Test 3


Benefits:

    • Reusability
    • Less duplication
    • Easier maintenance
    • Better readability
    • Easier debugging


=======================================================================
35.29 ARRAYS
=======================================================================

An array is a collection of elements stored together.

Conceptually:

    users = [A, B, C, D]


Positions are commonly accessed using indexes.

Conceptual indexing:

    users[0] → A
    users[1] → B
    users[2] → C
    users[3] → D


The exact indexing and array behavior depends on the programming
language.


=======================================================================
35.30 ARRAY USE IN TESTING
=======================================================================

Arrays can store:

    • Test data
    • Usernames
    • URLs
    • Product IDs
    • Expected results
    • Test cases


Example:

    test_users = [
        "user1",
        "user2",
        "user3"
    ]


Then:

    for user in test_users:
        run_login_test(user)


This avoids writing separate code for every user.


=======================================================================
35.31 STRINGS
=======================================================================

Strings are one of the most frequently used data types in QA
automation.

Common operations include:

    • Concatenation
    • Comparison
    • Searching
    • Splitting
    • Replacing
    • Converting case
    • Extracting portions of text


Example:

    first_name = "Apoorv"
    last_name = "Singh"

    full_name = first_name + " " + last_name


Result:

    "Apoorv Singh"


=======================================================================
35.32 STRING VALIDATION IN TESTING
=======================================================================

Suppose the application displays:

    "Login successful"


Expected:

    "Login successful"


Automation can compare actual and expected text.

Conceptually:

    actual_message
          |
          v
    Compare
          ^
          |
    expected_message


If they match:

    PASS


If they differ:

    FAIL


String validation is common in:

    • UI testing
    • API testing
    • Log validation
    • Error-message validation


=======================================================================
35.33 STRING SEARCH
=======================================================================

Sometimes we do not need exact equality.

Example:

Actual:

    "Welcome Apoorv to the dashboard"


We may only need to verify:

    "Welcome Apoorv"

is present.


Concept:

    Actual text
       |
       v
    Search substring
       |
       +-- Found → PASS
       |
       +-- Not found → FAIL


This is useful when responses contain dynamic values.

35.34 COLLECTIONS
=======================================================================

Collections are data structures used to store groups of values.

Common collection concepts include:

    • List
    • Set
    • Map / Dictionary


Exact names and behavior depend on the programming language.


=======================================================================
35.35 LIST
=======================================================================

A list stores multiple elements in an ordered collection.

Example:

    users = [
        "Apoorv",
        "Rahul",
        "Priya"
    ]


A list is useful when:

    • Order matters
    • Duplicate values may be allowed
    • We need to iterate through items


QA examples:

    test_users
    test_urls
    product_ids
    expected_messages


=======================================================================
35.36 SET
=======================================================================

A set represents a collection where uniqueness is important.

Example:

    roles = {
        "Admin",
        "User",
        "Tester"
    }


If duplicate values are added, the collection generally maintains
unique elements according to the language's set semantics.


QA use:

    Verify that returned IDs are unique.

Concept:

    Response IDs
         |
         v
       Set
         |
         v
    Check uniqueness


=======================================================================
35.37 MAP / DICTIONARY
=======================================================================

A map or dictionary stores key-value pairs.

Example:

    user = {
        "name": "Apoorv",
        "age": 25,
        "role": "Tester"
    }


Access concept:

    key
      |
      v
    value


Example:

    user["name"]

returns:

    "Apoorv"


Dictionaries/maps are extremely useful in API and automation testing.


=======================================================================
35.38 MAP / DICTIONARY IN API TESTING
=======================================================================

API JSON data naturally resembles key-value structures.

Example:

    {
        "id": 101,
        "name": "Apoorv",
        "role": "Tester"
    }


Conceptually:

    id   → 101
    name → Apoorv
    role → Tester


Automation can access individual fields.

Example concept:

    response["id"]

    response["name"]


This makes maps/dictionaries important for API response processing.


=======================================================================
35.39 COLLECTION COMPARISON
=======================================================================

LIST
----

    Ordered collection
    Duplicates may be allowed


SET
---

    Uniqueness-focused collection


MAP / DICTIONARY
----------------

    Key → Value


Example:

    List:
        ["A", "B", "A"]


    Set:
        {"A", "B"}


    Map:
        {
            "name": "Apoorv",
            "role": "Tester"
        }


The exact behavior depends on the chosen language.


=======================================================================
35.40 EXCEPTIONS
=======================================================================

An exception is an abnormal condition that occurs during program
execution.

Examples:

    • Invalid operation
    • Missing file
    • Invalid data
    • Unexpected runtime condition


Without proper handling, an exception may stop program execution.


=======================================================================
35.41 EXCEPTION HANDLING
=======================================================================

Common concepts:

    TRY
      |
      v
    Execute risky operation
      |
      +------ Success ------> Continue
      |
      +------ Exception ----> Handle


Conceptual example:

    try:
        perform_operation()

    catch exception:
        handle_failure()


The exact syntax depends on the programming language.


=======================================================================
35.42 WHY EXCEPTION HANDLING MATTERS IN TESTING
=======================================================================

Automation scripts interact with:

    • Browsers
    • APIs
    • Databases
    • Files
    • External systems


Failures can occur.

Good exception handling can:

    • Prevent uncontrolled crashes
    • Provide useful information
    • Allow appropriate cleanup
    • Make debugging easier


However, exceptions should not simply be hidden.

A test should still clearly report the failure when appropriate.

35.47 PRACTICAL AUTOMATION EXAMPLE
=======================================================================

Suppose we need to test multiple login users.

Test data:

    users = [
        {
            "username": "user1",
            "password": "pass1"
        },
        {
            "username": "user2",
            "password": "pass2"
        }
    ]


Conceptual automation:

    for user in users:

        result = login(
            user["username"],
            user["password"]
        )

        if result:
            print("PASS")
        else:
            print("FAIL")


This small example uses:

    • Collections
    • Loops
    • Functions
    • Variables
    • Conditions
    • Strings
    • Boolean result


This is the type of programming foundation required for automation.

35.49 INTERVIEW QUESTIONS
=======================================================================

Q1. Why does a QA Engineer need programming?
---------------------------------------------
Programming is required to create and maintain automation scripts,
process test data, implement reusable logic, and work with automation
frameworks.


Q2. What is a variable?
-----------------------
A variable stores a value that can be used by a program.


Q3. What are common data types?
--------------------------------
Examples include:

    Integer
    Floating-point
    String
    Boolean
    Collections


Q4. What is the difference between = and ==?
---------------------------------------------
Conceptually:

    =  → assignment

    == → comparison


Exact syntax can vary by language.


Q5. What is a loop?
-------------------
A loop repeatedly executes code while its iteration condition is
satisfied.


Q6. FOR vs WHILE?
-----------------
FOR is commonly used for iterating over a sequence/range.

WHILE is commonly used when repetition depends on a condition.


Q7. What is a function?
-----------------------
A reusable block of code that performs a specific task.


Q8. Why are functions useful in automation?
--------------------------------------------
They reduce duplication, improve reuse, readability, and
maintainability.


Q9. What is a collection?
-------------------------
A data structure used to store multiple values.


Q10. What is a dictionary/map?
------------------------------
A collection of key-value pairs.


Q11. What is exception handling?
--------------------------------
It is the mechanism used to handle abnormal runtime conditions
without uncontrolled program failure.


Q12. Why are files useful in test automation?
----------------------------------------------
Files can store test data, configuration, logs, and results.
