====================================================================
38.1 WHAT IS SELENIUM?
====================================================================

Selenium is a toolset used for automating web browsers.

It allows an automation program to interact with a web application
similar to how a user interacts with it.

Example:

    Human User
        ↓
    Open Chrome
        ↓
    Open website
        ↓
    Enter username
        ↓
    Enter password
        ↓
    Click Login
        ↓
    Verify dashboard


Using Selenium:

    Automation Code
        ↓
    Selenium WebDriver
        ↓
    Browser
        ↓
    Web Application


IMPORTANT:

Selenium is primarily used for WEB APPLICATION automation.

It is not the same thing as:

    Unit Testing
    Database Testing
    Performance Testing

Selenium's major role in this chapter is browser-based
web automation.


====================================================================
38.2 WHY SELENIUM?
====================================================================

Manual execution of repetitive browser tests can take significant
time.

Example:

    Login
    Search
    Add product
    Checkout
    Logout

If the same workflow must be executed for many releases,
automation becomes valuable.

Selenium allows us to automate browser interactions such as:

    Open web page
    Find elements
    Enter text
    Click elements
    Select options
    Handle browser windows
    Handle frames
    Handle alerts
    Perform mouse/keyboard actions
    Capture screenshots


====================================================================
38.3 SELENIUM WEBDRIVER
====================================================================

WebDriver is the core Selenium component used to control a browser.

Conceptually:

    Automation Program
           ↓
       WebDriver
           ↓
        Browser
           ↓
    Web Application


Example:

    Test Script
       |
       | command
       ↓
    WebDriver
       |
       | browser interaction
       ↓
    Chrome / Firefox / Edge / etc.
       |
       ↓
    Website


A test script should not directly manipulate the browser.

The automation flow is conceptually:

    Test Code
       ↓
    Selenium WebDriver
       ↓
    Browser
       ↓
    Application


====================================================================
38.4 BASIC SELENIUM WORKFLOW
====================================================================

A typical Selenium test follows this pattern:

    1. Start browser
    2. Open application
    3. Locate element
    4. Perform action
    5. Validate result
    6. Capture evidence if needed
    7. End browser session


Example:

    Open Login Page
          ↓
    Find Username
          ↓
    Enter Username
          ↓
    Find Password
          ↓
    Enter Password
          ↓
    Find Login Button
          ↓
    Click
          ↓
    Verify Dashboard


This basic pattern is fundamental to Selenium automation.


====================================================================
38.5 WEB ELEMENTS
====================================================================

A web element is an element present on a web page that Selenium
can interact with.

Examples:

    <input>
    <button>
    <a>
    <select>
    <textarea>
    <checkbox>
    <radio button>


Example HTML:

    <input id="username" type="text">


Selenium needs a way to identify this element.

That identification is done using LOCATORS.


====================================================================
38.6 WHAT IS A LOCATOR?
====================================================================

A locator is a mechanism used to identify a web element.

Suppose the page contains:

    <input id="username">


Selenium can locate it using its ID.

Common Selenium locator strategies covered in this chapter:

    1. ID
    2. Name
    3. Class
    4. Tag
    5. Link Text
    6. CSS Selector
    7. XPath


Conceptually:

    HTML Element
         ↓
    Locator
         ↓
    Selenium finds element
         ↓
    Perform action


====================================================================
38.7 LOCATOR — ID
====================================================================

Example:

    <input id="username">


Locator:

    ID = username


ID is commonly useful when the application provides a stable,
unique ID.


Concept:

    HTML
      ↓
    id="username"
      ↓
    Selenium identifies element


GOOD:

    Unique
    Simple
    Readable


Potential problem:

    Dynamically generated IDs may change between executions.


Example:

    username_123
    username_456
    username_789

If the ID changes dynamically, relying directly on it can make
automation unstable.


====================================================================
38.8 LOCATOR — NAME
====================================================================

Example:

    <input name="username">


Locator:

    name = username


The name attribute can be used when it is available and suitable
for identifying the element.


Example:

    <input
        name="username"
        type="text"
    >


Selenium can use the element's name to locate it.


====================================================================
38.9 LOCATOR — CLASS
====================================================================

Example:

    <button class="login-button">
        Login
    </button>


The class attribute can be used as a locator.


However, be careful.

Classes may be:

    Shared by many elements
    Dynamically generated
    Changed by UI frameworks


Example:

    <button class="btn primary login-button">


A class may not always uniquely identify the desired element.


Therefore:

    Unique/stable locator
          ↓
    Generally preferable


====================================================================
38.10 LOCATOR — TAG NAME
====================================================================

A tag name identifies the HTML tag.

Examples:

    input
    button
    a
    div
    table


Example:

    <button>Login</button>


Tag:

    button


Potential problem:

A page may contain many buttons.

Therefore:

    Tag = button

may identify multiple elements.

Tag locators are useful when the element type itself is sufficient
or when combined with another locator strategy.


====================================================================
38.11 LOCATOR — LINK TEXT
====================================================================

Used for links when the visible link text identifies the desired
link.

Example:

    <a href="/login">Login</a>


Visible text:

    Login


Locator concept:

    Link Text = Login


This can be useful when link text is unique and stable.


Potential problem:

If the visible text changes:

    Login

to:

    Sign In

the locator may need to change.


====================================================================
38.12 LOCATOR — CSS SELECTOR
====================================================================

CSS selectors provide a powerful way to identify elements using
CSS-style patterns.


Example HTML:

    <input id="username">


CSS selector:

    #username


Example:

    <button class="login-button">


CSS selector:

    .login-button


CSS can also combine attributes and relationships.


Concept:

    HTML
      ↓
    CSS Selector
      ↓
    Target Element


CSS selectors are commonly used because they can be concise and
powerful.


====================================================================
38.13 LOCATOR — XPATH
====================================================================

XPath is another powerful mechanism for locating elements in an
HTML/XML document.

Example:

    <input id="username">


XPath:

    //input[@id='username']


Another example:

    <button>Login</button>


XPath can use element properties and relationships to identify
elements.


Concept:

    HTML DOM
       ↓
    XPath expression
       ↓
    Target element


XPath becomes particularly useful when a simple locator such as
ID or name is unavailable.


====================================================================
38.14 CSS vs XPATH — BASIC IDEA
====================================================================

Both can identify web elements.

Example:

    HTML:

    <input id="username">


CSS:

    #username


XPath:

    //input[@id='username']


General comparison:

    CSS
      ↓
    Concise
    Powerful
    Commonly used


    XPath
      ↓
    Powerful
    Can express relationships
    Useful for complex element identification


The important skill is not memorizing syntax alone.

The important skill is selecting a stable locator.


====================================================================
38.15 LOCATOR PRIORITY MINDSET
====================================================================

When identifying an element, prefer a locator that is:

    Unique
       +
    Stable
       +
    Readable
       +
    Maintainable


Example:

    BEST CASE
        ↓
    Stable unique ID


If that is unavailable:

    Stable attribute
        ↓
    CSS
        ↓
    XPath
        ↓
    Other suitable locator


Do not blindly use one locator type for every element.

Choose based on the actual application.


====================================================================
38.16 FINDING ELEMENTS
====================================================================

Once a locator identifies an element, Selenium can interact with it.

Concept:

    Locator
       ↓
    Find Element
       ↓
    Web Element
       ↓
    Action


Examples of actions:

    click()
    enter text
    select
    read text
    inspect state


The exact API syntax depends on the programming language being
used.


====================================================================
38.17 TEXT INPUT
====================================================================

Typical login flow:

    Username field
         ↓
    Enter username

    Password field
         ↓
    Enter password


Conceptually:

    find username
          ↓
    type username

    find password
          ↓
    type password


This is one of the most basic Selenium operations.


====================================================================
38.18 CLICKING ELEMENTS
====================================================================

Buttons, links, checkboxes and other clickable elements can be
interacted with through Selenium.

Example:

    Find Login button
          ↓
    Click
          ↓
    Application processes request


Typical automation:

    Locate
       ↓
    Click
       ↓
    Validate result


Example:

    Login
      ↓
    Dashboard should appear


====================================================================
38.19 DROPDOWNS
====================================================================

Web applications frequently contain dropdown controls.

Example:

    Country:

    +------------------+
    | India          ▼ |
    +------------------+

Possible options:

    India
    USA
    UK
    Canada


Automation should:

    1. Locate dropdown
    2. Select appropriate option
    3. Verify selected value


Dropdown handling is a common browser automation requirement.


====================================================================
38.20 CHECKBOXES
====================================================================

Example:

    ☑ Accept Terms

Selenium can interact with checkbox elements.

Typical scenarios:

    Check checkbox
    Uncheck checkbox
    Verify checked state


Example test:

    Given:
        Terms checkbox is unchecked

    Action:
        Select checkbox

    Expected:
        Checkbox becomes selected


====================================================================
38.21 RADIO BUTTONS
====================================================================

Radio buttons generally allow selection among related options.

Example:

    Gender:

    ( ) Male
    ( ) Female
    ( ) Other


Automation can:

    Locate radio button
    Select it
    Verify selected state


Test objective:

    Only the expected option should be selected.


====================================================================
38.22 ALERTS
====================================================================

A browser alert is a browser-level dialog.

Example:

    +---------------------------+
    | Delete this item?         |
    |                           |
    |     OK       Cancel       |
    +---------------------------+


Automation may need to:

    Accept
    Dismiss
    Read alert text
    Interact appropriately


Typical flow:

    Action
      ↓
    Alert appears
      ↓
    Switch/handle alert
      ↓
    Accept or dismiss
      ↓
    Continue test


Important:

An alert is not necessarily a normal HTML element on the page.


====================================================================
38.23 FRAMES / IFRAMES
====================================================================

Some web pages contain content inside frames.

Concept:

    Main Page
       |
       +-----------------------+
       |       iframe          |
       |                       |
       |  Username             |
       |  Password             |
       |                       |
       +-----------------------+


An element inside an iframe may not be directly accessible from
the main document context.

Automation may need to switch into the frame before interacting
with its elements.


Conceptual flow:

    Main Page
       ↓
    Switch to Frame
       ↓
    Find Element
       ↓
    Perform Action


After completing work inside the frame, automation may need to
return to the main document context.


====================================================================
38.24 WINDOWS / TABS
====================================================================

Modern applications may open links in:

    New window
    New browser tab


Example:

    Main Tab
       ↓
    Click link
       ↓
    New Tab
       ↓
    Perform test


Automation needs to identify the correct browser window/tab before
interacting with elements in it.


Concept:

    Window/Tab A
          ↓
    Click
          ↓
    Window/Tab B
          ↓
    Switch
          ↓
    Test


====================================================================
38.25 MOUSE ACTIONS
====================================================================

Web applications may require mouse interactions such as:

    Click
    Double click
    Right click
    Hover
    Drag and drop


Example:

    Menu
      ↓
    Hover
      ↓
    Submenu appears
      ↓
    Click submenu


Such interactions can be automated using Selenium's action
capabilities.


====================================================================
38.26 KEYBOARD ACTIONS
====================================================================

Keyboard interactions can also be required.

Examples:

    Enter
    Tab
    Escape
    Arrow keys
    Control
    Shift


Example:

    Search box
       ↓
    Enter search term
       ↓
    Press Enter
       ↓
    Search results


Automation can reproduce appropriate keyboard interactions.


====================================================================
38.27 JAVASCRIPT EXECUTOR
====================================================================

Sometimes browser automation may require JavaScript execution.

Conceptually:

    Selenium
       ↓
    JavaScript Executor
       ↓
    Browser Page


Possible uses include interacting with the page through JavaScript
when appropriate.


However:

    Do not use JavaScript automatically for every action.

Prefer normal Selenium interaction when it correctly represents
the intended user action.

JavaScript should be used when there is a legitimate automation
need.


====================================================================
38.28 SCREENSHOTS
====================================================================

Screenshots provide visual evidence of test execution.

Example:

    Test Failure
         ↓
    Capture Screenshot
         ↓
    Attach to Report
         ↓
    Analyze Failure


Useful situations:

    Successful critical step
    Test failure
    Unexpected UI
    Debugging
    Defect evidence


A screenshot can help answer:

    "What did the application look like
     when the test failed?"

38.30 SELENIUM TESTING MINDSET
====================================================================

A beginner thinks:

    "How do I click this button?"


A QA engineer thinks:

    "What behavior am I testing?"


A good automation engineer thinks:

    "What is the most reliable way to locate this element,
     perform the action, and verify the expected behavior?"


Therefore Selenium is not just about:

    click()
    send keys
    find element


It is about creating reliable automated tests.

38.31 COMMON SELENIUM PROBLEMS
====================================================================

PROBLEM 1
---------

Element cannot be found.

Possible concern:

    Locator is incorrect
    OR
    Element is not available in the expected context


PROBLEM 2
---------

Locator changes.

Example:

    Old ID → username123
    New ID → username456


Automation may need a more stable locator.


PROBLEM 3
---------

Element is inside an iframe.

Solution concept:

    Switch to frame
        ↓
    Interact with element


PROBLEM 4
---------

Element is in another window/tab.

Solution concept:

    Identify window
        ↓
    Switch to correct window


PROBLEM 5
---------

Alert appears.

Solution concept:

    Handle alert
        ↓
    Continue


PROBLEM 6
---------

UI requires complex mouse interaction.

Solution:

    Use appropriate mouse/action capability.

38.32 SELENIUM AUTOMATION ARCHITECTURE
====================================================================

A simplified architecture:

    +--------------------------------+
    |       Test Automation Code     |
    +--------------------------------+
                  |
                  ↓
    +--------------------------------+
    |        Selenium WebDriver      |
    +--------------------------------+
                  |
                  ↓
    +--------------------------------+
    |          Web Browser           |
    +--------------------------------+
                  |
                  ↓
    +--------------------------------+
    |       Web Application          |
    +--------------------------------+


Test code defines:

    WHAT should be tested


WebDriver provides:

    HOW to communicate with browser


Browser performs:

    Actual browser interaction


Application provides:

    Actual system behavior

38.33 INTERVIEW QUESTIONS
====================================================================

Q1. What is Selenium?
----------------------

Selenium is a toolset used for automating web browsers.


Q2. What is Selenium WebDriver?
--------------------------------

WebDriver is the Selenium component used to control and interact
with web browsers programmatically.


Q3. What is a locator?
----------------------

A locator is a mechanism used to identify a web element.


Q4. What locator types are covered in Selenium?
------------------------------------------------

    ID
    Name
    Class
    Tag Name
    Link Text
    CSS Selector
    XPath


Q5. What is XPath?
------------------

XPath is a mechanism for identifying elements in an HTML/XML
document using expressions based on element properties and
relationships.


Q6. What is CSS Selector?
--------------------------

A CSS selector identifies elements using CSS-style selector
patterns.


Q7. Why are stable locators important?
---------------------------------------

Because unstable locators can make automation tests fragile and
increase maintenance.


Q8. How do you automate a login test?
--------------------------------------

Conceptually:

    Open login page
        ↓
    Locate username
        ↓
    Enter username
        ↓
    Locate password
        ↓
    Enter password
        ↓
    Click Login
        ↓
    Verify dashboard


Q9. What is an iframe?
----------------------

An iframe is a frame containing another document/page context
inside a web page. Automation may need to switch into the frame
before interacting with its elements.


Q10. Why are screenshots useful?
---------------------------------

They provide visual evidence for execution, debugging, and
failures.

38.36 CHAPTER 38 FINAL TAKEAWAY
====================================================================

Selenium automation fundamentally follows:

        TEST
         ↓
      LOCATE
         ↓
       ACT
         ↓
     VALIDATE
         ↓
      REPORT


The most important Selenium concepts to master first are:

    1. WebDriver
    2. Web Elements
    3. Locators
    4. CSS Selectors
    5. XPath
    6. Browser interactions
