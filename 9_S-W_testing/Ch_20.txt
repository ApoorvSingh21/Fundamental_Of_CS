1. WHAT IS JIRA?
====================================================================

Jira is a project and issue-tracking tool commonly used by software
teams to manage:

    - Software development work
    - Bugs
    - Tasks
    - Stories
    - Sprints
    - Backlogs
    - Workflows
    - Project tracking


For a QA Engineer, Jira is especially useful for:

    Bug reporting
    Bug tracking
    Defect lifecycle management
    Test-related task tracking
    Sprint-based testing
    Issue filtering
    QA status reporting


Simple idea:

    Requirement
         ↓
    Development
         ↓
    Testing
         ↓
    Defect found
         ↓
       Jira
         ↓
    Developer fixes
         ↓
    QA retests
         ↓
    Defect closed

2. JIRA IN SOFTWARE TESTING

    1. Create defects

    5. Add labels

    7. Link issues
    8. Track sprint work
    9. Search defects
    10. Create filters
    11. Monitor dashboards
    12. Communicate defect progress

    QA finds login defect.

        ↓

    Create Jira Bug

        ↓

    Developer receives issue

        ↓

    Developer fixes defect

        ↓

    QA retests

        ↓

    Jira status updated

        ↓

3. JIRA PROJECT
====================================================================

A Jira project is a workspace for organizing related work.

Example:

    Project:
        E-Commerce Application


The project may contain:

    Stories
    Tasks
    Bugs
    Sprints
    Components
    Reports


Example project:

    ECOM


Possible issues:

    ECOM-101
    ECOM-102
    ECOM-103


The project key is commonly included in the issue identifier.


====================================================================
4. JIRA ISSUE
====================================================================

An issue represents a unit of work or a tracked item.

Common issue types include:

    Bug
    Story
    Task
    Epic


For QA, the most important issue type is often:

    BUG


Example:

    ECOM-101

    Type:
        Bug

    Summary:
        Checkout fails when valid coupon is applied.


====================================================================
5. BUG ISSUE
====================================================================

A Bug issue represents a software defect that needs to be tracked.

Example:

    Project:
        E-Commerce

    Issue Type:
        Bug

    Summary:
        Payment fails for valid card


The issue can contain:

    Description
    Environment
    Steps
    Expected result
    Actual result
    Priority
    Assignee
    Labels
    Components
    Attachments
    Status


====================================================================
6. CREATING A BUG IN JIRA
====================================================================

Typical process:

    1. Open Jira project.
    2. Select Create issue.
    3. Select Issue Type = Bug.
    4. Enter summary.
    5. Enter description.
    6. Add environment.
    7. Add reproduction steps.
    8. Add expected result.
    9. Add actual result.
    10. Select priority.
    11. Add labels/components if required.
    12. Add attachments.
    13. Assign the issue if appropriate.
    14. Create the issue.


The exact Jira interface can vary by Jira version and project
configuration.


====================================================================
7. JIRA BUG EXAMPLE
====================================================================

PROJECT:
    E-Commerce

ISSUE TYPE:
    Bug

SUMMARY:
    Coupon is applied below the minimum order amount

DESCRIPTION:

    Preconditions:
        Valid coupon exists.

    Steps:
        1. Add products worth ₹999.
        2. Open cart.
        3. Enter valid coupon.
        4. Click Apply.

    Expected:
        Coupon should not be applied because minimum order amount is
        ₹1000.

    Actual:
        Coupon is applied successfully.

ENVIRONMENT:
    Chrome / Windows / QA

PRIORITY:
    High

LABEL:
    checkout

COMPONENT:
    Cart/Checkout

8. BUG ASSIGNMENT
====================================================================

After creating a bug, it may be assigned to the appropriate person
according to the project's workflow.

Example:

    QA
     ↓
    Creates BUG-101
     ↓
    Assigns to Developer A
     ↓
    Developer investigates


Assignment provides ownership.

However, exact assignment rules vary by organization.

Some teams may use:

    Developer assignment
    Component ownership
    Team queues
    Triage before assignment


====================================================================
9. JIRA STATUS
====================================================================

Status represents the current state of an issue.

A project may have statuses such as:

    To Do
    Open
    In Progress
    Resolved
    Reopened
    Closed


For QA defect workflows, a simplified flow may be:

    NEW
      ↓
    ASSIGNED
      ↓
    OPEN
      ↓
    FIXED
      ↓
    RETEST
      ↓
    CLOSED


Actual Jira workflows depend on project configuration.


====================================================================
10. STATUS TRANSITIONS
====================================================================

A transition moves an issue from one status to another.

Example:

    OPEN
      ↓
    IN PROGRESS


Then:

    IN PROGRESS
      ↓
    RESOLVED


Then:

    RESOLVED
      ↓
    RETEST


Then:

    RETEST
      ↓
    CLOSED


If the defect still exists:

    RETEST
      ↓
    REOPENED

Examples:

    regression
    smoke
    checkout
    payment
    login
    mobile

    api

Example:

    BUG-101

    Labels:

====================================================================
12. COMPONENTS
====================================================================

Components can be used to organize issues according to application
areas or modules.

Example e-commerce application:

    Login
    Product
    Cart
    Checkout
    Payment
    Order
    Notification


Example:

    BUG-101

    Component:
        Payment


This helps teams identify which area of the application is affected.


====================================================================
13. LABELS VS COMPONENTS
====================================================================

LABEL:

    Flexible tag used for categorization.

Example:

    regression


COMPONENT:

    Usually represents an application/project area or module.

Example:

    Payment


Simple distinction:

    Label → Tag

    Component → Application/module area


The exact behavior depends on the Jira project configuration.


====================================================================
14. PRIORITY IN JIRA
====================================================================

Priority helps communicate the urgency of an issue.

Examples commonly include:

    Highest
    High
    Medium
    Low
    Lowest


However, the actual priority options depend on the project's Jira
configuration.

Example:

    Payment failure:

        Priority = Highest/High


    Minor UI issue:

        Priority = Low


Do not assume every Jira project uses the same priority names.


====================================================================
15. SPRINT
====================================================================

A Sprint is a time-boxed period in Agile/Scrum during which the team
works on selected work.

Example:

    Sprint 21
    Duration:
        2 weeks


Sprint may contain:

    Stories
    Tasks
    Bugs


QA activities can include:

    Test planning
    Test execution
    Bug reporting
    Retesting
    Regression testing


====================================================================
16. BUGS IN A SPRINT
====================================================================

Suppose Sprint 21 contains:

    Story:
        User Login

QA tests the story.

QA discovers:

    Login fails with valid credentials.

A bug can be created and associated with the relevant work/sprint
according to the team's process.

Example:

    Story:
        ECOM-50

    Bug:
        ECOM-75


This helps maintain traceability.


====================================================================
17. BACKLOG
====================================================================

A backlog is a prioritized collection of work items.

It may contain:

    Stories
    Bugs
    Tasks
    Epics
    Other work items


Example:

    Product Backlog

    1. Login enhancement
    2. Payment integration
    3. Checkout bug
    4. Search improvement
    5. Mobile UI task


The team prioritizes and selects appropriate work for upcoming
sprints.


====================================================================
18. SPRINT BACKLOG
====================================================================

Sprint backlog contains work selected for the current sprint.

Example:

    Sprint 21

    - Login feature
    - Checkout feature
    - Payment bug
    - Regression testing task


QA can use the sprint backlog to understand the work that needs
testing during the sprint.


====================================================================
19. BACKLOG VS SPRINT BACKLOG
====================================================================

BACKLOG:

    Larger collection of planned work.

SPRINT BACKLOG:

    Work selected for a specific sprint.


Simple:

    Product Backlog
          ↓
    Select work
          ↓
    Sprint Backlog

20. JQL — JIRA QUERY LANGUAGE
====================================================================

JQL stands for:

    Jira Query Language


It is used to search and filter Jira issues using queries.

Example:

    project = ECOM


This can return issues belonging to the ECOM project.


====================================================================
21. BASIC JQL
====================================================================

Example:

    project = ECOM


Meaning:

    Find issues in project ECOM.


Example:

    project = ECOM AND priority = High


Meaning:

    Find ECOM issues with High priority.


Example:

    project = ECOM AND status = Open


Meaning:

    Find ECOM issues currently having Open status.


====================================================================
22. JQL — BUG SEARCH
====================================================================

Example:

    project = ECOM AND issuetype = Bug


Meaning:

    Find all bugs in ECOM.


Example:

    project = ECOM
    AND issuetype = Bug
    AND priority = High


Meaning:

    Find high-priority bugs in ECOM.


====================================================================
23. JQL — ASSIGNEE
====================================================================

Example:

    project = ECOM AND assignee = "DeveloperName"


This searches issues assigned to a particular user.

Actual user identifiers depend on Jira configuration.


====================================================================
24. JQL — LABEL
====================================================================

Example:

    project = ECOM AND labels = regression


This searches issues containing the regression label.


====================================================================
25. JQL — COMPONENT
====================================================================

Example:

    project = ECOM AND component = Payment


This searches issues associated with the Payment component.


====================================================================
26. JQL — COMBINING CONDITIONS
====================================================================

Example:

    project = ECOM
    AND issuetype = Bug
    AND priority = High
    AND status = Open


Meaning:

    Find open, high-priority bugs in the ECOM project.


Another:

    project = ECOM
    AND issuetype = Bug
    AND labels = regression


Meaning:

    Find regression-related bugs in ECOM.


====================================================================
27. JQL — ORDERING
====================================================================

JQL can also be used with ordering.

Example:

    project = ECOM
    AND issuetype = Bug
    ORDER BY priority DESC


This requests bugs ordered by priority in descending order.

Exact field values and permissions depend on the Jira instance.


====================================================================
28. JQL — PRACTICAL QA QUERIES
====================================================================

Find all bugs:

    project = ECOM AND issuetype = Bug


Find high-priority bugs:

    project = ECOM
    AND issuetype = Bug
    AND priority = High


Find open bugs:

    project = ECOM

====================================================================
29. IMPORTANT JQL NOTE
====================================================================

JQL syntax and available fields depend on the Jira configuration.

For example:

    Status names
    Priority names
    Components
    Custom fields
    Issue types

Therefore, always use the actual values configured in your Jira

====================================================================
30. FILTERS
====================================================================

A filter is a saved search.

Example:

    "My Open Bugs"


Query:

    project = ECOM
    AND issuetype = Bug
    AND assignee = currentUser()
    AND status != Closed


The filter can be saved and reused.

Useful QA filters:

    My Open Bugs
    High Priority Bugs
    Regression Bugs
    Payment Bugs
    Bugs in Current Sprint
    Reopened Bugs


====================================================================
31. WHY FILTERS ARE USEFUL
====================================================================

Without filters:

    Search manually every time.

With filters:

    Save useful queries once
        ↓
    Reuse them later


This improves productivity.

38. PRACTICAL JIRA BUG CREATION
====================================================================

Suppose you find:

    "Payment fails after entering valid card information."


Create:

    Issue Type:
        Bug

    Summary:
        Payment fails with valid card information

    Description:

        Preconditions:
            User is logged in.
            Product is in cart.

        Steps:
            1. Open checkout.
            2. Select payment method.
            3. Enter valid card details.
            4. Click Pay.

        Expected:
            Payment should complete successfully.

        Actual:
            Payment fails with an error.

    Environment:
        QA / Chrome / Windows

    Severity:
        High

    Priority:
        High

    Component:
        Payment

    Labels:
        payment
        regression

44. JIRA FOR BLOCKED TESTING
====================================================================

47. COMMON JIRA MISTAKES
====================================================================

MISTAKE 1:

    Creating vague bug descriptions.

SOLUTION:

    Use professional bug-report structure.


MISTAKE 2:

    Forgetting environment.

SOLUTION:

    Include browser, OS, build, and relevant device/environment.


MISTAKE 3:

    Using inconsistent labels.

SOLUTION:

    Follow project naming conventions.


MISTAKE 4:

    Not updating defect status after retesting.

SOLUTION:

    Keep issue state synchronized with actual testing progress.


MISTAKE 5:

    Closing a bug without verification.

SOLUTION:

    Retest the fix according to the project process.


MISTAKE 6:

    Creating duplicate bugs.

SOLUTION:

    Search existing issues when required.


MISTAKE 7:

    Sharing sensitive information.

SOLUTION:

    Sanitize screenshots, logs, and test data.

48. INTERVIEW QUESTIONS
====================================================================

Q1. What is Jira?

Answer:

Jira is a project and issue-tracking tool used by software teams to
manage work items, defects, Agile workflows, and project progress.


Q2. How is Jira useful for QA?

Answer:

QA can use Jira to create and track bugs, manage issue status,
communicate with developers, track sprint work, search defects, and
monitor testing-related work.


Q3. What is a Jira issue?

Answer:

A Jira issue is a trackable work item such as a bug, story, task, or
other configured issue type.


Q4. What is JQL?

Answer:

JQL stands for Jira Query Language and is used to search and filter
Jira issues.


Q5. What is a Jira filter?

Answer:

A filter is a saved search that can be reused to quickly find
relevant issues.


Q6. What is a sprint?

Answer:

A sprint is a time-boxed Agile work period during which selected work
is completed.


Q7. What is a backlog?

Answer:

A backlog is a collection of planned work items that can be
prioritized and selected for future work.


Q8. What are labels?

Answer:

Labels are tags used to categorize and search issues.


Q9. What are components?

Answer:

Components can organize issues around application or project areas,
such as Login, Payment, or Checkout.


Q10. What is a Jira dashboard?

Answer:

A dashboard provides a visual summary of project information such
as issues, statuses, and other tracked metrics.

50. SCENARIO-BASED QUESTIONS
====================================================================

SCENARIO 1
----------

You find a critical checkout defect.

What should you do in Jira?

Answer:

    1. Create a bug.
    2. Write a clear title.
    3. Add reproduction steps.
    4. Add expected/actual results.
    5. Add environment.
    6. Set severity/priority according to project rules.
    7. Add evidence.
    8. Assign/route according to workflow.
    9. Track the issue through resolution.


--------------------------------------------------------------------
SCENARIO 2
----------

Developer fixes a bug.

What should QA do?

Answer:

    Retest the defect using the appropriate test conditions.

If successful:

    Update the issue according to the team's closure workflow.

If unsuccessful:

    Reopen the issue and document the result.


--------------------------------------------------------------------
SCENARIO 3
----------

You need to find all high-priority bugs in the current project.

What can you use?

Answer:

    JQL/filter.


Example:

    project = ECOM
    AND issuetype = Bug
    AND priority = High


--------------------------------------------------------------------
SCENARIO 4
----------

You need to repeatedly monitor reopened bugs.

What can you create?

Answer:

    A saved Jira filter.

For example:

    project = ECOM
    AND issuetype = Bug
    AND status = Reopened


--------------------------------------------------------------------
SCENARIO 5
----------

A bug already exists for the same issue.

What should you do?

Answer:

    Follow the team's duplicate-defect process instead of creating
    unnecessary duplicate tracking.
