1.1 WHAT IS SOFTWARE?
====================================================================

Software is a collection of programs, instructions, data, and
related components that tell a computer how to perform specific
tasks.

Simple definition:

    Software = Instructions + Programs + Data

Examples:

    Windows
    Linux
    Chrome
    WhatsApp
    Instagram
    Microsoft Word
    Banking Applications
    E-commerce Websites


Example:

    When you open a calculator application and enter:

        10 + 20

    The software processes the input and produces:

        30

The tester's responsibility is to verify that the software behaves
as expected.

====================================================================
1.3 TYPES OF SOFTWARE
====================================================================

Major categories:

    1. System Software
    2. Application Software
    3. Programming Software
    4. Embedded Software


--------------------------------------------------------------------
1.3.1 SYSTEM SOFTWARE
--------------------------------------------------------------------

System software manages computer hardware and provides a platform
for application software.

Examples:

    Windows
    Linux
    macOS
    Android
    iOS
    Device Drivers
    Firmware

Main responsibilities:

    Hardware Management
    Memory Management
    Process Management
    File Management
    Security
    Providing services to applications


Example:

    You open Chrome.

    Chrome needs the operating system to:

        Access RAM
        Access CPU
        Access network
        Access storage
        Display graphics


TESTER POINT:

    System software can affect application behavior.

    Example:

        Application works correctly on Windows
        but crashes on a particular Linux environment.

    This can become a compatibility/environment testing issue.


--------------------------------------------------------------------
1.3.2 APPLICATION SOFTWARE
--------------------------------------------------------------------

Application software is designed to perform tasks for users.

Examples:

    MS Word
    Excel
    Chrome
    WhatsApp
    Banking Applications
    E-commerce Applications
    Hospital Management Systems
    Railway Reservation Systems


Application software can be:

    Web Application
    Mobile Application
    Desktop Application


--------------------------------------------------------------------
1.3.3 PROGRAMMING SOFTWARE
--------------------------------------------------------------------

These tools are used by developers to create software.

Examples:

    Visual Studio Code
    IntelliJ IDEA
    Eclipse
    GCC
    Git
    Debuggers
    Compilers


Tester relevance:

        Build tools
        Source code
        Logs
        Debuggers
        Version control systems
        CI/CD systems


--------------------------------------------------------------------
1.3.4 EMBEDDED SOFTWARE
--------------------------------------------------------------------

Embedded software runs inside hardware devices.

Examples:

    Washing Machine

Example:

         |

====================================================================
1.7 CLIENT-SERVER ARCHITECTURE
====================================================================

Client-server architecture divides an application into clients
and servers.

CLIENT:

    Requests services/data.

SERVER:

    Processes requests and provides services/data.


Simple architecture:

             CLIENT
                |
                | Request
                v
             SERVER
                |
                | Query
                v
             DATABASE


Example:

    User logs into an application.

    Step 1:
        User enters username and password.

    Step 2:
        Frontend sends login request.

    Step 3:
        Backend receives request.

    Step 4:
        Backend checks database.

    Step 5:
        Database returns user information.

    Step 6:
        Backend validates credentials.

    Step 7:
        Server sends response.

    Step 8:
        Frontend displays:

            "Login Successful"


TESTER RESPONSIBILITY:

    Test every important layer.

    UI
     ↓
    API
     ↓
    Backend
     ↓
    Database

====================================================================
1.9 BACKEND
====================================================================

Backend is the server-side part of an application.

It handles:

    Business Logic
    Authentication
    Authorization
    Data Processing
    Database Communication
    API Requests
    Security Rules


Common backend technologies:

    Java
    Python
    C#
    JavaScript/Node.js
    PHP
    Go


Example:

    Shopping application:

    User requests:

        "Buy product ID 101"

    Backend checks:

        Is user logged in?
        Is product available?
        What is the price?
        Is inventory available?
        Is payment successful?

    Then backend creates the order.


TESTER SHOULD VERIFY:

    ✓ Correct business rules
    ✓ Correct calculations
    ✓ Error handling
    ✓ API responses
    ✓ Database updates
    ✓ Authentication
    ✓ Authorization

1.10 FRONTEND VS BACKEND
====================================================================

+----------------+----------------------------+
| Frontend       | Backend                    |
+----------------+----------------------------+
| User-facing    | Server-side                |
| UI             | Business logic             |
| Browser        | Server                     |
| HTML/CSS/JS    | Java/Python/etc.           |
| Forms          | Processing                |
| Buttons        | Database operations        |
+----------------+----------------------------+


Example:

    Frontend:

        [ LOGIN ]

    Backend:

        Validate username/password

    Database:

        Store user information

1.11 DATABASE
====================================================================

A database is an organized collection of data.

Example:

    USER TABLE

    +----+----------+----------------+
    | ID | Name     | Email          |
    +----+----------+----------------+
    | 1  | Rahul    | r@email.com    |
    | 2  | Amit     | a@email.com    |
    +----+----------+----------------+


Common databases:

    MySQL
    PostgreSQL
    Oracle
    SQL Server
    MongoDB


Types:

    Relational Database
    NoSQL Database


Relational databases store data primarily in tables.

NoSQL databases may store data as:

    Documents
    Key-value pairs
    Graphs
    Wide-column structures


====================================================================
1.12 DATABASE TESTING
====================================================================

Database testing verifies whether data is correctly stored,
updated, retrieved, and related.

Example:

    User changes mobile number.

    UI shows:

        9876543210

    Tester checks database.

    Database should contain:

        9876543210


Important database testing areas:

    ✓ Data correctness
    ✓ Data integrity
    ✓ CRUD operations
    ✓ Constraints
    ✓ Relationships
    ✓ Transactions
    ✓ Data consistency


CRUD:

    C = Create
    R = Read
    U = Update
    D = Delete


====================================================================
1.13 API
====================================================================

API = Application Programming Interface

An API allows different software components to communicate.

Simple example:

    Frontend
       |
       | API Request
       v
    Backend
       |
       v
    Database


Example API:

    GET /users/101


Response:

    {
        "id": 101,
        "name": "Apoorv",
        "status": "active"
    }


The frontend can use this response to display user information.


====================================================================
1.14 WHY API IS IMPORTANT FOR A TESTER
====================================================================

Modern testers should not test only the UI.

A tester should understand:

    UI
     ↓
    API
     ↓
    Backend
     ↓
    Database


Suppose the UI displays:

    Account Balance: ₹10,000


A tester can verify:

    1. UI displays ₹10,000
    2. API returns ₹10,000
    3. Database contains correct balance


This provides much stronger validation.

1.15 EXAMPLE — COMPLETE E-COMMERCE SYSTEM
====================================================================

Suppose we have:

        AMAZON-LIKE APPLICATION


                    USER
                      |
                      v
                 FRONTEND
                      |
                      | API
                      v
                  BACKEND
                      |
          +-----------+-----------+
          |                       |
          v                       v
      DATABASE              PAYMENT SERVICE
          |
          v
      ORDER DATA


User action:

    "Buy Laptop"


FLOW:

    1. User clicks "Buy Now"

    2. Frontend sends request

    3. API receives request

    4. Backend validates user

    5. Backend checks inventory

    6. Backend calculates price

    7. Payment service processes payment

    8. Backend creates order

    9. Database stores order

   10. API sends response

   11. Frontend displays confirmation


TESTER CAN TEST:

    UI:
        Buy button
        Product information
        Cart

    API:
        Request
        Response
        Status code
        JSON

    Backend:
        Business rules
        Price calculation
        Inventory

    Database:
        Order record
        Product quantity
        Payment status

    Integration:
        Frontend ↔ API
        API ↔ Backend
        Backend ↔ Database
        Backend ↔ Payment service

    Development

    Staging
    Production


Example:

    Development:
        Developers write and test code.

    QA:

    Staging:

    Production:

    Which database is connected?

    Which API endpoint is being used?

    What test data is available?

1.18 WHAT DOES A SOFTWARE TESTER ACTUALLY TEST?
====================================================================

A tester may validate:

    FUNCTIONALITY
        Does the feature work?

    USABILITY
        Is it easy to use?

    PERFORMANCE
        Is it fast enough?

    SECURITY
        Is unauthorized access prevented?

    COMPATIBILITY
        Does it work across supported environments?

    RELIABILITY
        Does it work consistently?

    DATA
        Is the data correct?

    API
        Does the API behave correctly?

    DATABASE
        Is information stored correctly?

    INTEGRATION
        Do different systems work together?


====================================================================
1.19 EXAMPLE TESTER THINKING
====================================================================

Requirement:

    "User can withdraw money from an ATM."


A beginner may test only:

    Enter ₹1,000
    → Money received


A professional tester thinks further:

    Positive cases:
        Withdraw ₹1,000
        Withdraw ₹500

    Negative cases:
        Withdraw more than balance
        Withdraw invalid amount

    Boundary cases:
        Minimum withdrawal
        Maximum withdrawal

    Security:
        Invalid PIN
        Blocked card

    Network:
        Network failure during transaction

    Database:
        Balance updated correctly

    UI:
        Correct error messages

    Performance:
        Response should be acceptable

    Integration:
        ATM ↔ Bank API ↔ Database

This is the mindset required for a good tester.

1.21 IMPORTANT TERMS TO REMEMBER
====================================================================

SOFTWARE:
    Instructions/programs used to perform tasks.

APPLICATION:
    Software designed to provide functionality to users.

FRONTEND:
    User-facing part of an application.

BACKEND:
    Server-side processing and business logic.

DATABASE:
    Organized storage of application data.

API:
    Interface used for communication between software components.

CLIENT:
    Component that requests a service.

SERVER:
    Component that processes requests and provides services.

WEB APPLICATION:
    Application accessed primarily through a web browser.

MOBILE APPLICATION:
    Application designed for mobile devices.

DESKTOP APPLICATION:
    Application installed and executed on desktop computers.

BUSINESS LOGIC:
    Rules that determine how an application should behave.
