1. WHAT IS WEB TESTING?
======================================================================

Web Testing is the process of testing a web application to verify
that its functionality, UI, navigation, data handling, and other
expected behaviors work correctly.

Examples of web applications:

    • E-commerce websites
    • Banking websites
    • Educational portals
    • Social media applications
    • SaaS applications
    • Booking websites
    • Admin dashboards


Examples:

    Amazon-like shopping website
    Banking portal
    College management portal
    Online examination system


A QA engineer verifies that the web application behaves correctly
from the user's perspective and according to requirements.


======================================================================
2. WEB APPLICATION ARCHITECTURE
======================================================================

A basic web application can be represented as:

                USER
                  |
                  v
              BROWSER
                  |
                  | HTTP / HTTPS
                  v
              WEB SERVER
                  |
                  v
          APPLICATION / BACKEND
                  |
                  v
              DATABASE


Example:

    User opens:

        https://example.com/login


    Browser
       |
       | HTTP request
       v
    Server
       |
       | Process request
       v
    Database
       |
       | User information
       v
    Server
       |
       | HTTP response
       v
    Browser
       |
       v
    Login page / result


QA should understand this basic architecture because a defect
may originate in different parts of the system.


======================================================================
3. CLIENT-SIDE AND SERVER-SIDE
======================================================================

CLIENT-SIDE
-----------

The client is usually the browser.

Examples:

    Chrome
    Firefox
    Edge
    Safari


Client-side responsibilities may include:

    • Rendering UI
    • Handling user interactions
    • Sending requests
    • Displaying responses
    • Client-side validation


SERVER-SIDE
-----------

The server handles application/business logic.

Examples:

    Authentication
    Order processing
    Payment processing
    Database operations
    API processing


Simplified:

    Browser
       |
       | Request
       v
    Backend
       |
       | Database operation
       v
    Database

5. BROWSER TESTING
======================================================================

Browser Testing verifies that the web application works correctly
in supported browsers.

Common browsers:

    Chrome
    Firefox
    Edge
    Safari


Example:

    Application:
        Online Shopping Website


Test:

    Login using Chrome
    Login using Firefox
    Login using Edge
    Login using Safari


QA checks:

    • UI
    • Functionality
    • Layout
    • Forms
    • Navigation
    • JavaScript behavior
    • Application behavior


Browser compatibility is covered more deeply later in the syllabus,
but basic browser testing begins here.


======================================================================
6. UI TESTING
======================================================================

UI = User Interface.

UI Testing verifies that the visible and interactive parts of the
application behave as expected.

Examples:

    Buttons
    Text fields
    Labels
    Menus
    Checkboxes
    Radio buttons
    Dropdowns
    Icons
    Images
    Tables
    Forms


Example:

    Login Page

    Username: [____________]

    Password: [____________]

    [ Login ]


Test cases:

    ✓ Username field visible
    ✓ Password field visible
    ✓ Login button visible
    ✓ User can enter username
    ✓ User can enter password
    ✓ Login button works


======================================================================
7. UI TESTING — WHAT TO CHECK?
======================================================================

A QA engineer can check:

    1. Visibility
    2. Alignment
    3. Text
    4. Controls
    5. Input fields
    6. Buttons
    7. Error messages
    8. Navigation
    9. Consistency
   10. Expected interaction


Example:

    Button says:

        "Submit"


But application displays:

        "Submt"


This can be reported as a UI/content defect depending on
requirements and impact.

8. NAVIGATION TESTING
======================================================================

Navigation Testing verifies that users can move correctly through
the web application.

Example:

    Home
      |
      +---- Products
      |
      +---- Orders
      |
      +---- Profile
      |
      +---- Logout


Test:

    Home → Products
    Products → Product Details
    Product Details → Cart
    Cart → Checkout


Expected:

    Correct page should open after each navigation action.

        Products page should open.


Another:

Another:

    Verify navigation menu opens correctly.

11. FORM TESTING — POSITIVE TESTING

       ↓
    Submit
       ↓

12. FORM TESTING — NEGATIVE TESTING
======================================================================

Negative testing verifies invalid or unexpected input.

Examples:

    Invalid email
    Empty username
    Invalid password
    Password mismatch
    Invalid phone number
    Unsupported characters


Example:

    Email:

        abc


Expected:

    Appropriate validation message should be displayed.

13. VALIDATION TESTING
======================================================================

Validation Testing verifies that the application correctly validates
user input.

Example:

    Email field


Valid:

    user@example.com


Invalid:

    user
    user@
    @example.com


Expected:

    Invalid values should be rejected according to requirements.


======================================================================
14. REQUIRED FIELD VALIDATION
======================================================================

Suppose registration requires:

    Name *
    Email *
    Password *


Test:

    Leave Name empty
    Enter valid Email
    Enter valid Password
    Click Register


Expected:

    Appropriate error message should appear for Name.


Example:

    "Name is required."


Important:

    QA should verify both validation behavior and the associated
    error message where specified.

    1. Valid value
    2. Invalid value
    3. Empty value
    4. Minimum value
    5. Maximum value
    6. Boundary value
    7. Special characters
    8. Spaces
    9. Unexpected input
   10. Required/optional behavior


Example:

    Age field:

        Valid range = 18–60


Tests:

    18
    19
    60
    61
    17
    Empty
    abc


This connects web testing with the black-box test design techniques
covered in earlier chapters.

16. LINK TESTING

Link Testing verifies that hyperlinks work correctly.

    Products
    Privacy Policy

    ✓ Link is visible
    ✓ Link is clickable
    ✓ Correct destination
    ✓ No unexpected error
    ✓ Appropriate page opens

    Click "Contact Us"

Expected:

    Contact page opens.


Actual:

    404 Page Not Found

    FAIL

      ↓

28. PAGINATION
======================================================================

Pagination divides a large set of records into multiple pages.

Example:

    Products:

    Page 1
    Page 2
    Page 3
    Page 4
    ...


Example:

    Showing 1–20 of 200


QA should test:

    ✓ First page
    ✓ Next
    ✓ Previous
    ✓ Last page
    ✓ Page numbers
    ✓ Correct record count
    ✓ Boundary pages
    ✓ Navigation


======================================================================
29. PAGINATION TEST CASES
======================================================================

Example:

    TC_PAG_001

    Verify first page loads correctly.


    TC_PAG_002

    Verify Next moves to next page.


    TC_PAG_003

    Verify Previous returns to previous page.


    TC_PAG_004

    Verify Last opens the final page.


    TC_PAG_005

    Verify no duplicate/missing records occur between pages.


======================================================================
30. PAGINATION EDGE CASES
======================================================================

    Total records = 45
    Page size = 20


Expected:

    Page 1 → 20
    Page 2 → 20
    Page 3 → 5


QA should verify:

    Page 1 → correct 20
    Page 2 → correct 20
    Page 3 → correct 5


Also check:

    Previous/Next behavior
    First/Last behavior
    Page boundaries

31. SORTING
======================================================================

Sorting arranges data according to an ordering rule.

Examples:

    Price
    Name
    Date
    Rating
    Quantity


Example:

    Price:

    100
    200
    300
    500


Ascending:

    100 → 200 → 300 → 500


Descending:

    500 → 300 → 200 → 100


======================================================================
32. SORTING TEST CASES
======================================================================

Test:

    ✓ Ascending
    ✓ Descending
    ✓ Alphabetical
    ✓ Reverse alphabetical
    ✓ Date ascending
    ✓ Date descending
    ✓ Numeric sorting
    ✓ Sorting with duplicate values
    ✓ Sorting with empty/null values where applicable


Example:

    Product prices:

        100
        20
        300


Correct numeric ascending:

        20
        100
        300


A defective implementation might treat values as strings:

        100
        20
        300


depending on implementation.


QA should verify behavior against requirements.

33. FILTERING
======================================================================

Filtering displays only records matching selected conditions.

Example:

    E-commerce:

        Category:
            Electronics

        Price:
            ₹10,000 – ₹50,000

        Rating:
            4+


Expected:

    Only products matching the selected criteria should appear.


======================================================================
34. FILTER TESTING
======================================================================

Test:

    1. Apply one filter
    2. Remove filter
    3. Apply multiple filters
    4. Change filter
    5. Apply filter with no results
    6. Reset filters
    7. Combine filters
    8. Verify result count
    9. Verify displayed data
   10. Verify pagination after filtering


======================================================================
35. FILTER + SORT + PAGINATION
======================================================================

Real applications combine these features.

Example:

    Filter:
        Category = Laptop

            ↓

    Sort:
        Price Low → High

            ↓

    Pagination:
        Page 1


QA should verify that each operation continues to behave correctly
when combined with the others.


Example defect:

    User filters:

        Category = Laptop


    Then sorts:

        Price Low → High


    Application displays:

        Non-laptop products


Result:

    FAIL

37. WEB TESTING MINDSET
======================================================================

When testing any web page, ask:

    FUNCTIONALITY
        Does it work?

    UI
        Does it display correctly?

    NAVIGATION
        Can the user move correctly?

    VALIDATION
        Does it handle valid/invalid input?

    DATA
        Is the displayed data correct?

    LINKS
        Do links lead to the correct destinations?

    FILES
        Can users upload/download correctly?

    SEARCH
        Does search return appropriate results?

    PAGINATION
        Are records correctly divided?

    SORTING
        Is data ordered correctly?

    FILTERING
        Are only matching records displayed?

39. INTERVIEW QUESTIONS
======================================================================

Q1. What is web testing?

Answer:
Web testing is the process of verifying that a web application
works correctly according to its requirements.


Q2. What is UI testing?

Answer:
Testing the visible and interactive user-interface components of
a web application.


Q3. What is navigation testing?

Answer:
Testing whether users can correctly move between pages and
features of the application.


Q4. What is form testing?

Answer:
Testing forms for valid/invalid input, validation, submission,
error handling, and expected behavior.


Q5. What is validation testing?

Answer:
Testing whether the application correctly validates user input.


Q6. What is link testing?

Answer:
Testing whether links are available, clickable, and lead to the
correct destination.


Q7. What is file upload testing?

Answer:
Testing whether supported files can be uploaded correctly and
unsupported/invalid files are handled appropriately.


Q8. What is file download testing?

Answer:
Testing whether the correct file can be downloaded and opened
with correct content and format.


Q9. What is pagination testing?

Answer:
Testing page navigation and verifying that records are correctly
distributed across pages.


Q10. What is sorting testing?

Answer:
Testing whether data is arranged correctly according to the
selected sorting rule.


Q11. What is filtering testing?

Answer:
Testing whether only records satisfying selected filter conditions
are displayed.
