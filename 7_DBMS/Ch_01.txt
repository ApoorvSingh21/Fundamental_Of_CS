1.1 DATA
======================================================================

WHAT IS DATA?

    Data means raw facts or observations that have not yet been
    processed into meaningful information.

Example:

    Student Name: Apoorv
    Age: 23
    Marks: 85
    Course: MCA

These individual values are DATA.

Another example:

    101
    Apoorv
    85
    MCA

These values by themselves may not tell us much.

IMPORTANT:

    Data = Raw facts


REAL-WORLD EXAMPLES OF DATA:

    Banking:
        Account Number
        Customer Name
        Account Balance
        Transaction Amount

    College:
        Student ID
        Student Name
        Course
        Marks

    E-commerce:
        Product ID
        Product Name
        Price
        Quantity

    Hospital:
        Patient ID
        Patient Name
        Blood Pressure
        Doctor ID


CHARACTERISTICS OF DATA:

    - It can be numerical.
    - It can be textual.
    - It can be images.
    - It can be audio.
    - It can be video.
    - It can be dates and times.
    - It can be structured or unstructured.


======================================================================
1.2 INFORMATION
======================================================================

WHAT IS INFORMATION?

    Information is processed and organized data that has meaning
    and is useful for decision-making.

Example:

    Raw Data:

        Student A → 80
        Student B → 90
        Student C → 70

    Processed Information:

        "Student B obtained the highest marks."

The raw marks are DATA.

The conclusion obtained after processing the marks is INFORMATION.


DATA vs INFORMATION

    DATA
        ↓
    Processing
        ↓
    INFORMATION


Example:

    Data:
        80, 90, 70, 60

    Processing:
        Calculate average

    Information:
        Average = 75


KEY DIFFERENCE:

    Data:
        Raw facts

    Information:
        Meaningful processed data


======================================================================
1.3 DATABASE
======================================================================

WHAT IS A DATABASE?

    A database is an organized collection of related data that can
    be stored, accessed, managed, and updated efficiently.

Simple definition:

    DATABASE = Organized collection of related data


Example:

    Suppose a college stores information about students.

    STUDENT DATABASE

    +--------+---------+------+-------+
    | ID     | Name    | Age  | Marks |
    +--------+---------+------+-------+
    | 101    | Apoorv  | 23   | 85    |
    | 102    | Rahul   | 22   | 78    |
    | 103    | Neha    | 23   | 91    |
    +--------+---------+------+-------+

This collection of related student records can be a database.


IMPORTANT:

    A database is not simply a collection of random files.

    The data should be:
        - Organized
        - Related
        - Accessible
        - Manageable

1.4 WHY DO WE NEED DATABASES?
======================================================================

Imagine a college has 50,000 students.

The college needs to store:

    Student information
    ↓
    Courses
    ↓
    Teachers
    ↓
    Attendance
    ↓
    Marks
    ↓
    Fees
    ↓
    Examinations


If all information is maintained manually in separate files,
many problems can occur.

PROBLEMS:

    1. Data duplication
    2. Data inconsistency
    3. Difficult data searching
    4. Difficult data sharing
    5. Poor security
    6. Difficult backup
    7. Difficult recovery
    8. Concurrent access problems
    9. Data integrity problems


A database system is designed to solve these problems.


======================================================================
1.5 TRADITIONAL FILE SYSTEM
======================================================================

Before modern DBMSs became common, organizations often stored
information using separate files.

Example:

    College System

        students.txt
        teachers.txt
        courses.txt
        fees.txt
        marks.txt


Example:

    students.txt

        101, Apoorv, MCA
        102, Rahul, MCA
        103, Neha, MSc


    fees.txt

        101, Apoorv, 50000
        102, Rahul, 45000
        103, Neha, 40000


This approach works for small systems.

But as the amount of data grows, serious problems appear.


======================================================================
1.6 PROBLEMS WITH FILE SYSTEM
======================================================================

-----------------------------
1. DATA REDUNDANCY
-----------------------------

Redundancy means unnecessary duplication of data.

Example:

    students.txt

        101, Apoorv, MCA


    fees.txt

        101, Apoorv, 50000


    attendance.txt

        101, Apoorv, 90%


The name "Apoorv" is stored repeatedly.

This is DATA REDUNDANCY.


Problem:

    More storage
    +
    More maintenance
    +
    Greater chance of inconsistency


-----------------------------
2. DATA INCONSISTENCY
-----------------------------

Suppose:

    students.txt

        101, Apoorv Singh


    fees.txt

        101, Apoorv Singh Rathor


The same student has different names in different files.

This is DATA INCONSISTENCY.

Definition:

    Data inconsistency occurs when multiple copies of the same
    data contain different values.


-----------------------------
3. DIFFICULT DATA ACCESS
-----------------------------

Suppose the administrator asks:

    "Find all students whose marks are greater than 80."

With many separate files, finding this information can be difficult.

A DBMS provides SQL to make this much easier.

Example:

    SELECT *
    FROM Student
    WHERE Marks > 80;


-----------------------------
4. DATA ISOLATION
-----------------------------

Data may be distributed among different files and formats.

Example:

    students.txt
    marks.csv
    fees.xlsx
    attendance.dat


Combining information from these files can be difficult.

This problem is called DATA ISOLATION.


-----------------------------
5. INTEGRITY PROBLEMS
-----------------------------

Integrity means maintaining correctness and validity of data.

Example:

    Student age = -10

This is invalid.

A DBMS can enforce constraints such as:

    Age > 0


Example:

    Account balance should not become invalid.


-----------------------------
6. ATOMICITY PROBLEMS
-----------------------------

Suppose a bank transfer occurs:

    Account A:
        ₹10,000

    Account B:
        ₹5,000


Transfer:

    ₹2,000 from A → B


Correct result:

    A = ₹8,000
    B = ₹7,000


But suppose:

    A is debited
        ↓
    System crashes
        ↓
    B is not credited


Now the database is incorrect.

A DBMS uses TRANSACTIONS to help ensure that such operations
are handled reliably.


-----------------------------
7. CONCURRENT ACCESS PROBLEMS
-----------------------------

Multiple users may access the same data at the same time.

Example:

    User A → Withdraw ₹5,000
    User B → Withdraw ₹5,000

Both users access the same account simultaneously.

Without proper control, incorrect results may occur.

DBMS provides CONCURRENCY CONTROL.


-----------------------------
8. SECURITY PROBLEMS
-----------------------------

Not every user should be allowed to access every piece of data.

Example:

    Student:
        Can view own marks.

    Teacher:
        Can enter/update marks.

    Administrator:
        Can manage student records.

A DBMS provides authentication and authorization mechanisms.


-----------------------------
9. BACKUP AND RECOVERY PROBLEMS
-----------------------------

Suppose a server crashes.

Important database information may be lost.

A DBMS provides mechanisms for:

    Backup
    Recovery
    Logging
    Crash recovery


======================================================================
1.7 DBMS
======================================================================

WHAT IS DBMS?

    DBMS stands for:

        DATABASE MANAGEMENT SYSTEM


Definition:

    A DBMS is software used to create, store, organize, retrieve,
    update, manage, secure, and control access to databases.


Simple understanding:

    Database:
        Stores data.

    DBMS:
        Manages the database.


Think of it as:

    USER
      |
      ↓
    DBMS
      |
      ↓
    DATABASE


Examples of DBMS:

    - Oracle Database
    - MySQL
    - PostgreSQL
    - Microsoft SQL Server
    - SQLite


MongoDB is generally classified separately as a NoSQL DBMS/database
system rather than a traditional relational DBMS.


======================================================================
1.8 WHAT DOES A DBMS DO?
======================================================================

A DBMS provides facilities for:

    1. Data storage
    2. Data retrieval
    3. Data insertion
    4. Data modification
    5. Data deletion
    6. Security
    7. Integrity enforcement
    8. Concurrency control
    9. Transaction management
   10. Backup
   11. Recovery
   12. Query processing


Basic operations:

    CREATE
    ↓
    INSERT
    ↓
    SELECT
    ↓
    UPDATE
    ↓
    DELETE


Example:

    INSERT INTO Student
    VALUES (101, 'Apoorv', 23, 'MCA');


    SELECT *
    FROM Student;


    UPDATE Student
    SET Marks = 90
    WHERE ID = 101;


    DELETE FROM Student
    WHERE ID = 101;

1.9 CHARACTERISTICS OF DBMS
======================================================================

A good DBMS generally provides:

    1. Data abstraction
    2. Data independence
    3. Data security
    4. Data integrity
    5. Concurrency control
    6. Transaction management
    7. Backup and recovery
    8. Efficient data access
    9. Data sharing
   10. Reduced redundancy


======================================================================
1.10 ADVANTAGES OF DBMS
======================================================================

1. REDUCED DATA REDUNDANCY

    DBMS can reduce unnecessary duplication through proper
    database design.

2. DATA CONSISTENCY

    Centralized management and constraints help maintain
    consistent data.

3. DATA SECURITY

    Users can be given different permissions.

4. DATA INTEGRITY

    Constraints help ensure valid data.

5. DATA SHARING

    Multiple users/applications can access the database.

6. CONCURRENCY CONTROL

    DBMS manages simultaneous access.

7. BACKUP AND RECOVERY

    DBMS supports mechanisms to recover from failures.

8. TRANSACTION MANAGEMENT

    DBMS supports reliable execution of database operations.

9. DATA INDEPENDENCE

    Changes at one database level can often be made without
    requiring changes at another level.

10. CENTRALIZED CONTROL

    Database administration can be managed systematically.


======================================================================
1.11 DISADVANTAGES OF DBMS
======================================================================

DBMS also has disadvantages.

1. COST

    Enterprise database systems and infrastructure can be expensive.

2. COMPLEXITY

    Database systems are more complex than simple files.

3. HARDWARE REQUIREMENTS

    Large database systems may require significant CPU, RAM,
    and storage resources.

4. ADMINISTRATION

    Skilled database administrators may be required.

5. FAILURE IMPACT

    If a centralized database system becomes unavailable,
    many applications may be affected.

6. MAINTENANCE

    Database software requires monitoring, backup, updates,
    security management, and maintenance.


======================================================================
1.12 DBMS vs FILE SYSTEM
======================================================================

+----------------------+---------------------------+--------------------------+
| Feature              | File System               | DBMS                     |
+----------------------+---------------------------+--------------------------+
| Data organization    | Separate files            | Structured database      |
| Redundancy           | Usually higher            | Can be reduced           |
| Consistency          | Difficult to maintain     | Better control           |
| Security             | Basic/limited             | Advanced controls        |
| Data sharing         | Limited                   | Supported                |
| Concurrent access    | Limited                   | Concurrency control      |
| Transactions         | Limited                   | Supported                |
| Recovery             | Usually application-based | Built-in mechanisms      |
| Querying             | Difficult for complex     | SQL/query languages      |
| Integrity            | Difficult                 | Constraints supported    |
| Relationships        | Difficult                 | Easily modeled           |
| Scalability          | Limited                   | Generally better         |
| Administration      | Simple                    | More complex             |
+----------------------+---------------------------+--------------------------+


INTERVIEW ANSWER:

    "A DBMS provides centralized mechanisms for data management,
    security, integrity, concurrency, transactions, backup and
    recovery that are difficult to implement reliably using
    traditional file systems."

                  |

                  |

                  |

======================================================================
1.21 DDL — DATA DEFINITION LANGUAGE
======================================================================

DDL is used to define or modify the structure of database objects.

Common commands:

    CREATE
    ALTER
    DROP
    TRUNCATE


Example:

    CREATE TABLE Student (
        Student_ID INT,
        Name VARCHAR(100),
        Age INT
    );


ALTER:

    ALTER TABLE Student
    ADD Email VARCHAR(100);


DROP:

    DROP TABLE Student;


TRUNCATE:

    TRUNCATE TABLE Student;


IMPORTANT:

    DDL deals primarily with DATABASE STRUCTURE.


======================================================================
1.22 DML — DATA MANIPULATION LANGUAGE
======================================================================

DML is used to manipulate data stored in tables.

Common commands:

    INSERT
    UPDATE
    DELETE


Example:

    INSERT INTO Student
    VALUES (101, 'Apoorv', 23);


    UPDATE Student
    SET Age = 24
    WHERE Student_ID = 101;


    DELETE FROM Student
    WHERE Student_ID = 101;


DML deals with:

    DATA


======================================================================
1.23 DQL — DATA QUERY LANGUAGE
======================================================================

DQL is commonly used to refer to commands used for querying data.

Main command:

    SELECT


Example:

    SELECT *
    FROM Student;


Specific SQL standards and database products may classify SELECT
differently, but "DQL" is widely used in teaching/interview contexts.


======================================================================
1.24 DCL — DATA CONTROL LANGUAGE
======================================================================

DCL deals with access privileges.

Main commands:

    GRANT
    REVOKE


Example:

    GRANT SELECT
    ON Student
    TO developer;


REVOKE:

    REVOKE SELECT
    ON Student
    FROM developer;


Purpose:

    Control who can access what data.


======================================================================
1.25 TCL — TRANSACTION CONTROL LANGUAGE
======================================================================

TCL is used to control transactions.

Common commands:

    COMMIT
    ROLLBACK
    SAVEPOINT


Example:

    UPDATE Account
    SET Balance = Balance - 5000
    WHERE Account_ID = 101;

    UPDATE Account
    SET Balance = Balance + 5000
    WHERE Account_ID = 102;

    COMMIT;


If something goes wrong:

    ROLLBACK;


SAVEPOINT:

    SAVEPOINT transfer_start;


TCL will be studied deeply in the Transaction chapter.

1.27 DBMS vs RDBMS
======================================================================

DBMS:

    Database Management System


RDBMS:

    Relational Database Management System


RDBMS is a database management system based on the
RELATIONAL MODEL.

In an RDBMS, data is typically represented using:

    TABLES
      |
      +---- Rows
      |
      +---- Columns


Example:

    STUDENT

    +----+---------+-----+-------+
    | ID | Name    | Age | Marks |
    +----+---------+-----+-------+
    | 1  | Apoorv  | 23  | 85    |
    | 2  | Rahul   | 22  | 78    |
    +----+---------+-----+-------+


Examples of relational DBMSs:

    - Oracle Database
    - PostgreSQL
    - MySQL
    - Microsoft SQL Server
    - SQLite


======================================================================
1.28 DBMS vs RDBMS — IMPORTANT INTERVIEW CONCEPT
======================================================================

Historically, educational material often describes differences such
as relationships and normalization between "DBMS" and "RDBMS".

However, in modern usage:

    DBMS = broad category of database management software.

    RDBMS = DBMS specifically based on the relational model.


Therefore:

    RDBMS ⊂ DBMS

Meaning:

    Every RDBMS is a DBMS,
    but not every DBMS is relational.


Examples:

    Relational:
        PostgreSQL
        Oracle
        MySQL
        SQL Server

    Non-relational:
        MongoDB
        Redis
        Cassandra

1.37 IMPORTANT INTERVIEW QUESTIONS
======================================================================

Q1. What is DBMS?

ANSWER:

    DBMS stands for Database Management System. It is software
    used to create, store, retrieve, update, secure, and manage
    data in databases.


Q2. What is a database?

ANSWER:

    A database is an organized collection of related data that
    can be efficiently stored, accessed, and managed.


Q3. What is the difference between data and information?

ANSWER:

    Data is raw facts, whereas information is processed data
    that has meaningful context and is useful for decision-making.


Q4. Why do we need DBMS?

ANSWER:

    DBMS helps manage large amounts of data and provides mechanisms
    for security, integrity, concurrency, transactions, backup,
    recovery, and efficient data access.


Q5. What is data redundancy?

ANSWER:

    Data redundancy is unnecessary duplication of the same data.


Q6. What is data inconsistency?

ANSWER:

    Data inconsistency occurs when different copies of the same
    data contain different values.


Q7. What is RDBMS?

ANSWER:

    RDBMS stands for Relational Database Management System.
    It manages data according to the relational model, usually
    representing data as tables.


Q8. Give examples of RDBMS.

ANSWER:

    Oracle
    PostgreSQL
    MySQL
    Microsoft SQL Server
    SQLite


Q9. What is the difference between DBMS and RDBMS?

ANSWER:

    DBMS is the general category of database management systems,
    while RDBMS specifically refers to DBMSs based on the relational
    data model.


Q10. What is a DBA?

ANSWER:

    DBA stands for Database Administrator. A DBA manages database
    security, users, backup, recovery, performance, availability,
    and maintenance.


Q11. What is DDL?

ANSWER:

    DDL stands for Data Definition Language. It is used to define
    and modify database structures.

    Examples:
        CREATE
        ALTER
        DROP
        TRUNCATE


Q12. What is DML?

ANSWER:

    DML stands for Data Manipulation Language.

    Examples:
        INSERT
        UPDATE
        DELETE


Q13. What is DQL?

ANSWER:

    DQL is commonly used to refer to querying data using SELECT.


Q14. What is DCL?

ANSWER:

    DCL stands for Data Control Language.

    Examples:
        GRANT
        REVOKE


Q15. What is TCL?

ANSWER:

    TCL stands for Transaction Control Language.

    Examples:
        COMMIT
        ROLLBACK
        SAVEPOINT


Q16. What are the major problems of file systems?

ANSWER:

    - Data redundancy
    - Data inconsistency
    - Data isolation
    - Difficult data access
    - Integrity problems
    - Security problems
    - Concurrent access problems
    - Backup/recovery difficulties


Q17. What is data independence?

ANSWER:

    Data independence is the ability to change the schema at one
    level of database architecture without requiring changes at
    higher levels.

    Detailed study:
        Chapter 02


Q18. What is a transaction?

ANSWER:

    A transaction is a logical unit of database operations that
    should be executed reliably as a unit.

    Detailed study:
        Chapter 16
